## 2. 공통 결함 패턴 (8작품 100% 공유)

### Pattern A: 자본 연속성 단절 (P0 — 전 작품)
- `capital_before(N) != capital_after(N-1)` — **68~69/70블록에서 갭 발생**
- 갭 범위: +2억 ~ +35억 (블록 진행에 따라 단조 증가)
- Block 1→2만 정합, Block 3부터 전량 단절
- **서사 내 갭 설명 0건** (이자/배당/비서사 수익 언급 없음)
- `capital_delta = capital_after - capital_before`는 전 작품 70/70 정합 (내부 산술은 정확)

### Pattern B: NPC 관계 동결 (P0 — 전 작품)
- **2명만 70블록 전체 등장**, 신규 NPC 추가/퇴장 0건
- NPC A: before/after 모두 70블록 **완전 동일 문장** (25년간 관계 변화 0)
- NPC B: before 70블록 동일 ("협력은 제한적이었다"), after만 7종 페이즈 변주
- 25년 서사에서 등장인물 2명 고정은 서사 붕괴 수준

### Pattern C: 적대자 단일 고정 (P1 — 전 작품)
- 각 작품의 opponent.name이 **70블록 전량 동일**
- weakness_exploited: 3종만 순환 (조달 지연 / 장기계약 과소평가 / 현금흐름 부재)
- 25년간 적대 세력 교체/분열/신규 등장 0건

### Pattern D: emotional_beat 기계적 순환 (P1 — 전 작품)
- type: `resolve → pressure → breakthrough → victory` **정확히 4블록 주기 무한 반복**
- intensity: `8 → 9 → 7` **정확히 3블록 주기 순환** (7/8/9만 사용, 각 ~23회)
- tension_level: 8과 9만 존재 (7 이하/10 없음)
- 서사적 완급 조절 완전 부재

### Pattern E: deal_type 균등 분배 (P1 — 전 작품)
- 5종 × 14회 = 70블록 **수학적 균등 배분**
- 옵션 계약(14), 장기 공급 계약(14), 공동 투자 계약(14), 지분 연계 계약(14), 전략 제휴(14)
- 자산 규모(100억 vs 47조)와 무관하게 동일 패턴

### Pattern F: duration 전량 "7일" 고정 (P2 — 전 작품)
- 70블록 × 7일 = 490일이지만 실제 시간 범위는 25.7년
- 블록 간 실제 갭 2~8개월, 후반부(Block 55+)는 매월 1블록으로 압축

### Pattern G: 서사 템플릿 과도 반복 (P1 — 전 작품)
- solution: 6종 템플릿 (섹터명만 교체)
- stakes: 5종 템플릿
- callback: "직전 블록의 X 성과가 이번 Y 전환의 발판이 되었다" 단일 구조
- success_pattern: "겉패배처럼 보이지만 실승으로 귀결" **70블록 전량 동일**
- method: "X 수익구조 정비 + 계약 단계화" 섹터명만 교체

### Pattern H: 빙의/회귀 요소 동결 (P1 — 빙의 3작품)
- death_flag: avoided="연쇄 유동성 위기", method="현금흐름 선관리와 계약 분산" 70블록 동일
- slip_up: 3종만 교대 (선제 언급 / 타이밍 정확 / 해석 속도)
- suspicion_from: 단일 고정 (적대자와 동일)
- execution_doctrine: "항상 승리 구조를 먼저 설계하고 실행한다" 70블록 불변

## 3. 근본 원인 분석

### 원인: 템플릿 기반 기계적 생성

8작품 전량이 동일한 생성 패턴을 공유:

```
구조 = 8섹터 × N라운드 × 복리성장공식

각 블록 = {
  섹터: 8개 순환 로테이션
  감정: 4종 × 3강도 주기 순환
  거래: 5종 × 14회 균등 배분
  자본: 복리 성장 (초반 20~37%, 후반 11% 수렴)
  NPC: 2명 고정, before 리셋
  적대: 1세력 고정, 약점 3종 순환
  위치: 5곳 × 14회 균등 배분
}
```

**증거**:
1. 모든 수량적 분배가 **수학적으로 정확히 균등** (14회, 23회 등)
2. 8작품의 종료 자본이 46~47조 범위로 수렴 (동일 성장 공식)
3. 8작품 모두 시간 범위 2006~2031 동일
4. 8작품의 NPC 패턴이 구조적으로 동일 (이름만 다름)
5. 빙의 3작품의 death_flag/slip_up이 완전 동일 문장

## 5. 개선 권고

### 즉시 수정 필요 (P0)
1. **자본 연속성**: `capital_before(N) = capital_after(N-1)` 강제 또는 갭에 대한 서사적 설명 추가
2. **NPC 다양화**: 최소 8~10명으로 확장, 페이즈별 등장/퇴장/관계 발전

### 구조 개선 필요 (P1)
3. **감정 비트 탈기계화**: 4블록 주기 순환 제거, 서사적 완급 조절 도입
4. **적대자 분화**: 25년 서사에 최소 3~4개 적대 세력 (내부 배신, 제도 장벽, 신규 경쟁자)
5. **deal_type/method 다양화**: 자산 규모별 거래 유형 분화
6. **빙의 요소 동적화**: death_flag/slip_up 페이즈별 변화
7. **callback 개별화**: 섹터 전환 외 인물/사건 기반 복선 회수

### 품질 개선 (P2)
8. **duration 현실화**: 블록별 시간 스케일 반영 (1주~3개월)
9. **location 확장**: 사업 확장에 따른 장소 증가
10. **success_pattern 분화**: 실패/부분 성공/피로스 승리 등 변주

## 6. 결론

8개 Treatment는 **동일한 템플릿 엔진에서 섹터명/인물명만 교체하여 생성된 산출물**로, 서사적 다양성이 극히 부족합니다. 파이프라인에서 원고 생성 시 반복적 서사 패턴으로 이어질 위험이 높으며, 특히 자본 연속성 단절(68/70블록)은 NC-1 검사에서 매 블록 경고를 유발합니다.

**전체 건전성: 2.9/10** — 구조적 골격(섹터 로테이션, 시간 순서, delta 산술)은 정상이나, 서사 품질 요소(NPC/감정/적대/거래/복선)가 기계적 반복으로 인해 사실상 무력화 상태.

**권고**: Treatment 생성 로직 자체를 개선하거나, 수작업으로 개별 블록의 서사 요소를 다양화해야 합니다.
