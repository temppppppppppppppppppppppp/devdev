6. side-effect notes
- file writes: covered
- Fact: runtime writes include `drafts/ep_*.txt`, `logs/artifacts/stage*/...`, `logs/episode_production.jsonl`, `logs/pass_rate_monitor.json`, `logs/quality_metrics.jsonl`, `logs/runtime_audit.jsonl`, `logs/runtime_audit_summary.json`, `logs/soft_failures.jsonl`, and `logs/session/*.jsonl`.
- DB / transaction: covered
- Fact: `manuscripts` plus `martial_tracker` use explicit transaction control in `Stage4PostProcessor`; `world_state` and `fact_ledger` are grouped under `DBManager.transaction()` when available; many telemetry sinks (`stage_attempts`, `ui_events`, `llm_calls`) are best-effort and non-blocking.
- JSONL / logs / audit sinks: covered
- Fact: `append_jsonl_record()` uses a process-wide append lock; `SessionLogger` uses its own write lock and rotation; `AuditService` flushes in-memory audit buffer to `runtime_audit.jsonl` before writing summary.
- console / UI / operator surface: partial
- Fact: persistence chain stores UI-visible events in both DB (`ui_events`) and JSONL (`logs/session/ui_events.jsonl`), but operator rendering itself is owned by `T07`.
- recovery / retry / compensation: partial
- Fact: rollback exists for the primary `manuscripts` transaction and for in-memory `world_state` / `fact_ledger` snapshots; sidecars like quality labels, signals, pacing, and satisfaction tags degrade to `soft_failures.jsonl` instead of retrying inline.
- cache / global state: partial
- Fact: `PassRateMonitor` and `QualityDashboard` keep in-memory history and flush/snapshot later; `WorldStateManager` mutates process memory before anchor save; `episode_bible` cumulative cache invalidation happens on save.
- bootstrap / config-env: partial
- Fact: artifact/log roots fall back from `project.paths.root` to DB parent or fallback project paths; session lineage in proof digest explicitly records split plain-log vs structured session IDs.
- external interfaces: partial
- Fact: no external network call is required for the local persistence sinks themselves; `bridge_server` reads these sinks and exposes one DB write endpoint for `episode_quality_observations`.

7. contradictions or uncertainty
- Inference: `projects/0_260316` currently shows a strong artifact-truth chain for final Stage 4 passes: `stage_attempts -> artifact file -> manuscripts table -> drafts/ep_*.txt`.
- Inference: `runtime_audit_summary.json` is a snapshot artifact, not a continuously refreshed truth surface; the live sample lags later `quality_metrics.jsonl` and `ui_events` writes.
- Inference: `director_selections` is intentionally not the final authority for Stage 4 post-fix outputs; consumers that treat it as final will read pre-final artifacts and rationale.
