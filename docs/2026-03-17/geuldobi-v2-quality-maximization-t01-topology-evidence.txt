4. facts
- Fact: repo root currently exposes two human-noticeable app entry files, but only one is authoritative for Electron runtime. Root `main.js` explicitly says the authoritative Electron entry is `geuldobi-desktop/src/main.js` and only sets `GEULDOBI_ROOT_SHADOW_ENTRY` before re-exporting that file (`main.js:5`, `main.js:10-14`).
- Fact: packaged/desktop authority sits in `geuldobi-desktop/src/main.js`, not root `main.js`. The Electron main file imports `console_relay` and `desktop_control_plane_contract`, validates Electron main APIs, defines workspace-path helpers, syncs packaged workspace seed data, starts the backend, creates splash/main windows with `preload.js`, and registers IPC handlers for bridge/material/project/workspace surfaces (`geuldobi-desktop/src/main.js:49-54`, `geuldobi-desktop/src/main.js:156`, `geuldobi-desktop/src/main.js:191`, `geuldobi-desktop/src/main.js:239-277`, `geuldobi-desktop/src/main.js:358-409`, `geuldobi-desktop/src/main.js:479-976`).
- Fact: desktop mode starts the Python backend via `python -m uvicorn modules.api.bridge_server:app --port 8300` in dev mode and passes workspace env such as `GEULDOBI_WORKSPACE` and `GEULDOBI_PROJECTS_ROOT` into the spawned backend process (`geuldobi-desktop/src/main.js:250`, `geuldobi-desktop/src/main.js:276-277`).
- Fact: `modules/api/bridge_server.py` is the backend control-plane root. Its header declares `/run`, `/stop`, `/status`, `/events`, and `/run/{run_id}/input`, and the module wires `ProcessRunner`, `PromptBroker`, `RiskApprovalGate`, `DBManager`, `PassRateMonitor`, and `QualityDashboard` before constructing `app = FastAPI(...)` (`modules/api/bridge_server.py:4-8`, `modules/api/bridge_server.py:36-46`, `modules/api/bridge_server.py:1690-1712`, `modules/api/bridge_server.py:1720-2010`).
- Fact: `modules/api/process_runner.py` is the process boundary between the bridge server and the engine app. Its file header describes it as a `main_a.py` subprocess wrapper; it resolves engine root, falls back to `python main_a.py` if packaged engine.exe is absent, maintains runner state, and writes stdin sequences for Mode A/Mode B operation (`modules/api/process_runner.py:1-13`, `modules/api/process_runner.py:44`, `modules/api/process_runner.py:217-224`, `modules/api/process_runner.py:228-331`, `modules/api/process_runner.py:688-776`).
- Fact: `main_a.py` is the Python composition root for the engine path. It performs boot-time sys.path normalization, UTF-8 stdio bootstrap, Windows asyncio policy bootstrap, faulthandler activation, dotenv load, and large-scale module imports before defining `SovereignApp` (`main_a.py` top-of-file, `main_a.py:178`, `main_a.py:345`).
- Fact: `SovereignApp` composes `StudioSystem`, `Stage2Orchestrator`, `Stage3Orchestrator`, `Stage4Orchestrator`, `SessionLogger`, `AuditService`, `UIService`, `StateService`, `ProjectService`, and later `VecMemory`; it also exposes many thin delegates back into those services and orchestrators (`main_a.py:354`, `main_a.py:370-422`, `main_a.py:1310-1319`, `main_a.py:3218-3371`, `main_a.py:4114-4116`).
- Fact: direct CLI boot still exists. `main_a.py` ends with `if __name__ == "__main__": SovereignApp().boot()` and persists a boot traceback to `logs/error.log` if startup fails (`main_a.py:4797-4806`).
- Fact: top-level subsystem roots under `modules/` are `api`, `core`, `domain`, `models`, `protocols`, `ui`, and `validation`. `modules/domain/` is currently centered on `agents/`. `modules/core/` also contains subroots such as `genre_guards`, `laws`, `providers`, `services`, and `stage0`.
