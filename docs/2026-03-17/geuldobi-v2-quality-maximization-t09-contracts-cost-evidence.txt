4. facts
- Fact: `config/models.yaml` is the live model-routing SSOT read by `modules/core/models_config.py`; `modules/core/llm_router.py` enforces provider enable flags from that file and infers provider by model prefix/name. Current default runtime enables only `gemini`; `anthropic`, `openai`, and `vertex_ai` are disabled.
- Fact: `config/models.yaml` duplicates concrete model names in both `agents` and `role_constants`, and also defines a fallback chain (`gemini-2.5-pro -> gemini-2.5-flash`, `gemini-2.5-flash -> gemini-2.5-flash`). This is one central config file, but still a multi-surface contract inside the same file.
- Fact: threshold authority is primarily `config/settings/validation.yaml`, reached through `modules/core/config_manager.py` and `modules/validation/threshold_helper.py`. Live values include `context.max_context_chars=1000000`, `context.mandatory_context_max=400000`, `smart_retrieval.stage4_total_budget=300000`, and `smart_retrieval.slot_max_chars_default=3000`.
- Fact: fallback literals are not fully aligned to that YAML SSOT. `modules/core/context_advisor.py` still falls back to `1500` for `smart_retrieval.slot_max_chars_default`, `tests/property/test_budget_props.py` still codifies `1500`, and `modules/core/stage4_orchestrator.py` still falls back to `80000` for `context.mandatory_context_max`. By contrast, `modules/core/stage4_interview_round.py` and `modules/core/stage4_context_builder.py` already use `3000` and `400000`.
- Fact: `modules/core/constants.py` maps `ContextLimits.MAX_CONTEXT_CHARS` to YAML-backed `_LazyThreshold("context.max_context_chars", 1_000_000)`, but `modules/domain/agents/base_agent.py` still applies a separate prompt-size gate that head-clips oversized prompts and marks `requires_human_intervention=True`. Long-context policy is therefore partly centralized and partly local.
- Fact: prompt YAML files carry `_version` metadata, and `modules/core/prompt_loader.py` exposes `get_prompt_version()` and `compose_version_tag()`. Those version tags are consumed in Stage 2/3/4 orchestration and persistence paths, so runtime prompt authority is materially YAML-backed rather than comment-only.
- Fact: live Director prompt authority is split. `modules/domain/agents/director_ensemble.py`, `modules/domain/agents/director_auditor.py`, and `modules/domain/agents/director_continuity.py` use `PromptLoader()` and the YAML prompt pack. `modules/domain/agents/director_prompts.py` still ships large inline prompt constants, including legacy `ENSEMBLE_SELECTION_PROMPT`.
- Fact: `config/prompts/director.yaml` already contains the newer split contract (`ENSEMBLE_STABLE_CONTEXT`, `ENSEMBLE_VARIABLE_PROMPT`) plus expanded `PASS_WITH_FIX` and `fix_pack` rules. `modules/domain/agents/director_ensemble.py` prefers those split keys but still contains a fallback path for legacy `ENSEMBLE_SELECTION_PROMPT`. The worktree also has a dirty `config/prompts/director.yaml`, which increases drift risk for any code path still depending on inline constants.
- Fact: `config/settings.json` remains a live secondary authority. `main_a.py` still loads it and applies `validation.use_v0128`; `modules/domain/agents/director_auditor.py` also merges `use_self_consistency`, `consistency_votes`, and `use_retrospective` from that JSON into its default config. `modules/validation/validation_orchestrator.py` already has YAML-backed defaults for the same knobs.
- Fact: no live consumer was found for `config/settings.json` under `costs.max_retries` or `costs.temperature`. That makes the `costs` block appear stale or dead as a runtime contract.
- Fact: `modules/core/metrics_collector.py` captures agent/model/retry/tokens/cached_tokens/thinking_tokens/duration and computes scope-level cost by model, including `vertexai:` normalization. It does not record an explicit `stage` field or a duplicate-analysis candidate group in its own metric record.
- Fact: Triage `Pack D` is only partially satisfied across existing sinks. `modules/domain/agents/base_agent.py` and `modules/core/session_logger.py` add stage, prompt chars, usage, and duration in downstream logging; `modules/core/stage4_interview_round.py` writes round-level `model`, `duration_ms`, `round_total_tokens`, `round_total_cost_usd`, `round_model_breakdown`, `token_usage`, and `attempt_key`; `modules/api/bridge_server.py` aggregates DB cost rows for operator use. The required fields exist in pieces, not as one coherent cross-cut contract.
