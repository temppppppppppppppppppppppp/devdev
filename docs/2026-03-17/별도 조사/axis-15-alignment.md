## 3. 갭 식별

### G15-1. 외부 피드백 루프 완전 부재 — 완전 부재

**증거**: 코드베이스 전체에서 "독자 반응", "reader feedback", "편집자 피드백", "editor feedback", "시장 데이터", "market data", "A/B test", "클릭률", "이탈률" 등의 경로를 검색한 결과, 외부 데이터가 시스템에 유입되는 경로가 전혀 없음. 모든 품질 판단은 시스템 내부 기준(Quality Constitution + scoring dimensions + Director LLM 판단)에 의존.

**문제**: 시스템이 "좋다"고 판정한 원고가 실제로 독자에게 좋은지 검증할 방법이 없음. 내부 기준이 정확하다는 가정에 전적으로 의존.

### G15-2. "모순 없음 ≠ 재미있음" 간극의 구조적 인식 부재 — 부분 구현

**증거**: 채점 가중치에서 continuity(consistency 0.25) + engagement(0.15) + commercial(0.20) + satisfaction(0.10)으로, "정합성"(0.25)이 "재미"(engagement 0.15 + commercial 0.20 = 0.35)보다 낮은 비중. **가중치 설계 자체는 이 간극을 인식하고 있다.** 그러나:
- Director 프롬프트(director.yaml:129-136)에서 "연속성+모순검사: 40%"로, continuity가 프롬프트 레벨에서는 최대 비중. 이는 director_grading.py의 가중치와 불일치.
- TIER 1 BLOCKING에 5개 항목이 모두 정합성 관련(사망NPC, 아이템, 파괴, 파워, 분량). "재미없음"은 BLOCKING이 아닌 SCORING에서만 감점. **정합성 위반은 즉시 탈락이지만 재미 부족은 점수 감소에 그침.**

**간극 인식 상태**: 시스템 설계자는 이 간극을 인식하고 commercial_appeal, reader_satisfaction, engagement를 도입했으나, 구조적으로 정합성이 우선하는 비대칭이 남아 있음.

### G15-3. commercial_appeal의 측정 구체성 제한 — 부분 구현

**증거**: commercial_appeal은 Hook(7점) + Cliffhanger(7점) + Reward timing(6점) = 20점으로 정의. 이 3요소는 "독자 유지"의 근사치이나:
- Hook: "첫 500자에 포착 요소 3-4개" — 포착 요소의 정의가 "action, mystery, conflict, sensory description" 4종으로 고정. 장르별 효과적 Hook이 다를 수 있음(투자: 수익률 공개, 무협: 위기 상황, 요리: 미각 묘사).
- Reward timing: "3에피소드 내 보상" — 보상의 정의가 "성장, 획득, 인정"으로 일반적. 장르별 보상 유형이 다름(투자: 수익 실현, 헌터: 레벨업, 무협: 돌파).
- **실제 상업 성공 지표(조회수, 유료 전환율, 다음 화 클릭률)와의 상관관계 미검증.**

### G15-4. Director 프롬프트 가중치와 Grading 가중치 불일치 — 형식적 존재

**증거**:
- Director 프롬프트(`director.yaml:129-136`): 연속성+모순 40%, Blueprint 반영 20%, 문장+몰입 20%, 분량 10%, Python경고 10%
- Director Grading(`director_grading.py:65-72`): structure 0.15, prose 0.15, consistency 0.25, engagement 0.15, commercial 0.20, satisfaction 0.10

이 두 가중치 체계는 **다른 단계에서 다른 목적으로 사용됨** — 전자는 LLM에게 채점 가이드를 주는 프롬프트, 후자는 Python 측 점수 집계. 그러나 두 체계가 다른 우선순위를 제시하면 LLM 판단과 Python 집계가 괴리될 수 있음. 예: LLM이 "연속성 40% 기준으로 높은 점수"를 줬는데 Python이 "consistency 25%"로 재집계하면 최종 점수가 달라짐.

### G15-5. 시스템 평가와 인간 평가의 교정 메커니즘 부재 — 완전 부재

**증거**: confidence_calibration.py는 "시스템 내부 신뢰도"를 계산하나, 이는 "시스템이 자기 판단을 얼마나 확신하는가"이지 "시스템 판단이 인간 판단과 얼마나 일치하는가"가 아님. 시스템 점수 vs 인간 점수의 비교/교정 데이터 수집·분석·반영 경로 없음.

**연결 — 축 14 교차 발견**: Positive Few-Shot 부재(G14-1)로 인해 "인간이 좋다고 한 구체적 원고"가 시스템에 없으므로, 교정의 기준점 자체가 부재.

### G15-6. 플랫폼 적합성의 부분적 반영 — 부분 구현

**증거**: 분량(4000-15000자)과 클리프행어(target 40) 기준이 있으나:
- **연재 주기(일간/주간/격주)에 따른 에피소드 구조 차이** 미반영
- **플랫폼별 포맷 요구사항** (카카오페이지 vs 네이버시리즈 vs 문피아 등) 미반영
- **과금 모델에 따른 서사 구조 차이** (유료 전환 유도 에피소드 배치 등) 미반영
- 기존 기준(분량, 클리프행어)은 가장 기본적인 플랫폼 요구만 충족

### G15-7. 장르 임계값의 근거 불투명 — 형식적 존재

**증거**: validation.yaml의 장르별 임계값(68-72)이 주석으로 간략 근거를 제시(예: "헌터 68 — 액션 위주로 약간 낮게", "투자 72 — 논리성 중요로 약간 높게"). 그러나:
- 이 수치가 어떤 데이터/실험/경험에서 도출되었는지 불명
- 임계값 변경의 영향 분석 도구 없음
- 장르 내에서도 서브장르별 차이(예: 현대무협 vs 고전무협)는 미반영

**영향도 요약**: 시스템의 정렬 인프라는 **내부적으로 정교한 편**이다. 6차원 채점, 3계층 Quality Constitution, 장르별 가중치/임계값, Catharsis Timer, Adaptive Grading 등 풍부한 내부 기준이 설계되어 있다. 핵심 갭은 **외부 신호의 완전 부재(G15-1, G15-5)**로, 시스템이 "독자에게 좋은 것"을 내부적으로 정의하지만 그 정의가 실제 독자 가치와 일치하는지 검증·교정하는 폐루프가 없다. 이는 시스템 품질의 **천장**을 "설계자의 품질 직관의 정확도"에 의존하게 만든다.

부차적으로, **프롬프트-Grading 가중치 불일치(G15-4)**는 내부 기준 자체의 일관성 문제이며, 외부 정렬 이전에 내부 정합성부터 확보해야 함을 시사한다.
