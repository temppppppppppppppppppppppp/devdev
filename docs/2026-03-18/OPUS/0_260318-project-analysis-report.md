### 7.2 비판적 3pass

#### 비판 Pass 1 — "Director가 품질 게이트를 사실상 무력화하고 있는가?"

**논거**:

ep1의 사례가 가장 극적이다. Python 검증기는 대화 비율 8%(목표 30%), 씬 완성도 0/4, 분량 4,446자(목표 5,000자)로 세 가지 핵심 지표 모두 미달을 보고했다. 그런데 Director LLM은 99점을 부여하며 "씬 구현이 우수하다"고 평가했다.

이것은 단순히 "LLM이 관대하다"는 수준이 아니다. **씬 완성도 0/4인 원고에 대해 씬 구현을 칭찬하는 것은 논리적 모순**이다. Director가 Python 검증 결과를 입력으로 받되, 그것을 평가에 실질적으로 반영하지 않는 구조라면, Python 검증 단계 자체가 연산 낭비에 불과하다.

더 우려되는 것은 이 패턴이 일회성이 아니라는 점이다:
- ep2도 대화 비율 13-14%(목표 30%)에서 98점 PASS.
- Stage 3의 11개 블루프린트 전수 `quality_risk: true`이나 전수 PASS.

**결론**: 현재 품질 게이트는 "REJECT할 수 있는 구조"이지만 "실질적으로 REJECT하지 않는 운영" 상태다. ep1 1차 REJECT(분량 미달)는 length guard라는 하드코딩 조건에 의한 것이지 Director 재량이 아니었다. Director 재량으로 REJECT된 사례는 **0건**이다.

#### 비판 Pass 2 — "실패 분석 시스템이 완전히 죽어 있는데, 이것이 의도적 방치인가?"

**논거**:

`failure_analyzer`의 `sink_alignment_final_authority_contract`가 `get_stage4_final_authority_rows` AttributeError로 10회 연속 실패했다. 이 메서드는 `types.SimpleNamespace` 객체에서 호출되었는데, 해당 객체에 존재하지 않는 메서드다.

이것은 **인터페이스 계약 위반**이다. 코드가 기대하는 메서드가 실제 객체에 구현되지 않았다. 10회 반복은 이 에러가 한 번 발생한 게 아니라 파이프라인 실행 중 체계적으로 호출되었음을 의미한다.

동시에:
- 빈 추적 테이블 5개 (canonical_facts, timeline_entries, karma_status, character_voice, npc_relationship_edges)
- vec0 벡터 확장 미로드

이 세 가지를 종합하면, **연속성 추적·실패 분석·벡터 검색이라는 3대 보조 시스템이 전부 비작동 상태**에서 원고가 생산되었다. 이는 파이프라인이 "LLM 생성 + Director 승인"이라는 최소 경로로만 동작했음을 의미한다.

**결론**: 설계된 안전망 중 실제로 작동한 것은 length guard(하드코딩 분량 검증)뿐이다. 나머지 검증·추적·분석 시스템은 코드는 존재하나 실행 시 무력화되어 있다.

#### 비판 Pass 3 — "2편의 원고로 이 파이프라인의 신뢰성을 판단할 수 있는가?"

**논거**:

블루프린트 11개 중 원고 2편만 생산된 상태에서 파이프라인 전체를 평가하는 것은 표본 부족의 위험이 있다. 그러나 **부족한 표본에서도 구조적 결함이 이미 노출되었다는 점이 더 중요하다**.

2편만으로도 확인된 구조적 문제:
1. Director가 Python 검증을 체계적으로 override (2/2, 100%)
2. 아크↔원고 내용 어긋남 (ep1이 Arc ep1+ep2 병합)
3. 소프트 실패 분석기 전면 불능 (10/10, 100%)
4. 비용 계측 누락 (Stage 2-3 전건)
5. 품질 리스크 플래그 write-only (11/11, 100%)

이 문제들은 "가끔 발생하는 결함"이 아니라 **100% 재현율의 구조적 결함**이다. 따라서 표본 2편이라도 진단적 가치는 충분하다.

반대로, 2편으로는 판단할 수 **없는** 것도 명확히 해야 한다:
- ep7의 5회 재시도 원인 (reject_reason 미기록)
- ep3 이후 Arc beat 매핑 누적 편차의 실제 영향
- 대화 비율 부족이 후반 에피소드에서도 지속되는지 여부
- NPC 드리프트의 누적 패턴

**결론**: 2편의 원고는 "파이프라인이 정상인지"를 판단하기에 충분하다 — **정상이 아니다**. 다만 "얼마나 비정상인지"의 정밀 측정에는 추가 생산이 필요하다.

## 8. 종합 판단

### 파이프라인 상태: 기능적 작동, 구조적 불완전

프로젝트 0_260318의 파이프라인은 원고를 생산할 수 있는 상태이며 실제로 2편을 생산했다. 그러나 설계된 안전망과 품질 관리 체계의 대부분이 비활성 또는 무시 상태에서 작동하고 있다.

### 핵심 리스크 3선

1. **Director 단독 재량 체제**: Python 검증 지표가 전수 미달이어도 Director가 고점을 부여하여 통과시키는 구조. 품질 게이트가 사실상 단일 LLM의 주관적 판단에 의존한다.

2. **보조 시스템 전면 비작동**: 연속성 추적(빈 테이블 5개), 실패 분석(AttributeError 10회), 벡터 검색(vec0 미로드), 비용 계측(Stage 2-3 누락), 품질 리스크 플래그(write-only) — 5개 보조 시스템이 모두 무력화 상태.

3. **아크↔원고 구조 어긋남**: ep1이 Arc ep1+ep2 내용을 병합하면서 이후 에피소드의 beat 매핑이 어긋남. 2편 시점에서는 피해가 제한적이나, 추가 생산 시 누적 불일치 심화 위험.

### 생산 원고 품질

- ep1: 서사 밀도는 있으나 대화 극도 부족(8%), 웹소설 장르 기대치와 괴리.
- ep2: ep1 대비 개선(대화 13-14%) 되었으나 여전히 목표의 절반 미만.
- 두 편 모두 Director 고점(98-99)을 받았으나, 이 점수의 신뢰성은 위 분석에서 의문이 제기되었다.
