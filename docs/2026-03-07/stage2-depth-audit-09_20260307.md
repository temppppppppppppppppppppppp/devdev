## 1. 핵심 발견: LLM 레버리지 수익 산술 오류

**근본 원인**: LLM이 레버리지 수익을 계산할 때 `가격변동률 × 레버리지배수`를 정확히 수행하지 않고, **"원금의 약 100% 수익"으로 단순화**하는 패턴이 관찰됨. 투자물 장르에서 독자가 계산기를 두드리면 모순이 드러나는 수준.

### 오류 누적 경로

```
Arc 2: 유가 62→67, 3배 → 수익률 24.19% (Arc 주장 25%) ← 미세 괴리
Arc 3: 유가 62→75, 3배, 50% 청산 → 수익 4.72억 (Arc 주장 5.2억) ← 10% 과대
Arc 4: 금 620→680, 3배, 1/3 청산 → 수익 1.45억 (Arc 주장 5억) ← 245% 과대 ★
Arc 5: 금 620→701.5, 3배, 전량 청산 → 수익 3.94억 (Arc 주장 ~5억) ← 27% 과대
최종: 계산상 ~39억 vs Arc 주장 50.13억 ← 11억 과대 누적
```

## 4. 검증 코드 한계 분석

### NC-1 (Python-only 9개 검사)

| 감지 가능 | 감지 불가 |
|-----------|----------|
| "5억+5억=12억" 명시적 산술 | "횡보" 서술 vs 4.25억 수익 (서술-수치 의미 모순) |
| "10억×3배=60억" 명시적 레버리지 | 여러 문장에 걸친 암묵적 산술 |
| FactLedger vs 서술 숫자 교차 (5% 임계) | 대사 안의 수치 오류 (대사 제거 후 검사) |
| "X달러→Y달러×N배→Z%" 명시 패턴 | 레버리지 수익이 별도 문장에 서술된 경우 |

### NS-3-B (Arc vs Block 교차검증)

- `capital_after` **단일 키**만 비교, 30% 임계값
- 서사적 목표("횡보 국면")와 수치 괴리는 미감지
- 투자물에서 매 Arc 3건씩 경고 발생 (경고 피로)

### PATCH-B (소지품)

- 금전 문자열 토큰화 오류 지속 ("2,000,000,000원" → "000" 아이템 오인)
- `items_consumed` 교차 확인 없음 (소멸 감지만, 사유 미검증)

## 7. 근본 원인 → 대응 방안

### 원인 1: LLM의 레버리지 산술 능력 부족

투자물 장르에서 `가격변동률 × 레버리지배수 × 원금 = 수익`을 정확히 계산하지 못함. 특히 금 투자(Arc 4~5)에서 "원금의 100% 수익"으로 단순화하는 경향.

**대응 옵션**:
- **A. Stage 2 Python 사후검증 추가** — Arc 생성 후 `genre_ext`의 레버리지/진입가/청산가/원금에서 수익을 Python으로 역산, 30% 이상 괴리 시 advisory → Director MC 주입. NC-1 확장 또는 신규 체크.
- **B. Stage 2 프롬프트에 산술 템플릿 주입** — Arc 생성 프롬프트에 "수익 = 원금 × (청산가-진입가)/진입가 × 레버리지배수. 반드시 이 공식으로 검산하라" 명시.
- **C. NS-3-B 확장** — `capital_after` 외에 `leverage_return`, `entry_price`, `exit_price` 등 교차검증 키 추가.

### 원인 2: Director가 Arc 4~5 수치를 놓침

Arc 2~3에서는 정확히 잡았으나 Arc 4~5에서 100점 통과. 금 투자 구간에서 Director의 산술 검증 능력이 저하된 것으로 추정.

**대응 옵션**:
- **D. NC-1에 "암묵적 레버리지 교차검증" 추가** — Arc 전문에서 진입가/청산가/레버리지/수익 금액을 regex 추출 → Python 역산 → 괴리 시 Director advisory 주입.
- **E. Director 프롬프트에 산술 검증 의무화** — "레버리지 수익 서술이 있으면 반드시 (청산가-진입가)/진입가 × 배수로 검산하라" 추가.

### 원인 3: "서술-수치 의미 모순" 감지 공백

"횡보" + "4.25억 수익" 같은 모순은 NC-1(Python)도, Director(LLM)도 체계적으로 감지하지 못함.

**대응 옵션**:
- **F. 시장 상태 라벨 vs 수치 변동 Python 교차검증** — Arc에서 "횡보/급등/폭락" 키워드 추출 + 가격 변동률 추출 → "횡보"인데 10%+ 변동이면 advisory.

## 8. 결론

**Stage 2 자체의 파이프라인 로직은 정상**. Director가 Arc 2~3에서 수치 모순을 정확히 감지하고 교정한 것이 증거. 그러나 **LLM의 레버리지 산술 능력이 구조적으로 부족**하며, 특히 금 투자(Arc 4~5)에서 Director마저 놓치는 갭이 존재.

투자물 장르의 수치 신뢰성을 확보하려면 **Python 기반 레버리지 역산 검증(옵션 A/D)**이 가장 ROI 높음. LLM에 산술을 맡기는 것은 대원칙 1에도 부합하지 않음 — "Python은 수집만, 판단은 LLM이"에서 **산술 검증은 수집/사실확인 영역**이므로 Python이 담당하는 것이 적절.

**확신도: 99%** — Arc 5개 전문 산술 교차검증 + 로그/DB 전량 확인 + 검증 코드 한계 분석 완료.
