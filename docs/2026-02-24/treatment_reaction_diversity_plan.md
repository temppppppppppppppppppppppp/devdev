## 2. 개선 전략

### 전략 A: 캐릭터별 감정 아크 설계 (고정)

반복의 근본 원인은 각 인물의 감정이 "경외→복종" 단일 방향으로만 설계되어 있어,
등장할 때마다 같은 선상에서 반응하기 때문.
→ 인물마다 블록 구간별 **고정 포지션**을 부여해서 리셋 방지.

#### 마이클 첸 구간 설계
```
Block  7~14 : [게이트키퍼 → 경외기]  "어떻게 알았어?" 허용 구간
Block 15~22 : [실용적 파트너기]       이익 공유, 정보 교환 관계. 경외 표현 금지
Block 23~35 : [신뢰 동업자기]         묻지도 따지지도 않고 실행. 감탄 없음
Block 36~50 : [공포/거리두기]          규모가 너무 커져 오히려 관계가 소원해짐
Block 51~59 : [수용과 우정]            더 이상 놀라지 않음. 인간적 유대
Block 60    : [마무리]                 친구로 남음
```

#### 제이슨 (OTC 딜러) 구간 설계
```
Block 19~28 : [의심기]      "진짜 미친놈" 허용 구간
Block 29~39 : [체념기]      "그냥 시키는 대로"로 고정. 더 이상 감탄/의심 없음
Block 40~52 : [충성 실행자] 주도적으로 준비하고 선행. 리액션이 아닌 행동으로
Block 53~59 : [은퇴 준비]   자신의 이익 챙기기 시작. 독립적 행동
```

#### 박성호 PB 구간 설계
```
Block  2~ 6 : [경외기]      맹목적 추종 도달
Block  7~19 : [실무자]      감탄 없이 VIP 관리 역할만. 등장 최소화
Block 20~   : [거의 미등장] 연락책 수준. 매 등장 시 신규 정보 제공 역할만
```

## 3. 작업 순서

### Phase 1: Intensity 리듬 조정 (기계적, 빠름)
- 위 표의 12개 블록 `emotional_beat.intensity` 수정
- Python 스크립트로 일괄 처리 가능
- **리스크 없음**

### Phase 2: 캐릭터 구간 설계 적용 (수작업, 시간 필요)
- 각 캐릭터의 `relationship_delta` before/after 문구 수정
- 60블록 × 등장 인물별 확인
- **블록당 평균 2~3개 항목 수정**

구체 수정 범위:
- 마이클 첸: 34개 블록 중 Block 15 이후 27개 수정
- 제이슨: 19개 블록 중 Block 29 이후 12개 수정
- 박성호: 9개 블록 중 Block 7 이후 6개 수정

### Phase 3: power_shift 문구 조정 (선택적)
- "경외한다/굴복한다/무릎을 꿇는다" → 구간별 다른 표현으로
- Phase 2 완료 후 남은 중복 패턴 정리

### 결정 4 — Block 1 주인공 유능함·목적성 강화

**현재 Block 1 문제점:**
- `stakes`: "기회는 이번 한 번뿐"이라는 외적 압박만 있음
- `content.solution`: 아버지에게 담담하게 선언하는 수준. 구체적 전략 보임이 부족
- `emotional_beat.type`: `rebirth` → 재탄생 감정은 있으나 "이 사람 진짜 된다" 확신을 주는 임팩트 부족

**강화 방향:**
1. `content.context`에 회귀 직후 18년치 정보를 **정렬하는 장면** 추가
   - "원유는 2월에, 이란은 3월에, 나이지리아는 4월에..." 타임라인 정리 묘사
   - 독자가 주인공의 머릿속 데이터베이스를 직접 보는 느낌
2. `content.solution`에 법인 설립 및 계좌 개설의 **전략적 이유** 명시
   - 왜 해외 선물인가 / 왜 개인 자산만 쓰는가 / 왜 지금인가
3. `stakes` 재작성: 실패 시 단순 낙인 → "이번 생도 실패하면 다시 없다"는 존재론적 무게

### 결정 5 — 경제 지식 해설 삽입 (현판 문법)

**현판(현대판타지) 독자 특성**: 투자물에서 경제 메커니즘 설명 = 장르 쾌감의 일부.

**삽입 위치 원칙:**
- 주인공이 새 투자를 **결정하는 블록**의 `content.solution`에 1~3문장 해설 추가

- 해설은 주인공의 내적 독백 형식으로 (독자에게 말 거는 느낌)

**적용 대상 블록 (투자 진입 블록 위주):**

| 스테이지 | 활용 방식 | 적합성 | 비고 |

| **Stage 0 — block enricher** | block 단위로 enrichment 요청 | ✅ 즉시 투입 가능 | block_id + content 모두 충족 |
| **Stage 0 — 역설계** | 원고 대신 treatment 직접 입력 → Bible/스타일 추출 | ✅ 높음 | content 필드가 충분히 풍부 |
| **Stage 2 — Arc 생성** | treatment blocks → analyst → arc 설계 | ✅ 높음 | genre_ext 필드가 analyst 입력으로 직접 활용 |
| **Stage 3 — Blueprint** | arc 기반 blueprint 변환 | △ 간접 | treatment 직접 참조 안 함 |
| **Stage 4 — 원고** | blueprint → 원고 생성 | △ 간접 | 단, 컨텍스트 주입 시 추가 필드 가치 발생 |

---

### 9-3. 추가 필드들의 잠재 가치

직접 파싱은 안 되지만, LLM 컨텍스트로 전달될 때 유효한 필드들:

| 필드 | 잠재 가치 | 활용 가능 스테이지 |
|------|----------|-----------------|
| `foreshadow` / `callback` | arc 연속성 검증, 복선-회수 체인 유지 | Stage 2, Stage 3 |
| `power_shift` / `relationship_delta` | 캐릭터 관계 상태 추적 | Stage 4 |
| `emotional_beat` / `tension_level` | Director 심사 기준 보조, 강약 조절 | Stage 4 |
| `regression_ext` | 회귀물 설정 일관성 유지 | Stage 4 |
| `genre_ext.capital_before/after` | 자본 연속성 검증 | Stage 2 연속성 검사 |

### 9-4. 현재 한계 및 해소 방법

**한계 1**: `stakes`, `power_shift`, `relationship_delta` 등이 Stage 4 프롬프트에 주입되지 않으면 LLM이 이를 무시할 수 있음.

→ **해소**: `stage4_context_builder.py`의 컨텍스트 빌딩 단계에서 treatment block의 해당 필드를
  원고 생성 프롬프트에 명시적으로 주입하는 로직 추가 필요. (현재 미구현)

**한계 2**: `emotional_beat.type` 값들 (`rebirth`, `vindication`, `calm_before_storm` 등)이
  시스템 내부 enum과 다른 커스텀 타입이라 Director 심사 로직과 직접 연결되지 않음.

→ **해소**: 현재는 LLM 컨텍스트 힌트로만 활용. 추후 Director 심사 프롬프트에 tension_level을
  기준으로 고/저강도 판단 기준 추가 가능.

**한계 3**: `yearly_summary`, `instruments` 같은 골든루트 전용 필드는 범용 스키마와 충돌 없음
  (시스템이 모르는 필드는 무시하므로 안전).

### 9-5. 결론

> **이 Block JSON은 현 시스템에서 Stage 0과 Stage 2에 즉시 투입 가능한 양식이다.**
> 다만 `stakes`, `power_shift`, `relationship_delta`, `emotional_beat` 등 풍부한 추가 필드들의
> 가치를 실제로 뽑으려면 Stage 4 컨텍스트 빌더에 주입 로직을 추가해야 완전 활용이 된다.
> 현재 상태에서는 이 필드들이 70% 가량 소비되지 않고 있음.

**권장 사항**: 본 플랜 작업(리액션 다양화, 경제 해설 추가) 완료 후,
Stage 4 컨텍스트 빌더에 treatment 추가 필드 주입 로직을 별도 TF로 진행할 것.
