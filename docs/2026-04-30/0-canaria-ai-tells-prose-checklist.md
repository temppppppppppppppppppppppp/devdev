## 1. 회차 헤더 형식 — `# 부제` 금지

### 문제
드래프트 1행이 `# 회귀, 그리고 선언`, `# 자본의 재편` 같은 **마크다운 헤더 + 한국어 부제** 형식. 일부 회차는 `# 제11화`, `# 제12화: 75달러의 임계점`처럼 표기 자체도 일관되지 않음.

### 왜 AI 티
- 한국 웹소설(카카오페이지/문피아/노벨피아) 본문 텍스트에 부제는 거의 없음. 회차 제목은 플랫폼 메타데이터로 따로 들어감.
- AI가 "장 제목"이라는 문어체 도서 규범으로 학습된 흔적.
- 드래프트 내 부제 표기 형식이 회차마다 다른 것 자체가 자동생성 흔적.

### 처리 (2026-04-30 합본 기준)
- 합본에서는 `ⓚ001` ~ `ⓚ015` 단일 형식으로 통일, 부제는 모두 제거.
- 원본 ep 파일은 미수정. 합본만 정리됨.

### 향후 원칙
- 본문 내부에는 회차 식별자만. 부제는 별도 메타 필드로 관리.
- 부제가 꼭 필요하면 본문 1문장에 녹이기.

## 2. `[장소명]` 무대지문 금지

### 문제
씬 전환 직후 `[저택 1층 서재]`, `[저택 현관 앞]` 식의 **시나리오/희곡 무대지문**이 단독 줄로 박혀 있음.

### 왜 AI 티
- 시나리오 포맷이지 소설 본문 포맷이 아님. 한국 웹소설 본문에는 거의 안 씀.
- 직후 본문에서 어차피 "서재 문이 열렸다", "현관 등 뒤로 문이 닫혔다"로 장소가 자연 묘사됨 → **이중 표지**.
- `***` 씬 브레이크가 이미 있는데 `[장소]`까지 박는 것은 트리플 표지.

### 처리 (2026-04-30 합본 기준)
- 합본 1화 L86 `[저택 1층 서재]`, L152 `[저택 현관 앞]` 두 줄을 직전 빈 줄과 함께 삭제.
- 13화 L2265 `[미국 서브프라임 모기지 연체율 상승 속도 가파름. 일부 지역 주택 가격 하락세 뚜렷.]`은 **신문/리포트 인용** 톤이라 보존. 이 형식은 인용·발췌에만 한정 사용.

### 향후 원칙
- 무대지문 형식 `[장소]` 본문 직접 삽입 금지.
- 장소는 다음 문장 도입부에 자연스럽게 풀기 ("서재 문이 열렸다…").
- `***` 씬 브레이크 직후의 `[…]` 단독 줄은 **자동 의심**.
- 인용·보고서·뉴스 헤드라인 발췌는 예외 — 단, 본문 안에서 화자/매체가 분명해야 함.

## 3. 벽돌 단락 (한 줄에 여러 문장) 금지

### 문제
한 줄에 4~6문장이 한 단락으로 묶인 사례가 다수. 80자+ 줄 325개, 120자+ 152개, 200자+ **38개** (합본 기준 진단).

예시 (1화 L5):
> 숨이 막혔다. 산소가 부족한 물고기처럼 입을 벌린 채 거친 숨을 토해냈다. 목구멍을 타고 넘어오는 것은 차가운 겨울의 매연도, 반지하 셋방의 지독한 곰팡이 냄새도 아니었다. 은은하고 고급스러운 라벤더와 샌달우드가 섞인 디퓨저 향기였다.

### 왜 AI 티
- 한국 웹소설 모바일 가독성 표준은 **1문장 = 1줄**, 길어야 2문장.
- AI는 "한 단락 = 의미 묶음 여러 문장"이라는 문어체 도서 규범으로 학습 → 산문체 단락을 통째로 한 줄에 던짐.
- 모바일 화면에 6~7줄 벽돌이 들어차면 즉시 "AI 글" 신호.

### 사용자 선호 형식 (위 예시 변환):
```
숨이 막혔다. 산소가 부족한 물고기처럼 입을 벌린 채 거친 숨을 토해냈다.

목구멍을 타고 넘어오는 것은 차가운 겨울의 매연도, 반지하 셋방의 지독한 곰팡이 냄새도 아니었다.

은은하고 고급스러운 라벤더와 샌달우드가 섞인 디퓨저 향기였다.
```

### 처리 상태 (2026-04-30 시점)
- **미수정.** 작업량 큼(2,500줄 → 4,000~5,000줄 규모 리라이팅).
- 사용자 정책: regex/휴리스틱 일괄 변환 금지. 회차별 수동 검수 필요.
- 권장 진행: 1화부터 한 회차씩, 끊을 위치 제안 → 승인 → 적용.

### 향후 원칙
- 1문장 = 1줄. 길어도 2문장.
- 쉼표로 호흡을 길게 끄는 의도적 장문은 예외 — 단, 그 줄 자체가 내러티브 리듬을 만드는 경우에만.
- 대화 직후 묘사는 같은 문단에 붙여도 무방.
- 자동 일괄 변환(마침표 뒤 줄바꿈) 금지 — 호흡 깨짐 위험.

## 4. 일반 원칙 — 자동/일괄 변환 금지

사용자 명시 정책 (2026-04-30):
> "regex/휴리스틱 같은 거 금지. 수동으로 맥락 파악하고 해야 할 거 같은데"

### 적용 범위
- 본문 의미·문장 단위에 영향을 주는 변환은 모두 수동 맥락 검토.
- 단순 메타(헤더 형식 통일, 빈 줄 정리 등)는 일괄 처리 허용.
- 애매하면 사용자에게 단일 사례 확인 후 진행.
