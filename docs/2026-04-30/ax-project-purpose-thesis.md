# 글도비 목적과 문제 정의 메모

작성일: 2026-04-30
상태: 내부 메모, 3pass 감리 완료
연결 이슈: GitHub #145, "AX팀 제공 자료 제작 및 3pass 감리"

## 한 줄 정의

글도비는 문학 일반을 자동화하려는 프로젝트가 아니라, 산업형 장르 웹소설 생산 공정을 LLM pipeline으로 다루려는 프로젝트다.

## 문제 정의

이 문서에서 말하는 웹소설은 순수 문학 일반이 아니라 산업형 장르 콘텐츠다.

이 영역의 핵심은 독창적 문장미 하나가 아니다. 더 중요한 것은 독자가 기대하는 범주 안에서 반복되는 보상 구조를 안정적으로 제공하는 것이다.

- 대리만족
- 캐릭터 매력
- 장르 문법
- 회차별 hook
- 갈등과 보상의 반복
- 설정과 관계의 장기 일관성
- 독자가 이미 알고 기대하는 패턴의 변주

따라서 글도비가 다루는 질문은 "천재 작가의 고유한 필력을 LLM이 대체할 수 있는가"가 아니다.

더 정확한 질문은 아래에 가깝다.

> 정해진 장르 범주 안에서 독자가 기대하는 패턴, 감정 보상, 캐릭터 관계, 회차 단위 서사 리듬을 장기적으로 일관되게 생산할 수 있는가?

## 왜 LLM인가

LLM은 이 문제에 적합한 후보 기술이다.

산업형 장르 웹소설은 완전한 무작위 창작물이 아니라 반복 가능한 패턴들의 조합에 가깝다. 장르별 클리셰, 인물 관계, 갈등 구조, 보상 타이밍, 회차 말미 hook, 권력 상승, 관계 역전, 정보 공개 같은 장치들이 반복적으로 재배치된다.

이런 성격 때문에 LLM은 초안 생산, 변주, 대안 생성, 감리 대상 후보 생산에 강점을 가질 수 있다.

하지만 단순히 "길게 써 줘"로는 충분하지 않다.

장기연재에서는 아래 문제가 누적된다.

- 이전 회차의 사실을 잊는 문제
- 캐릭터 상태와 관계가 흔들리는 문제
- 설정, 수치, 사건 결과가 drift되는 문제
- 장르 보상 타이밍이 무너지는 문제
- 초반 선택이 후반 회차에 반영되지 않는 문제
- retry를 반복하면서 비용과 지연이 폭증하는 문제

따라서 글도비의 목적은 LLM에게 긴 원고를 한 번에 쓰게 하는 것이 아니다.

글도비의 목적은 LLM 생성물을 기획, 생성, 검증, 감리, retry, settlement하는 장기연재 생산 pipeline을 만드는 것이다.

## AX팀에 전달할 때의 framing

AX팀에는 이 프로젝트를 "챗봇으로 소설 쓰기"가 아니라 "장기 콘텐츠 생산 공정 자동화"로 설명하는 것이 맞다.

검토받고 싶은 핵심도 문장 스타일 polishing이 아니다. 더 근본적인 병목은 아래다.

1. 장기기억과 연속성의 authority boundary
2. Stage4 retry/post-select conflict로 인한 비용과 응답 지연
3. 모델 routing, context cache, session memory의 비용 대비 효과
4. final accepted context와 blueprint lineage의 freshness proof
5. 장기연재 품질을 증명할 수 있는 benchmark와 telemetry

즉 글도비의 중심 질문은 아래와 같다.

> LLM이 패턴화된 장르 콘텐츠를 양산할 수 있다는 전제 위에서, 그 생산물을 장기연재 수준으로 통제하고 검증할 수 있는 pipeline을 만들 수 있는가?

## 외부 표현 시 주의점

"웹소설은 문학이 아니다"라는 문장은 내부 문제의식으로는 유효하지만, 외부 검토 요청 문서에는 그대로 쓰지 않는 편이 좋다.

권장 표현:

> 글도비가 우선 대상으로 삼는 것은 문학 일반이 아니라, 반복 가능한 장르 문법과 독자 보상 구조를 가진 산업형 장르 웹소설입니다.

이 표현은 논쟁을 줄이면서도 핵심을 유지한다.

## 3pass 감리

1차 - 의도:

- 글도비를 만드는 이유와 자동화 대상의 성격을 분리했다.
- "문학 일반"과 "산업형 장르 웹소설"을 운영 정의로 구분했다.

2차 - 안전:

- 외부 전달 시 논쟁적일 수 있는 표현은 직접 문구와 권장 문구로 분리했다.
- AX팀이 비용/응답지연/토큰 최적화 관점으로 이해할 수 있도록 pipeline framing을 유지했다.

3차 - 유용성:

- 기존 AX 제출 패킷 앞에 붙일 배경 메모로 사용할 수 있다.
- 커버노트에 넣을 경우 1~2문단으로 축약 가능한 형태다.
