## 실행 프로토콜 (Sonnet 4.6 혼선 방지)

### 핵심 원칙

- 병렬 실행은 `재료(JSON) 생성`까지만 허용
- DB 적재는 반드시 `단일 작업자 1명`만 수행
- Sonnet 터미널은 DB/SQL 접근을 절대 시도하지 않음

### 1단계: 재료 생성 (병렬)

- 각 터미널은 결과를 JSON 파일로만 만든다.
- 저장 위치: `test_material/json_outputs/`
- 파일명 규칙: `<terminal>-<slug>.json` (예: `t3-time-axis-2010-2011.json`)
- 출력 형식: 코드펜스/설명문 없이 `순수 JSON`만
- 금지: DB insert, update, delete, merge, schema 변경

### 2단계: DB 적재 (직렬)

- DB 적재 담당은 Codex/G5 한 세션으로 고정
- JSON 유효성 검증 후 적재
- `source=<terminal>` 기준으로 건수 검증
- 중복 방지: 동일 `id` 재적재 시 무시(또는 upsert 정책 명시)

### 3단계: 상태 반영

- 적재 완료 터미널만 `v`, 미적재는 `x`
- `Evidence Tables`에는 실제 반영된 테이블만 기록

### Sonnet 4.6 오더 템플릿 (복붙용)

```text
[역할]
너는 "재료 생성 전용" 리서처다.

[절대 금지]
1) DB 접속, SQL 실행, DB 파일 수정
2) 다른 터미널 결과 파일 수정
3) 설명문/마크다운 출력

[반드시 수행]
1) 지정된 터미널 1개만 처리
2) 스키마에 맞는 JSON 배열 생성
3) id 접두사와 기간/키워드/최소 수량 준수
4) 날짜순 정렬

[최종 출력]
JSON 배열 1개만 출력 (코드펜스 금지)
```

### 운영 메모

- 질문의 답은 `네`: Sonnet에는 "재료만 만들어라"로 고정하는 것이 안전함
- DB 넣기와 상태 업데이트는 후속 단일 파이프라인으로 분리
