## 4. Director fix_scope reasoning 추가

### 문제

Director가 REJECT 시 `fix_scope` ("inplace" / "partial" / "full")를 반환하지만, **왜 그 범위를 선택했는지 근거가 없음**.

현재 스키마에는 "뭐가 잘못됐는지"(`contradiction_check`, `feedback.action_items`)는 있지만, "그 문제들의 조합이 왜 이 수정 범위를 요구하는지"는 설명하지 않음.

### 현재 흐름

1. Director → `fix_scope: "partial"` 반환
2. Stage4 interview_round → fix_scope 값으로 inplace/patch/full 분기 (L160~208)
3. Chief Writer → feedback의 action_items만 보고 작업

### 필요한 이유

- **Chief Writer 정밀도**: "씬 3만 재배치" vs "전체 구조 재설계" 같은 맥락을 CW가 알 수 있음
- **LOG-1 분석**: REJECT 로그에 fix_scope만 있고 근거가 없으면, 나중에 왜 partial인지 full인지 분석 불가
- **대원칙 #3 강화**: Director 주권 = 판단의 투명성. 근거 없는 판정은 주권이 아니라 독재

### 구현 방향

1. `response_schemas.py` — `fix_scope_reasoning` 필드 추가 (REJECT 시에만)
2. `config/prompts/director.yaml` — 프롬프트에 가이드 추가: "fix_scope를 정한 근거 (어떤 문제의 조합이 이 수정 범위를 요구하는가)"
3. Chief Writer에 `fix_scope_reasoning` 전달 배선

### 예시

```json
{
  "fix_scope": "partial",
  "fix_scope_reasoning": "모순은 1건(수치 오류)이고 구조는 양호하나, 씬 3의 배치를 바꿔야 하므로 부분 재작성 필요"
}
```

```json
{
  "fix_scope": "full",
  "fix_scope_reasoning": "장면 4~6이 완전히 누락되었고, 최종 위치가 설계와 맞지 않음. 전체 구조 재설계 필요"
}
```

### 수정 범위 (예상)

| 파일 | 변경 |
|------|------|
| `modules/core/response_schemas.py` | `fix_scope_reasoning` 필드 1개 추가 |
| `config/prompts/director.yaml` | 프롬프트 가이드 2줄 추가 |
| `modules/core/stage4_interview_round.py` | CW에 reasoning 전달 |

**규모**: ~20줄. LLM 토큰 비용 미미 (reasoning 한 문장 정도).

## 5. [P0 BUG] V73 자본금 파싱 — 한국어 복합 금액 오변환

### 증상

3화, 5화, 6화에서 반복 발생:
```
WARNING:[V73] 자본금 불일치 감지 (ep5): HUD capital=38억 3,154만 200원(→383154200억), 원고=38억
```

HUD에 저장된 `38억 3,154만 200원`이 **383,154,200억**으로 표시됨. 실제로는 ~38.3억.

### 원인 (2개 위치)

#### 원인 1: HUD→숫자 변환 시 단위 혼동

- **파일**: `modules/core/stage0/preset_registry.py` L549~588
- **함수**: `_parse_korean_number()`
- HUD의 `capital` 필드가 `"38억 3,154만 200원"` 같은 한국어 복합 형식으로 저장됨
- `_parse_korean_number()`는 정수 3,831,540,200을 정확히 반환하지만, 이 값이 이후 "억" 단위로 재해석될 때 **3,831,540,200억**으로 오인됨

#### 원인 2: 원고에서 자본금 추출 시 복합 형식 미지원

- **파일**: `modules/core/stage4_post_processor.py` L103~130
- **함수**: `_extract_capital_from_manuscript()`
- 정규식이 `"38억"` 단독만 매칭, `"38억 3,154만 200원"` 복합 형식 미지원
- 결과: 원고에서 38.0억만 추출 (실제 38.3억)

### 재현 예시

```
입력: "자본금은 38억 3,154만 200원입니다"
기대: 38.3154억
실제: 38.0억 (원고 추출) vs 383154200억 (HUD 표시)
```

### 수정 범위

| 파일 | 변경 |
|------|------|
| `modules/core/stage4_post_processor.py` | `_extract_capital_from_manuscript()` 복합 금액 정규식 추가 |
| `modules/core/stage4_post_processor.py` | `_reconcile_capital()` HUD 값 단위 정규화 |

## 6. [P1 BUG] Stage 3 Director 선택-사유 불일치 (V60.97 Silent Swap)

### 증상

Blueprint 1화 Director 출력:
```
선택: 후보 2
사유: ...후보 2는 시간 충돌 내부 모순...후보 3은 위치 불일치...
      따라서 후보 1이 가장 적합합니다.
```

사유에서 "후보 1이 최적"이라 했는데 `선택: 후보 2` 반환.

### 원인

- **파일**: `modules/domain/agents/director_ensemble.py` L554~565
- **함수**: `select_and_judge_ensemble()`
- **V60.97 Silent Swap 로직**: LLM이 선택한 후보(A)가 Python 검증 미통과 시, 분량 기준으로 다른 후보(B)로 **조용히 교체**
- 교체 후 `selection_reason`은 **원래 LLM 응답 그대로** 유지 → 선택과 사유 불일치

### 흐름

1. LLM: "후보 A 선택. 이유: 후보 1이 가장 적합"
2. Python 검증: 후보 A가 `qualified_indices`에 없음
3. V60.97: 분량 최대인 후보 B로 교체
4. 출력: `selected=B`, `selection_reason="후보 1이 가장 적합"` ← **불일치**

### 수정 범위

| 파일 | 변경 |
|------|------|
| `modules/domain/agents/director_ensemble.py` | V60.97 swap 시 `selection_reason`도 갱신 |
