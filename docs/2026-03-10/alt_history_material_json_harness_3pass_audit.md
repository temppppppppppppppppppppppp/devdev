## Pass 1. 규칙 구조 / 모순 감리

### 점검 포인트

- 기본 운영 배치가 실제로 `18터미널 압축 혼합 배치`로 고정돼 있는가
- `개별 팩 상한`과 `압축 배치 예외`가 서로 충돌하지 않는가
- canonical wave taxonomy와 표준 dispatch id가 혼동되지 않게 분리돼 있는가

### 확인 결과

- 기본 운영 배치는 `CTX 8 + LCTX 10 = 총 18`로 명시돼 있다.
- `42터미널 풀배치`는 예외 모드로만 남아 있고, 기본 운영값이 아니다.
- `3. 작업 단위 규칙`은 개별 팩 상한을 유지하되, `AH-STD18-1900-1950-B01`은 표준 맵 예외로 해석하게 정리돼 있다.
- `18.4 canonical wave와 표준 dispatch id 구분` 절이 추가돼, `18.2`의 정규 wave와 `22.4`의 `STD-*` 호출용 식별자가 분리됐다.
- `22.4 표준 터미널 맵`의 `wave_id`는 모두 `STD-*`로 바뀌어, 예전처럼 `T1`이 두 뜻으로 읽히는 충돌이 사라졌다.

### 개선 반영 사항

- `42터미널 기본값`을 `18터미널 기본값`으로 교체
- `CTX/LCTX` 분업 구조를 표준 맵에 고정
- `STD-*` dispatch id 도입으로 이름 충돌 제거
- 개별 팩 규칙과 압축 배치 예외를 분리

### 판정

- PASS

## Pass 2. 저컨텍스트 실행성 / 오더 해석 감리

### 점검 포인트

- `너는 1번 터미널이다`만 받아도 자기 row를 복원할 수 있는가
- `CTX`와 `LCTX` 작업 범위가 구분돼 있어 모델 능력별 분배가 가능한가
- 저컨텍스트 작업자가 멋대로 다음 팩으로 넘어가지 않게 막혀 있는가

### 확인 결과

- 축약 호출 모드에서 작업자는 로컬 오더 시트를 내부 복원한 뒤에만 파일을 쓸 수 있다.
- 축약 호출 지원 범위는 `AH-STD18-1900-1950-B01`의 `1~18`로 고정돼 있다.
- `1~8`은 `CTX`, `9~18`은 `LCTX`로 분리돼 있어, Codex/GPT-5/Opus와 Sonnet 계열을 분업시키기 쉽다.
- `22.5 기본 산출 규격`이 `CTX-STD-T*`, `CTX-STD-P*`, `CTX-STD-H*`, `LCTX-STD-S*`, `LCTX-STD-C*`로 나뉘어 있어 목표 수량도 계층별로 다르게 잡힌다.
- `23. 저컨텍스트 Sonnet 안전장치`에서 강제 실행 순서, 금지 행동, 질문 규칙, 보고 규격이 단계별로 고정돼 있다.
- `24. 완료 후 프로토콜`이 `status -> next_action -> completion_note -> 보고 -> 중단` 흐름을 강제한다.

### 개선 반영 사항

- `1~18`만 축약 호출 허용
- `19 이상`, `B02 이상`, 커스텀 범위는 전체 오더 시트 모드로 격리
- 완료 보고 예시를 `STD-T1 / 1900~1910` 기준으로 수정
- 저컨텍스트 질문 예시와 충돌 파일 예시를 최신 맵 기준으로 교체

### 판정

- PASS

잔여 리스크:

- `19 이상 비표준 터미널`은 여전히 전체 오더 시트가 필요하다.
- basename 충돌은 의도적으로 질문하도록 설계돼 있으므로, 배치 coordinator가 충돌 처리 규칙을 계속 관리해야 한다.

## Pass 3. UTF-8 / 문자 무결성 감리

### 점검 포인트

- UTF-8로 정상 읽히는가
- 구형 축약 호출 범위 흔적이 남아 있는가
- 물음표 3개 연속이 남아 있는가
- actual `U+FFFD`가 남아 있는가

### 확인 결과

- 하네스 본문은 UTF-8로 정상 읽힌다.
- 감리 문서도 UTF-8로 정상 읽힌다.
- 구형 축약 호출 범위와 구형 campaign id 흔적은 제거됐다.
- 구형 Sonnet 예시도 최신 `1900~1910 / STD-T1` 예시로 교체됐다.
- `triple_q` 검색 결과는 0건이다.
- actual `U+FFFD` 검색 결과도 0건이다.

### 판정

- PASS

## 개선방안

현재 문서는 표준 `18터미널 압축 혼합 배치` 기준으로는 충분히 강하다. 다만 더 올릴 수 있는 개선은 4개다.

1. `terminal_id -> 로컬 오더 시트` 자동 출력 helper script 추가
   - 지금은 문서 표를 읽어 해석한다.
   - 스크립트가 있으면 `너는 12번 터미널이다` 입력만으로 `source / payload / meta / 목표 수량`을 바로 뽑을 수 있다.

2. `Mode B`용 `.meta.json` 템플릿 파일 선제공
   - 지금은 문서 규격만 있다.
   - 실제 템플릿이 있으면 저컨텍스트 작업자의 필드 누락이 더 줄어든다.

3. dry-run 결과를 `.meta.json`에 자동 반영하는 보조 스크립트 추가
   - 현재는 `status`, `next_action`, `completion_note`를 수동 갱신한다.
   - 자동화하면 coordinator 감리 부담이 줄어든다.

4. `AH-STD18-1900-1950-B01.manifest.json` 추가
   - 하네스 전체를 읽지 않고도 표준 `1~18` 맵을 기계적으로 가져갈 수 있다.
   - 특히 저컨텍스트 작업자에게 안정성이 더 올라간다.

위 4개가 들어가면 신뢰도는 98~99%까지 올릴 수 있다.
