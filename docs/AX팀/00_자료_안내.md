# AX팀 전달 자료 안내

이 폴더는 AX개발팀에 전달할 글도비 LLM 파이프라인 검토 자료입니다.

Markdown 문서를 바로 보기 어려운 경우에는 `5_PDF판/` 폴더의 PDF 문서부터 보시면 됩니다. 같은 번호의 Markdown 문서와 PDF 문서는 같은 내용을 담고 있습니다.

검토 목적은 다음 다섯 가지입니다.

- LLM 파이프라인 구조 검토
- 비용 및 응답 지연 절감 가능 지점 검토
- 토큰 사용량 및 맥락 캐시 최적화 검토
- GCP/Vertex AI 직결 호출, 세션 메모리, 맥락 캐시 사용 방식 검토
- 비개발자 관점에서 MVP 범위, 적정 예산, 개발 기간, 실전 테스트 기준, 계속 투자 여부를 판단할 수 있는 의사결정 기준 수립 지원
- 안정화 종료 시점, 상업성 레이어/장기기억 검증 순서, 1차 개발 종료 조건을 포함한 로드맵 의사결정 보조

## 원본 자료 공유 방향

기본 방향은 AX팀 내부 검토에 필요한 자료를 최대한 열어 전달하는 것입니다. 원고, 원본 DB, LLM 호출 장부, 캐시 장부, 로그는 비용/지연/연속성 병목을 보는 데 중요하므로 공유 후보에 포함합니다.

다만 실제 비용이 나가거나 외부 계정에 접근할 수 있는 정보는 제외합니다. 예를 들면 `.env`, API key, OAuth token, service account JSON, billing console 접근 정보, 개인 계정 비밀번호, 배포/클라우드 인증 정보입니다.

## 검토 요청 핵심

- Stage4의 작가 에이전트 + 검토 에이전트 + 재시도 루프 비용/응답지연
- 최종 승인 맥락, 설계도 계보, 정착 상태의 권한 분리
- GCP/Vertex AI 직결 호출에서 맥락 캐시와 세션 메모리가 실제 비용/지연/품질에 주는 영향
- 맥락 캐시의 단순 적중률이 아니라 최신성 검증 기준
- 원고 전문 없이도 비용/토큰/응답지연을 분석할 수 있는 최소 관측 패킷
- 현재 상태를 PoC, MVP, alpha, beta, 운영 준비 중 어디로 봐야 하는지에 대한 판단 기준
- 적정 예산, 개발 기간, 실전 테스트 규모, 계속 투자/축소/전환 기준을 비개발자가 이해할 수 있는 형태로 정리해 주는 의사결정 보조
- 추가 안정화/최적화 이후 상업성 레이어와 장기기억 검증을 어떤 순서로 진행해야 1차 개발 종료를 선언할 수 있는지에 대한 로드맵 검토
