# 공유 가능 / 공유 제외 자료

이 문서는 AX팀 검토를 위해 어떤 자료를 공유할 수 있고, 어떤 자료는 반드시 제외해야 하는지 정리합니다.

## 현재 공유 원칙

이번 검토는 AX팀 내부 검토 한정으로 가능한 한 원본 자료를 열어 전달하는 방향입니다.

이전 기준은 원고 전문, 원문 프롬프트, 원본 DB를 기본 제외로 두었지만, 비용/응답지연/토큰/캐시/장기기억 병목을 정확히 보려면 원본 DB와 로그의 구조가 필요합니다. 따라서 돈이 나가거나 계정 접근이 가능한 자료만 제외하고, 나머지는 공유 후보로 둡니다.

## AX팀 내부 검토용 공유 후보

| 자료 | 공유 여부 | 비고 |
| --- | --- | --- |
| 시스템 구성도 | 가능 | 단계, 역할, 저장소, 관측 지점 설명 |
| 단계별 확대 구성도 PDF | 가능 | S0/S2/S3/S4 확대 설명 |
| 모델/역할별 호출 집계 | 가능 | 비용/지연 분석 핵심 |
| 입력/출력/캐시 토큰 집계 | 가능 | 회차/역할/모델 단위 |
| 추정 비용 집계 | 가능 | 실제 청구액은 AX팀 확인 필요 |
| 회차별 시도 수 | 가능 | 재시도 병목 진단 |
| 실패 범주 집계 | 가능 | 예: 제약 위반, 선택 후 충돌, 논리 오류 |
| 캐시 생성/적중/건너뜀/오류 집계 | 가능 | GCP/Vertex 캐시 정책 검토 대상 |
| 세션 메모리 envelope 관측값 | 가능 | 정본이 아니라 보조 계층으로 해석 필요 |
| 최종 승인 맥락 상태 | 가능 | 본문/해시/권한 상태를 함께 볼 수 있음 |
| 설계도 계보 해시/출처 상태 | 가능 | stale lineage 진단 |
| 원고 전문 | AX팀 내부 검토 한정 가능 | 작품 IP이므로 외부 재공유 금지 |
| 원문 프롬프트 | AX팀 내부 검토 한정 가능 | 비용/토큰/캐시 병목 분석용 |
| LLM 원문 응답 전체 | AX팀 내부 검토 한정 가능 | 원고와 판단 근거 포함 |
| 원본 로컬 DB | AX팀 내부 검토 한정 가능 | `llm_calls`, `context_cache_attempts`, `stage_attempts`, `manuscripts` 등 포함 |
| 비식별화되지 않은 LLM 입출력 로그 | AX팀 내부 검토 한정 가능 | 원문이 포함될 수 있으므로 취급 주의 |
| `projects/0_카나리아` 원본 폴더 | AX팀 내부 검토 한정 가능 | 프로젝트 DB, drafts, logs, stage 산출물 포함 |

## 반드시 제외하거나 별도 확인할 자료

| 자료 | 공유 여부 | 이유 |
| --- | --- | --- |
| `.env` 파일 | 제외 | API key, project id, 로컬 경로, secret 포함 가능 |
| API key / secret / token | 제외 | 실제 비용 발생 또는 계정 접근 가능 |
| OAuth refresh/access token | 제외 | 외부 계정 접근 가능 |
| GCP service account JSON | 제외 | 클라우드 자원 접근 가능 |
| private key / pem / p12 | 제외 | 서명 또는 계정 접근 가능 |
| billing console 접근 정보 | 제외 | 비용/계정 접근 가능 |
| 개인 계정 비밀번호 | 제외 | 보안상 공유 불가 |
| 배포/운영 인증 정보 | 제외 | 외부 서비스 접근 가능 |

## 제한 공유 메모

- 원고, 프롬프트, LLM 응답, DB는 "외부 공개"가 아니라 AX팀 내부 기술 검토용입니다.
- AX팀 외부 재공유, 재학습, 샘플 공개, 타 프로젝트 재사용은 하지 않는 전제로 전달합니다.
- 실제 청구 대조를 위해 GCP/Vertex billing 화면이나 프로젝트 접근이 필요하면, 원본 credential을 넘기기보다 화면 공유 또는 AX팀 권한 부여 방식으로 처리하는 편이 안전합니다.

## AX팀에 확인받고 싶은 점

- 원본 DB와 로그를 열어 드리면 비용/응답 지연 진단을 더 정확히 할 수 있는가?
- 실제 청구 대조를 위해 필요한 기간, GCP 프로젝트, 모델, 호출 식별 기준은 무엇인가?
- GCP/Vertex 직결 호출에서 캐시 생성/조회/저장 비용을 어떤 필드로 분리해 봐야 하는가?
- 세션 메모리와 맥락 캐시가 오래된 맥락을 재유입하지 않게 하려면 어떤 무효화 지문이 필요한가?
