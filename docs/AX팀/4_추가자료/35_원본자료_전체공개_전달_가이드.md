# 원본자료 전체공개 전달 가이드

기준일: 2026-04-30

## 결론

AX팀 검토에는 원본 자료를 가능한 한 열어 전달하는 편이 좋습니다.

글도비의 병목은 단순한 문장 표현 문제가 아니라 LLM 호출 구조, GCP/Vertex AI direct 호출, 세션 메모리, 맥락 캐시, DB 정착, 재시도 루프, 장기 연속성 권한 경계가 얽힌 문제입니다. 비식별 집계만으로는 비용과 지연의 원인을 충분히 보기는 어렵습니다.

따라서 원고 IP와 프롬프트 IP는 민감하지만, AX팀 내부 기술 검토 한정으로 공유 후보에 넣습니다. 반대로 실제 비용이 나가거나 계정 접근이 가능한 키, 토큰, credential은 제외합니다.

## 민감정보 스윕 결과

2026-04-30 기준으로 아래 범위를 읽기 전용으로 스윕했습니다.

- `docs/AX팀`
- `projects/0_카나리아`
- `projects/0_카나리아/project_data.db`의 TEXT 계열 컬럼

고위험 패턴:

- OpenAI 형태 `sk-...`
- Google API key 형태 `AIza...`
- GitHub PAT 형태 `ghp_...`
- OAuth 계열 장기/단기 토큰 문자열
- private key block
- client secret 문자열
- `bearer ...`
- API key 대입문
- authorization 대입문

결과:

| 범위 | 결과 |
| --- | --- |
| 텍스트/JSON/로그/백업 파일 | 고위험 credential 패턴 미검출 |
| `project_data.db` TEXT 컬럼 | 고위험 credential 패턴 미검출 |
| DB 스캔 예외 | `vec_episodes`는 로컬 `vec0` 모듈 부재로 schema 조회 예외. 일반 credential 저장 후보 표는 아님 |

이 스윕은 현재 파일/DB 표면 기준의 자동 패턴 점검입니다. GCP 콘솔, 로컬 shell 환경변수, 브라우저 세션, OS credential manager에 저장된 값은 이 패키지에 포함하지 않는 전제로 별도 취급해야 합니다.

## 반드시 제외할 것

아래는 발견 여부와 무관하게 전달 패키지에서 제외합니다.

- `.env`
- GCP service account JSON
- API key, secret, bearer token
- OAuth refresh/access token
- private key, `.pem`, `.p12`
- billing console 접근 정보
- 개인 계정 비밀번호
- 배포/운영 credential

## AX팀에게 함께 설명할 문장

아래 문장을 커버 메일 또는 회의 첫머리에 붙이면 됩니다.

> 원본 프로젝트 폴더와 DB까지 열어 드릴 수 있습니다. 다만 API key, OAuth token, service account, billing console 접근 정보처럼 실제 비용 발생이나 계정 접근이 가능한 credential은 제외했습니다. 원고, 프롬프트, LLM 응답, DB는 외부 공개가 아니라 AX팀 내부 기술 검토용으로만 봐 주시면 됩니다.

## 적대적 3회 감리

### 1회차: 자료 충분성

원본 DB와 로그를 제외하면 Stage4 비용 병목, 캐시 효과, 재시도 구조, 세션 메모리 효과를 재현하기 어렵습니다. 따라서 원본 패키지 공유 방향은 타당합니다.

### 2회차: 보안/비용 누수

원고와 프롬프트는 IP 민감자료지만, 비용 누수 자료는 아닙니다. 반대로 API key, GCP service account, OAuth token, billing 접근 정보는 한 줄이라도 있으면 비용/계정 리스크입니다. 현재 자동 스윕에서는 고위험 credential 패턴이 발견되지 않았습니다.

### 3회차: AX팀-facing 실용성

AX팀에게는 "무엇을 봐 달라"가 명확해야 합니다. 원본 패키지를 던질 때는 `00_자료_안내.md`, `1_필수문서/00_한장_요약.md`, `1_필수문서/05_모델_비용_토큰_표면.md`, 이 문서를 먼저 보게 하고, 이후 DB와 logs를 열게 하는 순서가 좋습니다.

## 추가 서베이 필요 여부

큰 방향의 외부 리서치는 지금 더 필요하지 않습니다.

필요한 것은 자료 보강형 서베이입니다.

1. AX팀이 실제 청구 데이터와 로컬 추정치를 대조할 수 있는 기간/모델/호출 id 기준 확정
2. 캐시/세션 메모리 benchmark에서 비교할 before/after 구간 확정
3. 원본 DB에서 민감 credential이 없다는 전달 전 최종 스윕
4. AX팀이 DB를 바로 열 수 있도록 key table 목록과 샘플 쿼리 제공
5. 비개발자 의사결정을 위해 MVP 범위, 예산, 개발 기간, 실전 테스트 규모, 계속 투자 기준을 잡을 수 있는 판단표 확정

이 중 1번, 2번, 5번은 AX팀과 함께 정해야 하며, 3번과 4번은 이 패키지에서 선제 보강할 수 있습니다.
