# Vertex 청구 대조 요청표

이 문서는 로컬 추정 비용과 실제 Vertex 청구 데이터가 어느 정도 일치하는지 확인하기 위한 요청표입니다.

현재 문서의 비용은 로컬 `llm_calls` 집계에서 산출한 추정값입니다. 실제 과금 정책, 캐시 토큰 과금, preview 모델 가격/쿼터, 저장 비용은 AX팀 또는 GCP/Vertex 청구 기준으로 확인이 필요합니다.

## AX팀 확인 요청

| 확인 항목 | 현재 값 / 질문 | AX팀 확인값 |
| --- | --- | --- |
| 실제 Vertex 청구액 | 위 기간/호출 집계와 실제 청구가 어느 정도 일치하는가? |  |
| preview 모델 단가 | `gemini-3.1-pro-preview` 단가와 쿼터 정책은 무엇인가? |  |

| 캐시 입력 토큰 과금 | 캐시 토큰은 일반 입력 토큰과 다르게 과금되는가? |  |

| `count_tokens` 사용 | 호출 전 토큰 계산이 비용 절감에 유리한가? |  |
| API 지연 분해 | API 자체 지연과 클라이언트 재시도/연속 생성 지연을 분리할 수 있는가? |  |

## 권장 대조 방식

1. 대조 기간을 하나로 고정합니다.
2. 해당 기간의 모델별 호출 수, 입력/출력/캐시 토큰, 추정 비용을 집계합니다.
3. Vertex 청구 데이터에서 같은 기간과 모델을 조회합니다.
4. preview 모델과 정식 모델을 분리합니다.
5. 캐시 토큰과 일반 입력 토큰의 과금 차이를 분리합니다.
6. 차이가 크면 로컬 비용 계산식, 모델 단가, 캐시 단가, thinking 토큰 처리 방식을 재검토합니다.

## 이 대조가 필요한 이유

- 지금은 로컬 추정 비용 기준으로 병목 우선순위를 세우고 있습니다.
- 실제 청구 구조가 다르면 최적화 우선순위가 달라질 수 있습니다.
- 특히 캐시 토큰이 비용을 얼마나 줄이는지 확인해야 캐시 정책을 확장할지 판단할 수 있습니다.
