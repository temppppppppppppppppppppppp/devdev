# 운영/기획 의사결정 지원 요청

기준일: 2026-04-30

## 목적

이 문서는 AX팀에 기술 검토뿐 아니라 운영/기획 판단 기준을 요청하기 위한 자료입니다.

핵심 요청은 개발 로드맵과 예산 설정입니다. S4 실제 원고 단계의 연속성 최적화가 기술적으로 어느 정도 가능하고 필요한지 확인한 뒤, 그 결과를 바탕으로 다음 4주/8주/12주 목표, 실전 테스트 규모, 적정 비용 범위, 계속 투자/축소/전환 기준을 정하는 데 필요한 판단 기준을 요청드립니다.

글도비는 LLM 기반 장기 웹소설 생산 파이프라인입니다. 현재는 15화 감독형 생성, GCP/Vertex AI 직결 호출, 세션 메모리, 맥락 캐시, DB 정착, Stage4 검토/재시도 루프까지 갖춘 상태입니다.

다만 개발 실무자가 아닌 운영/기획 담당자 관점에서는, 현재 상태를 기술적으로 어느 단계로 봐야 하는지, 어느 정도 예산과 기간이 적절한지, 다음 목표를 어떻게 잡아야 하는지에 대한 판단 기준이 필요합니다.

## 현재 내부 판단

현재 내부 판단은 다음과 같습니다.

```text
1차 생산성 이슈는 어느 정도 닫혔다.
이후는 실전 테스트를 통해 디버깅, 안정화, 비용 통제 기준을 잡아야 한다.
현재는 안정화 후반 단계에 가까운 상태로 본다.
추가 안정화/최적화 이후 상업성 레이어와 장기기억을 검증하면 1차 개발 종료 단계로 볼 수 있을 것으로 예상한다.
```

즉 지금은 "아예 만들 수 있느냐"보다 "반복 실행해도 비용, 품질, 속도가 예측 가능한가"를 확인해야 하는 단계라고 보고 있습니다.

이 판단이 맞는지 AX팀 관점의 확인을 요청드립니다.

특히 안정화, 상업성 레이어, 장기기억 검증, 1차 개발 종료 선언을 어떤 순서와 기준으로 묶어야 하는지 로드맵 판단 기준이 필요합니다.

## 판단이 어려운 지점

| 질문 | 왜 어려운가 |
| --- | --- |
| 현재를 PoC/MVP/alpha/beta/운영 준비 중 어디로 봐야 하는가 | 기능은 있으나 실전 안정성 기준이 모호함 |
| 어느 정도 예산이 적정한가 | LLM 비용은 회차, 재시도, 모델, 캐시 정책에 따라 크게 달라짐 |
| 어느 정도 개발 기간이 적정한가 | 코드 기능 개발과 운영 안정화, 실전 테스트 기간을 구분하기 어려움 |
| 몇 회차/몇 작품을 테스트해야 하는가 | 15화 감독형 생성은 성공했지만 완전 자동 장기 실행 기준은 별도 |
| 계속 투자해야 하는가 | 생산성, 품질, 비용 중 어떤 지표를 기준으로 판단해야 할지 불명확함 |
| 어디서 멈추거나 축소해야 하는가 | 비용 증가가 정상적인 탐색인지 구조적 실패인지 구분하기 어려움 |
| 언제 1차 개발 종료로 봐야 하는가 | 안정화, 상업성, 장기기억 검증의 종료 조건이 아직 명확하지 않음 |
| 카나리아 테스트를 무엇으로 통과 처리해야 하는가 | 단순 S2-S3-S4 재현성만으로는 팔리는 장르물 품질, 스타일, 장기 연속성, 회차별 보상 구조를 보장하기 어려움 |

## AX팀 의사결정 검토 질문

1. 현재 글도비는 PoC, MVP, alpha, beta, 운영 준비 중 어디에 가깝습니까?
2. "1차 생산성 이슈는 닫혔고, 이후는 실전 테스트 기반 디버깅/안정화 단계"라는 판단은 맞습니까?
3. 다음 4주, 8주, 12주 목표를 어떻게 잡는 것이 현실적입니까?
4. 회차당, 작품당, 월 단위로 어느 정도 LLM 비용이면 정상 범위입니까?
5. 비용이 어느 수준을 넘으면 모델 라우팅, 캐시, 공정 축소, 제품 방향 전환을 검토해야 합니까?
6. 몇 회차/몇 작품/몇 반복 실행을 통과해야 MVP 검증으로 볼 수 있습니까?
7. 완전 자동 실행과 감독형 실행을 어떤 기준으로 분리해 평가해야 합니까?
8. 운영/기획 담당자가 매주 확인해야 할 대시보드 항목은 무엇입니까?
9. AX팀 관점에서 지금 가장 먼저 예산을 투입해야 하는 곳과 투입하지 말아야 하는 곳은 어디입니까?
10. 이 프로젝트를 계속 밀어붙일지, 범위를 줄일지, 특정 기능만 제품화할지 판단할 기준은 무엇입니까?
11. 현재를 안정화 후반 단계에 가까운 상태로 분류해도 됩니까?
12. 추가 안정화/최적화 이후 상업성 레이어와 장기기억 검증을 통과하면 1차 개발 종료로 판단해도 됩니까?
13. 카나리아 테스트는 S2-S3-S4 재현성뿐 아니라 장르가드, 스타일 레퍼런스, 장기기억/연속성, 상업성 보상 구조까지 함께 검증하는 방식으로 설계해야 합니까?
14. 1차 개발 종료까지의 로드맵은 어떤 단계, 기간, 종료 조건으로 짜는 것이 좋습니까?

## 요청 산출물

AX팀 검토 후 아래 형태의 산출물이 있으면 의사결정에 바로 활용할 수 있습니다.

- 현재 단계 분류: PoC/MVP/alpha/beta/운영 준비 중 어디인지
- 다음 4주/8주/12주 목표안
- 회차당, 작품당, 월 단위 적정 비용 범위
- 개발 기간과 안정화 기간의 분리 기준
- 실전 테스트 통과 기준
- 장르가드/스타일 레퍼런스/장기기억/상업성 보상 구조를 포함한 카나리아 테스트 평가표
- 계속 투자/축소/보류/전환 판단 매트릭스
- 운영/기획용 주간 대시보드 항목
- AX팀 지원이 가장 효과적인 우선순위 3개
- 추가 안정화/최적화, 상업성 레이어, 장기기억 검증, 1차 개발 종료 조건을 포함한 로드맵 의사결정안

## 결론

기술적으로 "무엇을 고쳐야 하는가"와 함께, 운영/기획 담당자가 "무엇을 목표로 잡고, 얼마까지 써도 되고, 언제 멈춰야 하는가"를 판단할 수 있는 기준이 필요합니다.

이 문서는 그 판단 기준을 AX팀에 명시적으로 요청하기 위한 자료입니다.
