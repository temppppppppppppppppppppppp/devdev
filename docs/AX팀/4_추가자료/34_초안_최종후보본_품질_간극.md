# Stage4 초안과 최종 후보본 품질 간극

이 문서는 왜 현재 Stage4 통과 원고를 곧바로 플랫폼 제출 후보본으로 보지 않는지 설명합니다.

원고 전문은 포함하지 않고, 산출물 간 통계와 문제 유형만 공유합니다.

## 핵심 결론

현재 Stage4는 설정, 분량, 설계도 반영, 장면 긴장에는 강합니다.

다만 모바일 독자용 최종 후보본 기준에서는 다음 문제가 남습니다.

- 줄과 단락이 길어 모바일에서 숨이 막히는 문제
- 과잉 비유, 과잉 감탄, 과잉 장르어가 반복되는 문제
- 돈/권력 대리만족이 숫자 반복으로 흐르는 문제
- 조연이 전문성을 가진 인물보다 놀라고 복종하는 인물처럼 보이는 문제
- 주인공 말투가 짧은 실무 지시보다 과한 선언문처럼 보이는 문제

따라서 Stage4 통과는 "사용 가능한 초안"이고, 별도 독자용 폴리싱 관문을 거쳐야 최종 후보본으로 보는 것이 안전합니다.

## 이미 하고 있는 보강과 남은 간극

현재 글도비는 일부 품질 문제를 줄이기 위해 문체 예시 기반 주입과 구조 패턴 도너를 사용하고 있습니다.

- 문체 예시 기반 주입: 원하는 문장 호흡, 말투, 장면 처리 방식을 예시로 제공하는 방식입니다. few-shot에 가까운 접근입니다.
- 구조 패턴 도너: 성공한 장르 전개 구조, 보상 타이밍, 관계 역전, 회차 후킹 같은 패턴을 참고 재료로 제공하는 방식입니다. 쉽게 말해 성공 사례에서 뽑은 참고 패턴입니다.

이 방향은 유효하지만 아직 충분하지 않습니다.

1. 예시와 도너를 많이 넣으면 입력 토큰과 응답 지연이 늘어납니다.
2. 예시가 너무 강하면 작품 고유 설정보다 예시 문체나 구조가 과하게 따라붙을 수 있습니다.
3. 구조 패턴은 Stage3 설계도 단계에 넣을지, Stage4 원고 생성 단계에 넣을지 역할 분리가 필요합니다.
4. 문체 문제는 Stage4 재시도로 해결할지, Stage4 이후 독자용 폴리싱 관문으로 분리할지 비용 기준이 필요합니다.
5. 현재는 도너가 실제로 재시도 수, 토큰, 최종 후보본 품질을 얼마나 개선하는지 비교 실험이 더 필요합니다.

따라서 AX팀에는 문체 예시/구조 패턴 도너를 더 쓰자는 단순 결론이 아니라, 어느 단계에 어떤 방식으로 넣어야 비용 대비 효과가 좋은지 검토를 요청드립니다.

## 모바일 가독성 비교

| 항목 | Stage4 초안 묶음 | 최종 후보본 |
| --- | ---: | ---: |
| 전체 라인 | 2,546 | 3,025 |
| 비어 있지 않은 라인 평균 길이 | 60.6 | 43.9 |
| p90 라인 길이 | 119.5 | 87.0 |
| 120자 이상 라인 | 154 | 75 |
| 200자 이상 라인 | 39 | 3 |
| 느낌표 | 90 | 4 |

해석:

- 최종 후보본은 줄 수가 늘고 평균 줄 길이가 줄었습니다.
- 긴 줄과 과한 감탄이 크게 줄었습니다.
- 이 차이는 내용 생성 문제가 아니라 모바일 독자용 가공 문제에 가깝습니다.

## 과잉 표현 감소 예시

아래는 원문 문장 공유 없이, 문제어 빈도만 비교한 표입니다.

| 표현 유형 | Stage4 초안 묶음 | 최종 후보본 |
| --- | ---: | ---: |
| 폭풍 | 10 | 0 |
| 패닉 | 10 | 0 |
| 미친 | 11 | 0 |
| 비명 | 14 | 0 |
| 짐승 | 5 | 0 |
| 포식자 | 6 | 0 |
| 압도 | 5 | 0 |
| 완벽 | 117 | 21 |
| 거대한 | 129 | 24 |
| 마른침 | 13 | 1 |

해석:

- Stage4 초안은 장면 긴장을 만들기 위해 강한 표현을 자주 씁니다.
- 최종 후보본에서는 같은 장면을 더 짧고 덜 과장된 표현으로 정리했습니다.
- 이 문제는 "원고 생성 실패"보다 "최종 독자용 레지스터 조정"에 가깝습니다.

## AX팀 검토와 연결되는 지점

이 품질 간극은 문체 문제처럼 보이지만, 파이프라인 비용 문제와도 연결됩니다.

1. Stage4에서 최종 후보본 기준까지 한 번에 달성하려 하면 재시도가 늘어날 수 있습니다.
2. 반대로 Stage4는 초안 통과에 집중하고, 별도 저비용 폴리싱 관문을 두면 비용을 더 예측 가능하게 만들 수 있습니다.
3. 독자용 폴리싱은 전체 재작성보다 짧은 수정/규칙 기반 점검/작은 모델 후보가 될 수 있습니다.
4. Stage4 통과 점수와 최종 제출 후보본 점수를 분리해야 합니다.
5. 문체 예시와 구조 패턴 도너는 품질을 올릴 수 있지만, 토큰과 지연도 늘릴 수 있으므로 별도 비용/효과 측정이 필요합니다.

## AX팀 검토 요청 사항

- 초안 생성과 최종 후보본 폴리싱을 분리하는 구조가 비용/응답 지연 관점에서 타당한가?
- 모바일 가독성, 과잉 표현, 문체 레지스터 같은 검사는 더 작은 모델이나 규칙 기반 점검으로 처리할 수 있는가?
- 폴리싱 관문을 Stage4 내부 재시도로 넣는 것과 Stage4 이후 별도 단계로 두는 것 중 어느 쪽이 더 비용 예측 가능성이 높은가?
- 최종 후보본 점수를 별도 지표로 두는 경우 어떤 관측값이 필요할까?
- 문체 예시와 구조 패턴 도너는 어느 단계에 넣는 것이 비용 대비 효과가 좋은가?
- 도너 적용 전/후를 비교하려면 어떤 최소 벤치마크 패킷이 필요한가?
