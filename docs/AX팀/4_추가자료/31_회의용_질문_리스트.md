# AX팀 회의용 질문 리스트

이 문서는 미팅에서 바로 확인하고 싶은 질문만 모은 목록입니다.

## 가장 먼저 묻고 싶은 질문

1. 현재 자료 기준으로 Stage4의 비용/응답 지연 병목은 API 자체 지연, 토큰 예산, 재시도 구조, 캐시 정책 중 어디에 가장 가깝게 보이나요?
2. 작가 에이전트와 검토 에이전트의 모델을 같은 등급으로 두는 것이 적절한가요?
3. `max_output_tokens` 같은 출력 예산은 역할별로 분리하는 것이 맞을까요?
4. 원고 생성 전에 옮길 수 있는 저비용 검증 항목이 있을까요?
5. 높은 점수를 받은 후보가 선택 후 충돌로 거절되는 경우, 전체 재작성 대신 더 싼 경로가 가능할까요?

## 캐시/세션 메모리 질문

6. Vertex 기준으로 캐시 입력 토큰, 캐시 생성, 캐시 저장, 캐시 읽기는 어떻게 과금되나요?
7. 캐시를 사용하려면 어떤 계보 지문이 있어야 오래된 맥락 재사용을 막을 수 있을까요?
8. 세션 메모리를 정본이 아니라 보조 증거로 사용할 때 필요한 안전장치는 무엇인가요?
9. 캐시/세션 메모리가 실제로 재시도 수를 줄였는지 증명하려면 어떤 비교 실험이 필요할까요?

## 관측/데이터 질문

10. 원고 전문과 원문 프롬프트 없이도 AX팀이 병목을 진단하려면 어떤 최소 필드가 필요할까요?
11. API 응답 지연, 재시도 지연, 연속 생성 지연, 캐시 지연을 분리하려면 어떤 타임스탬프나 로그가 더 필요할까요?
12. 로컬 추정 비용과 실제 Vertex 청구액을 대조하려면 어떤 기준으로 기간과 호출을 묶어야 할까요?

## 공정 구조 질문

13. S2를 장기적으로 S3 사전 점검/정규화 단계로 흡수하는 방향이 비용/지연 관점에서도 타당해 보이나요?
14. Stage4 통과를 최종 제출 후보본과 분리하고, 별도 독자용 폴리싱 관문을 두는 구조가 맞아 보이나요?
15. 장기 실행 검증과 비용 벤치마크를 어떤 형태로 설계해야 실사용 신뢰 기준을 주장할 수 있을까요?
16. 문체 예시 기반 주입은 매번 프롬프트에 넣는 것이 좋을까요, 검색/캐시로 넣는 것이 좋을까요?
17. 구조 패턴 도너(성공 사례에서 뽑은 참고 패턴)는 Stage3 설계도 단계와 Stage4 원고 생성 단계 중 어디에 넣는 것이 비용 대비 효과가 좋을까요?
18. 문체 예시와 구조 패턴 도너가 실제로 재시도 수를 줄이는지 보려면 어떤 비교 실험이 필요할까요?

## 회의 후 받고 싶은 산출물

- 비용/응답 지연 병목 우선순위
- 역할별 모델 라우팅 권고
- 토큰 예산 조정 권고
- 캐시/세션 메모리 사용 기준
- 최소 비식별 진단 패킷 필드 목록
- 문체 예시/구조 패턴 도너 운영 권고
- 장기 실행 검증/벤치마크 설계 권고
