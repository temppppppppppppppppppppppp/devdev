# 글도비 LLM 파이프라인 검토 요청

안녕하세요.

요청 주신 글도비 LLM 파이프라인 검토 자료를 전달드립니다.

이번 자료는 아래 세 가지 검토 목적에 맞춰 정리했습니다.

1. LLM 파이프라인 구조 검토
2. 비용 및 응답 지연 절감 가능 지점 검토
3. 토큰 사용량 및 맥락 캐시 최적화 검토

검토 전제는 다음과 같습니다. 저희가 파악하는 범위에서는 LLM을 통한 장편 글쓰기, 특히 장기 연재형 웹소설 생산에 대해 널리 합의된 표준 프로세스가 아직 없습니다. 글도비는 상업 웹소설을 반복 가능한 장르 패턴, 대리만족, 캐릭터 관계, 회차별 보상 구조를 가진 패턴 구조로 보고, 이를 LLM 파이프라인으로 안정적으로 생산할 수 있는지 검증하는 프로젝트입니다.

## 주요 검토 요청 사항

현재 가장 중점적으로 검토받고 싶은 부분은 Stage4 원고 생성 이후의 비용과 응답 지연입니다.

특히 아래 항목에 대한 의견을 부탁드립니다.

- 작가 에이전트와 검토 에이전트 호출이 반복될 때 비용이 누적되는 구조
- 비싼 원고 생성 호출 전에 더 앞단으로 옮길 수 있는 검증 항목
- 역할별 모델 라우팅과 출력 토큰 예산 분리 가능성
- 맥락 캐시 사용 시 필요한 최신성 검증 기준
- 최종 승인 원고, 회차 설계도, 장기기억 계층 사이의 권한 경계
- 원고 전문 없이 비용/지연 분석에 필요한 최소 관측 데이터

## 제출 범위

이번 공유 자료에는 시스템 구조, 데이터 흐름, 모델/토큰/비용 관측값, 구성도만 포함했습니다.

아래 항목은 기본 공유 범위에서 제외했습니다.

- 원문 프롬프트
- 원고 전문
- 원본 로컬 DB
- 비식별화되지 않은 LLM 입출력 로그
- 로컬 환경 설정 또는 인증 정보

필요하신 경우, 원고 전문을 제외한 비식별 집계 데이터나 제한된 샘플 형태로 추가 자료를 준비하겠습니다.
