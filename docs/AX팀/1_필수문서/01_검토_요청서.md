# 글도비 LLM 파이프라인 검토 요청

안녕하세요.

요청 주신 글도비 LLM 파이프라인 검토 자료를 전달드립니다.

이번 검토의 우선 요청은 두 가지입니다.

1. S4, 즉 실제 원고 생성/검토/정착 단계에서 연속성 문제를 어떻게 더 낮은 비용으로 조기에 탐지할지에 대한 최적화 검토
2. 현재 상태를 기준으로 앞으로의 개발 로드맵, 적정 예산, 실전 테스트 규모, 계속 투자/축소/전환 기준을 어떻게 잡을지에 대한 판단 기준 제안

아래 항목들은 위 두 요청을 판단하기 위한 하위 검토 항목입니다.

1. LLM 파이프라인 구조 검토
2. 비용 및 응답 지연 절감 가능 지점 검토
3. 토큰 사용량 및 맥락 캐시 최적화 검토
4. GCP/Vertex AI 직결 호출, 세션 메모리, 맥락 캐시 사용 방식 검토
5. 운영/기획 관점의 MVP 범위, 적정 예산, 개발 기간, 실전 테스트 기준, 계속 투자 여부 판단 기준
6. 안정화 종료 시점, 상업성 레이어/장기기억 검증 순서, 1차 개발 종료 조건을 포함한 로드맵 판단 기준
7. 카나리아 실전 테스트를 단순 S2-S3-S4 재현성 확인이 아니라 장르가드, 스타일 레퍼런스, 장기기억/연속성, 상업성 보상 구조까지 함께 보는 검증으로 설계할 수 있는지 검토

검토 전제는 다음과 같습니다. 저희가 파악하는 범위에서는 LLM을 통한 장편 글쓰기, 특히 장기 연재형 웹소설 생산에 대해 널리 합의된 표준 프로세스가 아직 없습니다. 글도비는 상업 웹소설을 반복 가능한 장르 패턴, 대리만족, 캐릭터 관계, 회차별 보상 구조를 가진 패턴 구조로 보고, 이를 LLM 파이프라인으로 안정적으로 생산할 수 있는지 검증하는 프로젝트입니다.

추가로, 개발 실무자가 아닌 운영/기획 담당자 관점에서는 기술 병목 진단뿐 아니라 의사결정 기준 수립도 필요합니다. 현재 내부 판단은 "1차 생산성 이슈는 어느 정도 닫혔고, 이후는 실전 테스트 기반 디버깅/안정화 단계"입니다. 이 판단이 맞는지, 현재 상태를 PoC/MVP/alpha/beta/운영 준비 중 어디로 봐야 하는지, 어느 정도 예산과 기간을 정상 범위로 봐야 하는지 검토 의견을 요청드립니다.

현재 로드맵 가설은 글도비가 안정화 후반 단계에 가깝고, 추가 안정화/최적화 이후 상업성 레이어와 장기기억 검증을 통과하면 1차 개발 종료 조건을 논의할 수 있다는 것입니다. 이 로드맵 판단이 타당한지, AX팀 관점에서 종료 조건과 다음 단계 순서를 어떻게 잡아야 하는지도 함께 확인 요청드립니다.

## 주요 검토 요청 사항

현재 가장 중점적으로 검토 요청드리는 부분은 S4 실제 원고 단계의 연속성 최적화와, 다음 투자/개발 단계를 정하기 위한 로드맵/예산 판단 기준입니다.

특히 아래 항목에 대한 검토 의견을 요청드립니다.

- S4에서 연속성 오류, 선택 후 충돌, 장기기억 반영 시점 문제가 어디에서 생기는지
- 비싼 원고 생성 호출 전에 더 앞단으로 옮길 수 있는 연속성/충돌 검증 항목
- 작가 에이전트와 검토 에이전트 호출이 반복될 때 비용이 누적되는 구조
- 역할별 모델 라우팅과 출력 토큰 예산 분리 가능성
- 맥락 캐시 사용 시 필요한 최신성 검증 기준
- 최종 승인 원고, 회차 설계도, 장기기억 계층 사이의 권한 경계
- 원고 전문 없이 비용/지연 분석에 필요한 최소 관측 데이터
- 현재 상태를 PoC, MVP, alpha, beta, 운영 준비 중 어디로 봐야 하는지
- 적정 예산, 개발 기간, 안정화 기간, 실전 테스트 규모, 계속 투자/축소/전환 기준
- 카나리아 테스트에서 재벌/회귀/투자/복수물 장르가드, 네이버 무연시 기준 문체/문단 호흡, 장기기억/연속성, 회차별 대리만족 보상 구조를 함께 검증하는 기준
- 운영/기획 담당자가 매주 확인할 수 있는 비용/품질/속도 대시보드 항목
- 추가 안정화/최적화, 상업성 레이어 검증, 장기기억 검증, 1차 개발 종료 선언을 어떤 순서와 기준으로 배치해야 하는지

이번 공유 자료에는 시스템 구조, 데이터 흐름, 모델/토큰/비용 관측값, 구성도, 현재 상태/장애물/지원 요청, 원본 자료 공유 가이드를 포함했습니다.

- 배포/운영 credential
