## 3. POC 과정에서 확인된 제약 및 전환 판단

POC 개발은 단발성 호출 기반으로 기능을 검증하는 방식으로 진행되었다. 이후 연속 생산 시뮬레이션을 진행하는 과정에서 현 Google Gemini API(직접 호출) 환경의 제약을 확인하였다.

**확인된 제약**: Gemini 3.x Pro 모델의 분당 요청 제한(RPM)이 본 시스템의 에피소드당 6회 이상 병렬 호출 구조와 충돌한다. 연속 생산 시 제한에 걸려 중단이 발생한다.

**현재 대응**: 4단계 모델 폴백 체인(gemini-3.1-pro → 3-pro → 2.5-pro → 2.5-flash) + API Key 멀티 로테이션 + 네트워크 오류 22회 재시도. 야간 무인 운영 수준의 안정성은 확보되었으나, 처리량 상한은 여전히 존재한다.

**전환 방안**: Vertex AI(Google Cloud)로 전환하면 동일 Gemini 모델을 기업 등급 호출 한도로 사용할 수 있다. 시스템 코드 변경은 API 인증 계층에 한정되며, 파이프라인 전체 재개발이 필요 없다.

### 병렬 생산 구조

본 시스템은 단일 에피소드 내 API 호출을 병렬로 처리한다(ThreadPoolExecutor, 6개 지점). Vertex AI 전환으로 RPM 제약이 해소되면 **복수 작품을 동시에 생산**하는 것이 가능해진다. 이론상 하루 100작품 생산이 가능하며, 이는 **생산량이 인력이 아닌 API 예산에만 비례하는 구조**임을 의미한다.

현재 목표는 하위권 복수 작품 대량 생산이다. 시스템 고도화가 완료되는 시점에는 투입 대비 생산량 비율(ROI)이 단계적으로 높아진다.
