Static findings:
1. Command readiness is gated by websocket state in renderer.
- index.html only runs actions when `window.geuldobiDesktop && _backendConnected`
- `_backendConnected` is driven by websocket open/close, not by command-channel health
- runKey itself goes through preload -> ipcMain -> main-process `bridgeFetch()` HTTP path

2. Concurrent prompt requests are dropped in renderer.
- renderer ignores `prompt_request` while dialog is already open
- PromptBroker stores a set of pending prompts per run and can issue more than one prompt lifecycle entry
- dropped renderer prompt means backend prompt can age into timeout/default

3. Reconnect path lacks explicit state resync.
- websocket reconnect on open calls `refreshQualitySummary()`
- preload exposes `getStatus()`, but renderer has no active consumer
- there is no source evidence of prompt replay, status resync, or active-run snapshot restore after websocket reconnect

4. Startup readiness barriers are split.
- splash polls `/status` until backend reports `idle`
- Electron main process also has an 8s fallback timer that can switch to the main window before that poll would give up
- main window separately waits on websocket connection and logs backend-undetected after 5s

5. bridgeFetch has no explicit timeout and has stale dead code.
- splash fetch uses AbortSignal timeout
- bridgeFetch in main.js uses plain fetch without timeout
- bridgeFetch contains a second error return block after an earlier return in the same branch

6. Renderer direct network ownership is explicitly split but not behaviorally normalized.
- splash status polling has its own timeout and retry loop
- main window websocket uses reconnect logic plus quality-summary refresh
- main window API key validation fetches Google directly from renderer and bypasses bridgeFetch timeout/error envelopes
- source contracts document these direct surfaces, but they do not yet impose shared timeout or telemetry behavior

7. Dead-candidate preload surfaces remain exposed while no live renderer consumer exists.
- preload exposes getStatus() and getWorkspacePath()
- desktop shadow hygiene tests assert they remain dead-candidate compatibility surfaces
- renderer reconnect path does not consume getStatus() for live state resync despite the method being present

8. Existing tests are strong on route/schema presence, weak on live state semantics.
- desktop transport tests cover route names, event schema, preload/main contract, and direct surface inventory
- no source-level regression found for websocket reconnect state resync
- no source-level regression found for concurrent prompt_request handling
- no source-level regression found for decoupling command readiness from websocket readiness
- no source-level regression found for bridgeFetch timeout behavior or startup handoff coherence
