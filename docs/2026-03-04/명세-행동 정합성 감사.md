## 4) 핵심 발견(수동 감사)

### F-1) PF-4는 현재 "스킵 제어"가 아니라 "진단 로그"

- 설정 문구:
  - `config/settings/validation.yaml:99`
    - `inplace_min_success_rate: 30   # ... 미만이면 스킵`
- 실제 코드:
  - 성공률 계산 함수는 존재 (`stage4_interview_round.py:28-54`)
  - 사용 지점 2곳 모두 `logging.info`만 수행 (`1142-1146`, `1694-1698`)
  - `inplace_min_success_rate` 참조는 repo 전체에서 config 한 곳만 검색됨
- 테스트도 "스킵하지 않음" 방향:
  - `tests/test_pass_with_fix.py:1954`

판정: **명세/주석과 실행이 어긋난 상태**
> **2026-03-04 수정**: YAML 주석을 "진단 로그용 (디렉터 주권주의: 스킵 안 함)"으로 교정 완료.

---

### F-2) 변경량 제어가 프롬프트 의존이라, 넓은 재작성 위험이 남음

- 프롬프트는 강함:
  - `chief_writer.yaml:81,86,87,99`
- 코드 강제는 약함:
  - Stage4 in-place는 응답 최소 길이 중심 (`chief_writer.py:817`, `stage4_interview_round.py:1160-1163`)
  - 패치 결과를 그대로 채택 가능 (`chief_writer.py:873-874`)
  - 문장/문단 diff 비율, 숫자/고유명사 보존율 같은 기계적 검증 없음

판정: **"부분수정 의도"는 있으나 "부분수정 집행 강제"는 약함**

---

### F-3) fix_scope는 프롬프트상 필수지만, 스키마상 optional

- 프롬프트:
  - `config/prompts/director.yaml:221,225` (동일 규칙 반복 블록 다수)
- 스키마:
  - `modules/core/response_schemas.py:146`, `168` required 목록에 `fix_scope` 없음
- 결과:
  - 런타임에서 PF-1 fallback(점수 기반) 코드가 필수 방어 로직으로 유지됨

판정: **명세와 구조화 출력 계약(schema) 불일치**

---

### F-4) 트렁케이션으로 "원본 그대로 유지" 보장이 약해질 수 있음

- 원고 패치 입력:
  - `smart_truncate(...150000, head_chars=20000)` (`chief_writer.py:803,811,965,973`)
- Arc/Blueprint 패치 입력:
  - `json.dumps(... )[:30000]` (`four_phase_arc_generator.py:624,722`, `three_phase_blueprint_generator.py:668`)

판정: **원본이 큰 경우 후반 맥락 손실 가능**

---

### F-5) Stage4 PF-3 소진 경로에서 상태 전파 불일치 가능성(고위험 후보)

- 소진 시 패치본 채택:
  - `final_manuscript = _last_patched_ms` (`stage4_interview_round.py:1253-1254`)
- 그러나 REJECT 경로 `previous_attempt`는:
  - 점수: `pre_firewall_score` 우선 (`1534`)
  - 원고: `selected_candidate.manuscript` 기준 (`1536`)
- `_execute_pass_with_fix_loop` 반환은 `director_result`(원본 객체)이고, `_current_audit_result`를 통째로 치환해주지 않음 (`1269`)

판정: **PF-3로 채택된 패치본이 다음 라운드 seed로 완전 전파되지 않을 가능성**  
비고: 이 항목은 재현 테스트 추가로 확정 필요(현재 문서에서는 "가능성"으로 분류).

## 6) 운영 감리 아이디어 (코드 수정 없이 즉시 가능)

1. 표본 감사
- 주 1회 `PASS_WITH_FIX + fix_scope=inplace` 30건 수동 판정(A/B/C 등급)
- A: 지적 지점만 수정 / B: 경미한 확장 / C: 사실상 재작성

2. 수치 지표(읽기 전용 DB 질의)
- `fix_scope=inplace`의 최종 PASS 전환률
- `patch_fallback` 비율 추세
- PASS_WITH_FIX 소진 후 REJECT 비율

3. 문장 보존율 샘플 체크(수동)
- 패치 전/후 총 길이 비율
- 고유명사/숫자/핵심 사실 변동 여부
- Director action_items 외 변경 영역 존재 여부

4. 감사 문서 운영 규칙
- 매 회차 감사 문서에 commit hash + 시각 기록
- 라인 기준 깨지면 `rg` 키워드 재매핑 후 갱신

## 7) 최종 감사 판정

- P0(즉시 장애급): 없음
- P1(운영 리스크): 있음
  - 이유: PASS_WITH_FIX가 "부분수정" 의도는 따르지만, 변경량 강제장치가 부족하고 일부 명세-행동 불일치(PF-4, schema 계약)가 존재

즉, 지금 상태는  
`부분수정 정책(문구)` > `부분수정 집행 강제(코드)` 구조다.
