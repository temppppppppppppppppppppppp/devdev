# TF: Golden Canary Block Accountability Triage

> 대상: `treatments/01_tr_투자물_골든_카나리아 테스트.json`
> 작성일: 2026-03-13
> 목적: OPUS 보고서를 그대로 따르지 않고, 실제 handoff gate 기준으로 block 책임 부족 구간을 분리한다.

---

## 1. 판정

- 분류 1순위: `production_density_failure`
- 분류 2순위: `handoff_false_pass`
- 핵심: 이 샘플은 `avg_bundle_chars`는 높지만, `callback_ratio`, `recognition` 신호, `section_rotation`, 후반 `stakes`, 후반 opponent 배치가 비어 있어 Stage 2/4가 알아서 메워야 하는 구간이 너무 많다.

## 2. 이번 triage에서 믿는 것 / 안 믿는 것

- 채택:
  - 후반 `stakes` 공허
  - 복선 회수 부족
  - 회귀 인정/재평가 반응 부재
  - 후반 긴장 급락
- 비채택:
  - `content` 각 필드 최소 100자 일괄 규칙
  - 전체 Treatment가 전반적으로 저밀도라는 진단

## 3. 실제 handoff 관점 취약점

- `avg_bundle_chars = 647.32`라서 평균 글자수는 문제의 본체가 아니다.
- `callback_ratio = 0.49`로 복선 회수 책임이 부족하다.
- 주인공의 비범함을 외부가 인정하거나 재평가하는 반응이 Treatment에 거의 잠겨 있지 않다.
- `section_rotation_missing = 60`이라 각 block이 arc 안에서 무슨 역할인지 안 잠겨 있다.
- 마지막 10블록 opponent 공백이 많아 후반 책임 소재가 흐려진다.
- 마지막 5블록 `stakes < 35자`가 다수라 해소 구간이 아니라 무압력 구간이 된다.

## 4. Block별 보강안

### Block 49 `폐허`

- 시장 저점 설명만 두지 말고, 이 타이밍을 본 사람이 누구인지 명시한다.
- 후보:
  - 박성호 PB
  - 패밀리오피스 리스크 실무자
  - OTC 거래 상대방
- `recognition_from`은 `없음`이 아니라 "박성호 PB가 이건 운이 아니라 실력이라고 인정하고 먼저 다음 거래를 붙으려 한다" 같은 문장으로 잠근다.

### Block 53 `의심의 계절`

- `AI 버블론`을 추상 시장이 아니라 이름 있는 애널리스트, 파트너, 기자 중 하나로 치환한다.
- `stakes`는 손실 공포만이 아니라 "이 사람을 더 이상 우연의 승자라고 넘길 수 없다"는 외부 인정이 만들어내는 압박으로 바꾼다.
- 예:
  - "수익보다 더 부담스러운 건, 누군가가 이 매매를 운이 아니라 실력이라고 인정하고 먼저 줄을 서기 시작하는 순간이다."

### Block 56 `정점`

- 익절 자체보다 "너무 정확한 상투 매도"의 흔적을 남긴다.
- callback은 가격 예측 실현에서 끝내지 말고, 그 정확함을 기억한 observer를 함께 남긴다.
- `recognition_from` 후보:
  - 기존 PB의 재평가
  - 해외 거래 파트너의 경탄
  - 패밀리오피스 내부 실무자의 신뢰 전환

### Block 57 `여름의 기다림`

- 관망 블록이라도 `재진입 비용`, `기다리는 동안 잃는 관계/평판`, `타이밍 오판 시 무너지는 다음 수`를 반드시 쓴다.
- 이 블록은 얇아지기 쉬우므로 "왜 기다리는가"가 아니라 "잘못 기다리면 무엇이 깨지는가"를 stakes에 쓴다.

### Block 59 `정리`

- `없음. 평화로운 정리.` 금지.
- 아래 중 1개 이상을 stakes로 고정한다.
  - 운용권 위임 후 주도권 상실
  - 가족 화해가 지배력 약화로 이어질 위험
  - 세무/규제/승계 문서 꼬임
  - 너무 완벽한 수익률이 남기는 추적 가능성

### Block 60 `골든 루트`

- 완전 무위험 해피엔딩 대신, 행복을 지키기 위해 무엇을 포기하거나 봉인하는지 남긴다.
- 마지막 블록의 stakes 후보:
  - 거버넌스
  - 가족
  - 후계
  - 정체 은폐
  - 전생 지식 봉인
- callback은 "성공했다"가 아니라 "무엇을 대가로 지켰는가"까지 닫는다.

## 5. 후반 49~60 공통 규칙

- 최소 4개의 이름 있는 opponent 또는 observer를 배치한다.
- 최소 4개의 non-empty `recognition_from` 또는 동등한 인정 반응을 배치한다.
- 마지막 5블록 `stakes < 35자` 금지.
- 마지막 3블록에 최소 1개 장기 복선 회수, 최소 1개 후폭풍 callback 유지.
- `section_rotation`을 전 블록 채운다.

## 6. 보강 단위

문자수 늘리기가 아니라 아래 4요소를 채우는 방식으로 고친다.

1. 이번 block에서 잃을 것
2. 누가 이상함을 감지했는가
3. 무엇을 회수했는가 / 무엇이 아직 열려 있는가
4. 자산이 권력, 관계, 통제로 어떻게 변환되는가
