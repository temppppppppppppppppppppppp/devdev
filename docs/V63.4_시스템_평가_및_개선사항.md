## P0: 즉시 수정 권장 (버그/데이터 정합성)

### 1. `_is_standalone_name()` 뒤쪽 한글 경계 미검사
- **파일**: `state_tracker.py:995-1007`
- **문제**: 앞쪽 한글만 검사, 뒤쪽 미검사 → "강철무" 텍스트에서 "강철" 오탐 가능
- **현재**: `before`만 검사 (`'\uAC00' <= before <= '\uD7A3'`)
- **수정안**: `after` (이름 뒤 글자)도 동일하게 한글 경계 검사 추가
- **영향**: 죽은 NPC 검증 3개 메서드 모두에 적용됨

### 2. 금융 레지스트리 DB 미저장
- **파일**: `state_tracker.py` (financial_number_registry)
- **문제**: 메모리에만 존재, 앱 재시작 시 소실
- **수정안**: `project_manager.py`에서 앵커 저장 (`save_anchor('financial_registry', ...)`)

### 3. NPC 병합 시 사망 정보 덮어쓰기 위험
- **파일**: `state_tracker.py:1175-1191` (merge_npc_registry)
- **문제**: 병렬 호출 시 사망 정보가 일반 정보로 덮어쓰기 가능
- **수정안**: `status == "dead"` 엔트리는 비사망 업데이트 차단

### 4. Director 캐시 검증 실패 시 폴백 없음
- **파일**: `director.py:3267-3305` (check_manuscript_history_with_cache)
- **문제**: 캐시 참조 LLM 호출 실패 시 원고 역사 검증 자체가 스킵됨
- **수정안**: except 블록에서 `check_manuscript_history_conflicts()` 폴백 호출

| 리스크 | 영향 | 완화 방안 |

| 장르 위반 경고 과다 → 프롬프트 비대화 | 중간 | `has_critical=True`인 경우만 경고 전달 |
| V0128 경로 vs 기본 경로 경고 포맷 불일치 | 낮음 | `pre_llm_critical_warnings` 키 통일 |

## 시스템 강점 요약 (유지/보존 대상)

1. **3단계 파이프라인** (Constraint→Ensemble→Validate): 책임 분리 명확
2. **Director 주권주의**: Python은 정보 제공, LLM이 최종 판단 (V63.4 완성)
3. **7-tier 검증 시스템**: PRE_LLM → CONTINUITY → BLOCKING → ... → ADVISORY
4. **야간 무인 운영**: API 키 순환(9개), 네트워크 복원력(22회 재시도), 타임아웃 방어
5. **V63.x 통합 완벽**: 제약 전달 체인, 투자물 금융 검증, 장기 기억 시스템 모두 정상
6. **9개 장르 동시 지원**: BaseGuard 추상화로 확장 용이
7. **state_changes 구조화**: 98% 정확도, Regex 폴백 안전망
8. **캐시 전략 4종**: cumulative_state, StateTracker 증분, Entity Registry, BlueprintMemory
