## 스파이크 1: PyInstaller + sqlite-vec 번들 (블로커 검증)

### 목적
sqlite-vec C 확장이 PyInstaller 번들에 정상 포함되는지 확인.
실패 시 exe 배포 아키텍처 전면 재검토 필요.

### 작업
```
1. 최소 테스트 스크립트 작성 (spike_pyinstaller.py):
   - import sqlite3
   - conn.enable_load_extension(True)
   - sqlite_vec 로드
   - 벡터 검색 1건 실행
   - "SPIKE-1 PASS" 출력

2. PyInstaller spec 작성 (spike_pyinstaller.spec):
   - hiddenimports에 sqlite_vec 포함
   - datas에 sqlite_vec .pyd/.so 바이너리 경로 추가

3. 빌드: pyinstaller spike_pyinstaller.spec
4. 실행: dist/spike_pyinstaller.exe
5. "SPIKE-1 PASS" 출력 확인
```

### 산출물
- `spikes/pyinstaller/spike_pyinstaller.py`
- `spikes/pyinstaller/spike_pyinstaller.spec`
- `spikes/pyinstaller/result.md` (성공/실패 + 번들 크기 + 에러 로그)

### 실패 시 대안
- one-dir 모드로 재시도
- sqlite-vec 대신 순수 Python 벡터 검색 폴백 검토
- result.md에 실패 원인 + 대안 기록

## 스파이크 2: subprocess stdin/stdout 제어 (Mode A 핵심)

### 목적
main_a.py를 숨김 프로세스로 기동하고, stdin으로 메뉴 키를 보내 stdout 응답을 파싱할 수 있는지 확인.

### 작업
```
1. 최소 테스트 스크립트 작성 (spike_subprocess.py):
   - subprocess.Popen으로 main_a.py 기동 (stdin=PIPE, stdout=PIPE, stderr=PIPE)
   - 메뉴 출력 대기 (stdout에서 "선택" 또는 "[0]" 패턴 감지)
   - stdin으로 "5\n" (종료 키) 전송
   - stdout에서 종료 메시지 수신 확인
   - "SPIKE-2 PASS" 출력

2. 타임아웃 처리:
   - 메뉴 출력 30초 대기
   - 초과 시 프로세스 kill + "SPIKE-2 TIMEOUT" 기록

3. 인코딩 확인:
   - stdout 한글 출력 깨짐 여부 (cp949 vs utf-8)
   - 필요 시 encoding 파라미터 조정
```

### 산출물
- `spikes/subprocess/spike_subprocess.py`
- `spikes/subprocess/result.md` (성공/실패 + stdout 샘플 + 인코딩 정보)

### 실패 시 대안
- main_a.py의 input() 호출이 subprocess와 호환 안 되는 경우 → input 래퍼 패치 검토
- result.md에 실패 원인 + 대안 기록

## 스파이크 3: FastAPI 브리지 스켈레톤

### 목적
subprocess 제어(스파이크 2) 위에 얹을 FastAPI 서버의 뼈대를 미리 구현.
스파이크 2 결과와 합치면 Mode A 동작.

### 전제
- 스파이크 2와 **병렬 착수 가능** (subprocess 호출부는 인터페이스만 정의, 스텁 사용)
- 스파이크 2 PASS 후 실제 subprocess 연결

### 작업
```
1. FastAPI 서버 스켈레톤 (modules/api/bridge_server.py):
   - POST /run → RunValidator(T4) 호출 → subprocess stdin 주입 (스텁)
   - POST /stop → subprocess kill
   - GET /status → {"state": "idle|starting|running", "pid": N}
   - WS /events → stdout 파싱 → event-schema-v1.json 형식 emit (스텁)

2. subprocess 래퍼 (modules/api/process_runner.py):
   - start(key, inputs) → Popen 기동 + stdin 주입
   - stop() → kill + cleanup
   - read_stdout() → 비동기 stdout 수집 (asyncio.create_subprocess_exec)
   - 인터페이스만 정의, 실제 구현은 스파이크 2 결과 반영

3. 기존 T4/T5/T6 모듈 연결:
   - /run 라우트에서 run_validator.validate() 호출
   - 위험키 시 risk_approval.validate() 호출
   - Mode B 프롬프트 시 prompt_broker 호출

4. 기동 확인: uvicorn modules.api.bridge_server:app --port 8300
   - GET /status → {"state":"idle"} 응답 확인
```

### 산출물
- `modules/api/bridge_server.py`
- `modules/api/process_runner.py`
- `spikes/bridge/result.md` (서버 기동 + /status 응답 캡처)

```

   - geuldobi-desktop/ 디렉터리 생성 (글도비 레포 루트 하위)
   - npm init + electron 설치

   - src/splash/splash.html — PenLine 아이콘(lucide) + 로딩바 + "시작하는 중..."
```

## GO / NO-GO 판정

| 조건 | 필수 |
|---|---|
| 스파이크 1 PASS (exe에서 sqlite-vec import 성공) | **필수** — 실패 시 배포 아키텍처 재검토 |
| 스파이크 2 PASS (stdin 키 전송 + stdout 수신) | **필수** — 실패 시 Mode A 불가, API 직접 통합 검토 |
| 스파이크 3 서버 기동 | 권장 — 스텁이라도 /status 응답 |
| 스파이크 4 스플래시 표시 | 권장 — 시각 확인용 |

**스파이크 1 또는 2가 FAIL이면 NO-GO. 대안 검토 후 재스파이크.**
