## 감리 1회 — 오탐 검토

**VAL-1, VAL-2 오탐 가능성 검토**:
`unified_blueprint_validator.py`, `stage2_finalizer.py` 등 다른 파일에 fix_scope/PASS_WITH_FIX 처리가 있을 수 있음. 그러나 `validation_orchestrator.py`는 6-Tier 통합 진입점으로, 이 파일에서 fix_scope를 Tier별로 전달하지 않으면 하위 Tier가 context로 받지 못함. Stage4 경로(`audit_manuscript`)는 별도이므로 이 오케스트레이터 한정 GAP으로 최종 판정. **오탐 아님.**

**VAL-8 오탐 가능성 검토**:
`scoring_validator.py`의 Python threshold 비교는 LLM이 각 항목 점수를 매긴 결과를 합산한 것을 Python이 임계값과 비교하는 구조. "판단"이 LLM에게 있고 Python은 수학적 집계만 한다고 볼 수도 있음. 대원칙 1의 정신에 부합하므로 P0→P2 하향. **오탐 가능성 있음, P2 유지.**

**공통-A threshold_helper 오탐 가능성 검토**:
`except Exception: _cfg = None`은 ConfigManager() 초기화 실패 시 전체 임계값을 기본값으로 폴백시키는 의도된 방어 코드일 수 있으나, 오류 원인을 로깅하지 않아 운영 중 디버깅 불가. **오탐 아님, P1 유지.**

## 감리 2회 — 등급 적정성 검토

**VAL-1, VAL-2 등급 검토**:
PASS_WITH_FIX는 TF-27~34에서 구현된 핵심 기능으로 Stage4 경로에는 구현됨. `validation_orchestrator.py`는 Stage 2/3의 BLUEPRINT 모드 검증에 사용되므로, fix_scope 미전달 시 Stage2/3 PASS_WITH_FIX 흐름에서 피드백 손실이 발생. **P1 적정.**

**공통-A 등급 검토**:
threshold_helper는 모든 검증 임계값의 SSOT 접근 함수. 초기화 실패 시 silent하면 전체 임계값이 기본값으로 동작해 검증 강도가 예기치 않게 변경될 수 있음. **P1 적정.**

**VAL-10 Guard 체인 등급 검토**:
Guard 체인 조립은 stage4_context_builder(8번 터미널 담당)에서 수행될 가능성이 높으므로 9번 터미널 단독 GAP으로 보기 어려움. 조립 코드 부재 시에도 GenreGuard 개별 호출로 기능. **P2 적정, 8번 터미널과 교차 확인 권장.**
