### [TF-20-01] P1 — meta_wall severity="low" 탈출 갭

**핵심 문제**: `_check_system_term_exposure()` 탐지 결과가 **단독 1건**이면 수정 없이 통과.

**원인 추적**:

```python
# _self_critique() L272-278
severity = "low"
if len(issues) >= 5:
    severity = "high"
elif len(issues) >= 3:
    severity = "medium"
# 1~2건: severity="low", has_issues=True
```

```python
# apply_self_critique() L185-186
if critique_result["severity"] == "low":
    break  # ← 수정 루프 탈출
```

meta_wall 이슈 **1건 단독** 발생 시:
- `len(issues) = 1` → `severity = "low"`
- `apply_self_critique()` → `break` → **수정 없이 원고 그대로 Director에 제출**

즉, 실전 모순 사례인 "Block 2" 대사 노출이 **단독 1건**이면 탐지는 되지만 자동 수정이 이루어지지 않음.

**TF-G 게이트 우회 여부 확인**:
TF-G 게이트(`apply_self_critique()` L140-163)는 ending_hook + 분량 부족만 검사. meta_wall은 TF-G 게이트 대상이 아님 → TF-G 경로로도 수정 안 됨.

**패치 방향 (0번 터미널 수행)**:
`_check_system_term_exposure()` 반환값에 `meta_wall` 이슈가 있을 때, `_self_critique()`에서 severity를 "low"보다 높게 강제:

```python
# 옵션 A: meta_wall 감지 시 최소 severity="medium" 보장
if any(i.get("type") == "meta_wall" for i in issues if isinstance(i, dict)):
    if severity == "low":
        severity = "medium"
```

또는 TF-G 게이트에 meta_wall 조건 추가:

```python
# TF-G 게이트에 meta_wall 추가
_mw_issues = self._check_system_term_exposure(current_manuscript, genre_name)
if _mw_issues:
    _gate_issues.extend([i["description"] for i in _mw_issues if isinstance(i, dict)])
```

옵션 B(TF-G 추가)가 더 직접적이고 안전함. severity 조작 없이 게이트에서 severity="high"로 수정 강제.
