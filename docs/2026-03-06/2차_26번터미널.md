### TC-3: fact_ledger.py key_stat_change 파싱 안전성

**TF-26-06** | P1 | `modules/core/fact_ledger.py:292-294` | BUG | **비무협 key_stat_change 문자열이 fact_ledger numbers에 미등록됨**

```python
# L292
energy = shadow.get("key_stat_change") or shadow.get("internal_energy_loss")

    self.update_number("내공_소모량", energy, "단위", ep_num, ...)
```

비무협에서 `key_stat_change = "자산 5% 증가"` (문자열) 반환 시:
- `energy = "자산 5% 증가"` → `isinstance(energy, int | float)` → **False**
- `update_number` 미실행 → fact_ledger `numbers` 미등록

무협에서 `key_stat_change = None`, `internal_energy_loss = 5` (정수) 반환 시:
- `energy = 5` → `isinstance(energy, int | float)` → **True**
- `update_number("내공_소모량", 5, ...)` 실행 ✅

**결론**: 비무협 key_stat_change는 fact_ledger에서 **silently 무시**됨. TF-45 의도("key_stat_change 장르 중립화")와 다르게 비무협 수치 추적이 실질적으로 비활성화됨.

패치 방향 (0번 터미널 수행용):
```python
# 현재
energy = shadow.get("key_stat_change") or shadow.get("internal_energy_loss")
if energy is not None and isinstance(energy, int | float):
    self.update_number("내공_소모량", energy, "단위", ep_num, ...)

# 개선안
_key_stat = shadow.get("key_stat_change")
_energy_loss = shadow.get("internal_energy_loss")
if isinstance(_energy_loss, int | float):
    self.update_number("내공_소모량", _energy_loss, "단위", ep_num, note="status_shadow 자동 추출")
elif isinstance(_key_stat, int | float):
    self.update_number("내공_소모량", _key_stat, "단위", ep_num, note="status_shadow 자동 추출")
elif isinstance(_key_stat, str) and _key_stat:
    # 비무협: 문자열 key_stat_change → 별도 팩트 키로 기록
    self.update_number("key_stat_변동", _key_stat, "텍스트", ep_num, note="비무협 수치 변동")
```

단, `update_number`의 value 파라미터가 문자열을 받도록 허용하는지 확인 필요 (현재 타입 제약 없음, 문자열도 저장됨).

21번 터미널 LR-4 연계 항목 — 교차 확인:
