### TF-21-01 | P2 | numeric_consistency_checker.py:523 | GAP | _LEVERAGE_PCT_RE 음수/한국어 미처리

**현상:**
`_LEVERAGE_PCT_RE` 패턴이 `(\d[\d.]*)` 양수 전용. 아래 두 케이스 미감지:
- 음수 수익률: `-30%` (손실 표현)
- 비달러 표현: "1억2000만원→2억 × 3배 → 수익률 50%" (원화 레버리지)

패턴은 "달러" 단위 표현에만 동작. 실전 투자물 원고 중 원화 기반 레버리지는 미감지.

**패치 방향:** 현재 실전 사례("X달러→Y달러" 패턴)를 직접 겨냥한 설계이므로 P2 유지.
원화 패턴 확장은 False positive 위험 증가 가능성 있어 별도 검토 필요.

**감리 1회:** 의도적 설계 여부 — CLAUDE.md에 "X달러→Y달러 × N배 → Z% 패턴 감지"로
명시. 달러 한정 설계가 의도적. ✅ 오탐 제거. **등급 하향: P2 → 정보 기록 (NO-OP)**

### TF-21-02 | P1 | numeric_consistency_checker.py:523-526 | GAP | _LEVERAGE_PCT_RE False positive 위험

**현상:**
```python
_LEVERAGE_PCT_RE = re.compile(
    r"(\d[\d.]*)\s*달러[^.。\n]{0,60}?(\d[\d.]*)\s*달러[^.。\n]{0,80}?"
    r"(\d[\d.]*)\s*배[^.。\n]{0,60}?"
    r"(?:수익률|수익)[^.。\n]{0,30}?(\d[\d.]*)\s*%",
    re.DOTALL,
)
```

`re.DOTALL` 플래그를 사용하지만 `[^.。\n]`으로 개행을 제외하고 있어
실제로는 단일 문장 내에서만 매칭됨. 그러나 `{0,60}?`, `{0,80}?` 허용 범위가 넓어
"65달러짜리 구두를 샀고 … 85달러짜리 지갑도 … 3배 좋은 … 수익 50%" 같은
비관련 문장에서 오탐 가능성 존재.

**위험도:** MINOR — 한국어 투자물 원고에서 "달러" 단위와 "배" + "수익률" 3요소가
우연히 인접하는 경우가 드물어 실전 오탐 확률 낮음. 그러나 구조적으로 잠재함.

**패치 방향 (P1 권장):**
`re.DOTALL` 제거(이미 `[^.。\n]`이 개행 차단) + 중간 허용 범위 축소 검토.
또는 4개 그룹이 문장 부호로 구분되는 경우 별도 `re.DOTALL` 없이 단일 줄 매칭.

**현상:**
```python
loss_str = shadow.get("key_stat_change") or shadow.get("internal_energy_loss", "0%")
try:
    match = re.search(r"(\d+)", str(loss_str))
    if match:

        final_energy = Stage2Limits.INTERNAL_ENERGY_FALLBACK
```

비무협 장르(투자물)에서 `key_stat_change = "자산+5%"`:

2. `loss_str = "자산+5%"`
3. `re.search(r"(\d+)", "자산+5%")` → 매칭: `"5"`

**영향 범위:**

- LLM에게 전달되는 이전 Arc 요약에 "최종 내공: 95%"가 포함되어 비무협 장르 오염 가능성

### TF-21-05 | P1 | fact_ledger.py:292-294 | GAP | 비무협 key_stat_change 문자열 → FactLedger 수치 미추적

**현상:**
```python
energy = shadow.get("key_stat_change") or shadow.get("internal_energy_loss")
if energy is not None and isinstance(energy, int | float):
    self.update_number("내공_소모량", energy, "단위", ep_num, note="status_shadow 자동 추출")
```

비무협 장르 `key_stat_change = "자산 5% 증가"` (문자열) 경우:
- `energy = "자산 5% 증가"` (truthy, not None)
- `isinstance("자산 5% 증가", int | float)` → **False** → `update_number` 미실행

결과: 비무협 장르의 `key_stat_change` 값이 FactLedger에 전혀 추적되지 않음.

**위험도 평가:**
- 무협 `internal_energy_loss`(숫자)는 여전히 fallback 경로로 추적됨
- 비무협 수치 추적은 `financial_events` 필드로 별도 처리 (`_extract_numerical_facts` L300-311)
- `key_stat_change` 문자열 자체를 숫자로 파싱해 FactLedger에 저장하는 것은 의미 없음
- 단, 비무협 `key_stat_change`의 의미있는 수치(예: "자산 5% 증가"에서 5%)를 별도 파싱해
  `update_number("key_stat_change_pct", 5, "%", ep_num)` 형태로 저장하면 NC-1 교차검증에 활용 가능

**감리 2회:** 대원칙 1 준수 — Python은 수집만, 판단 없음. `update_number`도 수집 범주.
현재 로직이 비무협 key_stat_change를 건너뛰는 것은 의도된 설계(숫자 타입만 추적)에 가까우나
설계 의도 주석이 없어 명확하지 않음.

**패치 방향 (P1):**
`key_stat_change`가 문자열일 때 숫자 파싱 시도 후 저장:
```python
energy = shadow.get("key_stat_change") or shadow.get("internal_energy_loss")
if energy is not None:
    if isinstance(energy, int | float):
        self.update_number("내공_소모량", energy, "단위", ep_num, note="status_shadow 자동 추출")
    elif isinstance(energy, str):
        # 문자열에서 숫자 추출 시도 (예: "자산+5%" → 5)
        import re as _re
        _m = _re.search(r"[-+]?(\d[\d.]*)", energy)
        if _m:
            try:
                _val = float(_m.group(1))
                self.update_number("key_stat_change", _val, "%", ep_num, note=f"status_shadow 문자열 파싱: {energy}")
            except ValueError:
                pass
```
