### TF-CV-1 [P2] — `_check_location_continuity()` Arc 경계(arc_pos==1) 면제 미구현

**파일**: `modules/validation/continuity_validator.py:563`

**근거**

```python
def _check_location_continuity(
    self, current_ep: int, manuscript: str, prev_hud: dict, prev_manuscript: str | None
) -> dict:
```

`arc_pos` 파라미터 없음. `validate()` 호출 시 전달받는 `_cv_context`에서도 arc_pos를 참조하지 않음.

**영향**

Arc N 마지막 화에서 위치 A → Arc N+1 첫 화에서 위치 B 이동은 서사상 정상. 그러나:

1. `DISTANT_LOCATION_PAIRS`(서울↔뉴욕 등)에 해당하면 arc_pos==1이어도 BLOCKING violation 생성
2. `location_jump` WARNING도 arc 경계 구분 없이 발생 가능
3. 생성된 violation은 `validation_results[ci]["warnings"]`에 누적 → Director에게 노이즈 전달

실전 투자물(서울→뉴욕 Arc 경계 이동)에서 false positive 발생 가능성 실재.

단 advisory-only 체인이므로 직접 REJECT 없음 — 합격률 직접 영향 없음.

**완화 요인**

`has_time_skip` 체크(이튿날/다음날/며칠 후 등)가 Arc 경계 상당수를 자연 처리. false positive 빈도는 낮으나 구조적 결함으로 실재.

**수정 방향 (가장 위험도 낮은 순)**

옵션 C (권장): `_build_cv_context()`에 `arc_pos` 추가 → `continuity_validator.validate()` 내에서 arc_pos==1 시 DISTANT_LOCATION_PAIRS BLOCKING → WARNING 다운그레이드

```python
# stage4_interview_round._build_cv_context() 내
ctx["arc_pos"] = arc_pos

# continuity_validator._check_location_continuity() 내
arc_pos = validation_context.get("arc_pos", 0)
if arc_pos == 1 and violations:
    # BLOCKING → WARNING 다운그레이드
    for v in violations:
        v["severity"] = "WARNING"
    warnings.extend(violations)
    violations = []
```

옵션 A: `_check_location_continuity()` 시그니처에 `arc_pos: int = 0` 추가 (인터페이스 변경 필요)

**우선순위**: P2 (advisory 노이즈 감소, 합격률 직접 영향 없음)

**CLAUDE.md 기재**: "four_phase_arc_generator._generate_prev_context() → 다음 Arc arc_start_state.location 강제 주입 코드는 미구현(P1 잔여)"와 동일 맥락의 Arc 경계 연속성 미완성 항목 — P1 잔여 항목과 함께 검토 권장

### TF-PLV-1 [P2] — `PreLLMValidator` protagonist_name 미전달

**파일**: `modules/validation/validation_orchestrator.py:205`

**근거**

```python
# validation_orchestrator.py L202-205
_pov = ""
if context and isinstance(context, dict):
    _pov = context.get("pov", "")
self.pre_llm = PreLLMValidator(genre=genre, pov=_pov) if PRE_LLM_AVAILABLE else None
```

`PreLLMValidator(genre, pov, protagonist_name="")` — `protagonist_name` 인자 미전달.

**영향**

V70 `_check_pov_consistency()` 내 3인칭 패턴이 `(?:그는|그녀는|그가|그를)` 범용 대명사만 사용. 주인공 이름 기반 확장(`|이름는|이름가`) 불가.

- 1인칭 POV 작품: 무영향 (1인칭 검사이므로 3인칭 대명사로 충분)
- 3인칭 POV 작품: 주인공이 이름으로 3인칭 서술될 때 1인칭 침범 탐지 정확도 소폭 하락

또한 Stage4 파이프라인(stage4_interview_round.py)에서 `PreLLMValidator`는 `validation_orchestrator` 경로를 거치지 않고 `ManuscriptValidator.validate_all_candidates()`를 직접 호출함 — Stage4에서 V70이 실제 실행되는지 별도 확인 필요.

**수정 방향**

```python
_protagonist_name = ""
if context and isinstance(context, dict):
    _protagonist_name = context.get("protagonist_name", "")
self.pre_llm = PreLLMValidator(
    genre=genre, pov=_pov, protagonist_name=_protagonist_name
) if PRE_LLM_AVAILABLE else None
```

**우선순위**: P2 (정확도 개선 수준, 핵심 기능 미영향)
