## Executive Verdict

개선안은 많아 보이지만, 실제로는 우선순위가 분명하다.

제일 중요한 것은 아래 세 가지다.

1. donor 명사를 generalized loop slots로 바꾸는 것
2. 그 generalized loop를 `Phase0 + work_guard`의 canonical law로 올리는 것
3. canary가 `문체`가 아니라 `loop completion`을 직접 보게 만드는 것

즉 가장 큰 개선은 `더 세게 베끼기`가 아니라 `더 일반화하고 더 측정 가능하게 만들기`다.

## Option A. Loop Abstraction Packet

### 목적

donor의 표면 명사를 걷어내고, 현 체제에서 반복 가능한 `대리만족 loop slot dictionary`를 만든다.

### 핵심 예시

- `PB tone shift` -> `gatekeeper attitude shift`
- `named seat` -> `private receipt seat`
- `priority response list` -> `next-gate access unlock`
- `exception account` -> `privileged execution lane`
- `public proof` -> `reader-visible reevaluation trigger`

### 기대 효과

- donor overfit 감소
- 다른 작품/블럭으로 확장성 증가
- 동일 loop의 vocabulary rotation 가능

### 리스크

- 너무 추상화하면 현 작품의 촉감이 사라질 수 있다

## Option B. Canonical Loop Law Promotion

### 목적

generalized loop doctrine을 `Phase0 + work_guard`의 1급 계약으로 승격한다.

### 구현 방향

- `Phase0`에는 generalized step chain, success condition, failure condition을 둔다.
- `work_guard`에는 timing threshold, forbidden flattening, observer shift requirement, reward conversion rule을 둔다.

### 기대 효과

- donor packet이 없어도 작품 SSOT만 읽으면 loop truth가 살아남는다.
- downstream drift 방지력이 좋아진다.

### 리스크

- 너무 이른 강경 rule화는 material-side 유연성을 줄일 수 있다

## Option C. Reward Portfolio Rotation Matrix

### 목적

60블록 체제에서 같은 보상 표면 반복으로 인한 fatigue를 줄인다.

### 보상 class 후보

- 금전 보상
- 접근권 보상
- 우선권 보상
- 내부 인정 보상
- 거래권 보상
- 보호권 보상
- 규칙 변경 보상
- signboard 보상

### 기대 효과

- `named seat` 같은 donor-flavored receipt의 과사용 방지
- 장기 루프의 신선도 유지

### 리스크

- rotation만 강조하다가 누적 compounding 감각이 약해질 수 있다

## Option D. Episode Loop Contract

### 목적

각 화의 minimum satisfaction contract를 명시한다.

### 후보 체크리스트

- pressure visible
- execution visible
- proof visible
- receipt visible
- observer shift visible
- next gate visible

### 운영 원칙

- 매 화 6개 전부가 필수는 아니다
- 하지만 4개 미만이면 satisfaction drop 위험으로 본다
- `proof 없이 hook`, `receipt 없이 next gate`, `observer shift 없는 reward`는 경고로 본다

### 기대 효과

- `한 화가 재미있었나`를 더 구체적으로 판단할 수 있다

## Option E. Loop-Oriented Canary Scorecard

### 목적

현재 canary의 `PASS/FAILED + score`를 보완한다.

### scorecard 후보 지표

- loop_deadline_hit
- structural_receipt_conversion
- receipt_transport_survival
- carryover_persistence
- legal_bridge_efficiency
- anti_contamination_pass
- anti_fatigue_risk

### 기대 효과

- style pass와 loop pass를 분리할 수 있다
- Probe A의 개선 원인을 더 냉정하게 볼 수 있다

### 리스크

- 지표가 많아지면 해석이 복잡해질 수 있다

## Option F. S2/S3 Receipt Preservation Hardening

### 목적

receipt-heavy truth가 `episode_details / work_focus / must_focus`에서 flattening되지 않게 한다.

### 방향

- `episode_details` specificity floor 강화
- `work_focus` fallback genericity 감시
- `must_focus` 추출 시 receipt slot 우선도 상승

### 기대 효과

- material-side에서 공들인 loop truth가 downstream에서도 살아남는다

### 리스크

- hardening을 너무 세게 걸면 summary 유연성이 죽을 수 있다

## Option G. Process Upgrade for Serial Fatigue

### 목적

좋은 doctrine이 filler pressure에 망가지지 않게 한다.

### 방향

- release 전에 micro-tranche 단위로 buffer를 가진다
- `arc` 단위가 아니라 `bounded loop tranche` 단위로 감리한다
- 반복 명사와 반복 reward class를 추적한다

### 기대 효과

- serial production pressure로 인한 늘어짐 완화

## Recommended Priority Order

현재 기준 우선순위는 아래가 맞다.

1. Option A `Loop Abstraction Packet`
2. Option B `Canonical Loop Law Promotion`
3. Option D `Episode Loop Contract`
4. Option E `Loop-Oriented Canary Scorecard`
5. Option C `Reward Portfolio Rotation Matrix`
6. Option F `S2/S3 Receipt Preservation Hardening`
7. Option G `Process Upgrade`

이 순서가 좋은 이유는 아래와 같다.

- 먼저 언어를 일반화해야 한다
- 그다음 canonical law를 세워야 한다
- 그다음 무엇을 측정할지 정해야 한다
- 그 뒤에야 장기 fatigue와 transport hardening을 다루는 것이 낭비가 적다

## Adversarial Audit Targets

이 개선안들은 다음 감리 3회에서 아래 순서로 깨져 봐야 한다.

1. `Anti-Overfit`
- generalized slot이 donor noun보다 우선하는가

2. `Anti-Flattening`
- downstream seam에서 receipt truth가 살아남는가

3. `Anti-Fatigue`
- 60블록 체제에서도 같은 loop가 닳지 않게 설계됐는가
