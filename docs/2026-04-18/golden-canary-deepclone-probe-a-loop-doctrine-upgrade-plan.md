## Executive Reframe

이번 프로젝트의 기준 질문은 더 이상 아래가 아니다.

- `도너 완결까지 대응해야 하는가`
- `현 도너를 끝까지 깊게 베껴야 하는가`

이번 프로젝트의 기준 질문은 아래로 바꾼다.

- `현 도너가 실제로 잘하는 대리만족 loop grammar는 무엇인가`
- `그 loop grammar를 donor 고유 명사 없이 현 체제에 더 잘 심는 방법은 무엇인가`
- `그 변경이 runtime과 canary에서 실제로 회수되는가`

따라서 본 계획은 `deepclone completion project`가 아니라 `loop doctrine upgrade project`다.

## Working Thesis

현재까지의 bounded evidence를 기준으로, `Probe A`의 효용은 donor 고유 설정보다 아래 체인에서 나온다고 본다.

- pressure
- execution
- public proof
- private receipt
- observer shift
- next gate

이 체인은 웹소의 `대리만족 loop`와 더 가깝고, 헐리우드식 막 구조나 메시지 설계와는 구분된다.

따라서 고도화의 핵심은 `donor plot coverage 확대`가 아니라 `loop contract 정교화`다.

## Mission Freeze

이번 업그레이드 프로젝트의 미션은 아래 4개다.

1. 현 donor에서 살아 있는 `대리만족 loop doctrine`을 추출한다.
2. donor 명사와 donor 표면을 걷어내고, 현 체제용 일반화 슬롯으로 바꾼다.
3. 그 일반화 슬롯을 material-side SSOT와 canary 평가 체계에 동시에 심는다.
4. 적대적 감리 3회를 통과한 뒤에만 bounded execution으로 들어간다.

## Workstream 4. Improvement Design

이 단계에서는 실제 코드/산출물 수정을 시작하지 않고, 아래 개선안을 문서로 설계한다.

### Improvement A. Loop Abstraction Packet

핵심:
- donor 명사를 지우고 `loop slot dictionary`를 만든다.

예시:
- `PB tone shift` -> `gatekeeper attitude shift`
- `named seat` -> `private receipt seat`
- `priority response list` -> `next-gate access unlock`
- `exception account` -> `privileged execution lane`

### Improvement B. Reward Portfolio Rotation

핵심:
- 모든 화가 같은 보상 표면을 쓰지 않게 한다.

목표:
- `돈을 벌었다` 반복 금지
- `접근권`, `통과권`, `우선권`, `내부 인정`, `거래권`, `보호권`, `가문 규칙 변경` 같은 보상 class를 순환시킨다.

### Improvement C. Episode Loop Contract

핵심:
- 한 화 단위 minimum satisfaction contract를 만든다.

후보 체크포인트:
- pressure visible
- execution visible
- proof visible
- receipt visible
- observer shift visible
- next gate visible

### Improvement D. Loop-Oriented Canary Scorecard

핵심:
- `문체/점수`가 아니라 `loop completion`을 본다.

후보 지표:
- proof present
- receipt present
- reward converted to structural asset
- observer shift present
- next gate opened
- donor contamination absent

### Improvement E. Loop Transport Hardening

핵심:
- S2/S3 seam에서 `receipt-heavy truth`가 generic summary로 눌리지 않게 한다.

후보 방향:
- `episode_details` specificity floor 재정의
- `work_focus` fallback genericity 감시
- `must_focus` extraction에서 receipt slot 우선도 상승

## Workstream 5. Adversarial Audit x3

실행 전에는 아래 적대적 감리 3회를 모두 돈다.

### Audit 1. Anti-Overfit Audit

질문:
- donor 명사, donor 기관, donor 장면 질감이 과도하게 살아남지 않았는가
- 현 작품 고유 문법이 donor 표면에 눌리지 않았는가

통과 기준:
- generalized slots가 donor nouns보다 우선한다
- donor contamination red flag가 남지 않는다

### Audit 2. Anti-Flattening Audit

질문:
- material-side loop truth가 S2/S3 seam에서 generic packet으로 평평해지지 않는가

통과 기준:
- `episode_details`, `work_focus`, `must_focus`, `stop_line`에 receipt truth가 남는다
- `style pass but loop drop` 사례가 줄어든다

### Audit 3. Anti-Fatigue Audit

질문:
- 같은 보상과 같은 명사를 반복해도 되는 구조로 설계되지 않았는가
- 60블록 체제에서 reward rotation과 scale management가 가능한가

통과 기준:
- reward portfolio rotation이 설계상 존재한다
- `권한 포화`, `보상 둔화`, `반복 피로`에 대한 방지책이 문서에 있다
