# 5-Block 정밀 생산 정책 + 밀도 보정 통합 설계서 v3

> 작성일: 2026-03-25
> 상태: **설계 확정안 (v1 → 적대적 감리 → v2 생존자 바이어스 수정 → v3 정책 전환)**
> 핵심 결정: **블록 생산 단위를 5블록으로 제한. 전 장르 공통. 자동화 스크립트 사용 금지.**
> 적용 범위: blockguide (현대/재벌/금융) + wuxguide (무협/선협/세가) 전 패밀리

## 0. 배경: 왜 5블록인가

### 0.1 실측 기반 교차 검증 결과

11건 전수 분석 (raw draft + densification 완료본 구분):

| 생산 방식 | 작품 수 | ARC 밀도 패턴 | 결과 |
|-----------|---------|--------------|------|
| 전 ARC 균일 스켈레톤 → 전면 densify | 다수 (02_시리즈) | 균일 300~340자 | 2중 작업 비용 |
| 초반 정성 → 후반 급조 | 1건 (천의무쌍) | 1030→226자 (78% 손실) | 후반 품질 붕괴 |
| densification 완료본 | 다수 | 균일 900~1000자 | 안정 (당연) |

**어느 방식이든 문제**: 한 번에 70블록을 만들면 균일 스켈레톤이거나 후반 붕괴.
결국 densification으로 2중 작업. 처음부터 고밀도로 만드는 게 총비용이 낮다.

### 0.2 5블록 근거

- ARC 1개 = 10블록. 5블록 = **반 ARC**
- 5블록이면 LLM이 컨텍스트 내에서 전 블록을 참조 가능 (5블록 × ~2000자 = ~10000자 = ~5000토큰)
- 5블록 후 필수 정지 → 감리 → 다음 5블록. **밀도 감소가 시작되기 전에 잡음**
- 3블록은 너무 잦은 정지. 10블록은 이미 감소 시작 후. 5블록이 균형점

## 1. 최상위 정책: 전 장르 공통 5-Block 생산 규칙

### 1.1 절대 규칙 (Override)

이 규칙은 기존 하네스의 모든 자동 진행 정책을 **override**한다.

```
규칙 1: 한 번에 생산하는 블록은 최대 5개다.
규칙 2: 사용자가 "자동 진행"을 지시해도, 5블록 후 반드시 정지한다.
규칙 3: 정지 시 5-Block 감리 체크리스트(§3)를 완료해야 다음 5블록을 시작할 수 있다.
규칙 4: 블록 생산에 자동화 스크립트를 사용하지 않는다.
         (감리/검증 스크립트는 허용. 생산 프롬프트 자동 생성도 허용.
          금지 대상은 "LLM 호출을 루프로 돌려 블록을 찍어내는 자동화".)
규칙 5: 비효율을 수용한다. 70블록 완성에 14회 사이클이 필요하다.
         이것이 densification 2중 작업보다 총비용이 낮다.
```

### 1.2 기존 하네스 충돌 지점과 해소

| 기존 규칙 | 위치 | 충돌 | 해소 |
|-----------|------|------|------|
| "Go 조건 충족 시 멈추지 않고 다음 단계로" | wuxguide SSOT §11, blockguide SSOT §9 | **단계 간** 자동 진행은 유지. **블록 생산 중** 자동 진행만 5블록 제한 | 단계 전환(Planning→Production→BI)은 자동. 블록 생산은 5블록 정지 |
| "다음 단계로 갈까요? 질문 금지" | production-harness 자동 진행 규칙 | 블록 생산 5개 후 정지는 "단계 전환"이 아님 | 5블록 정지는 "질문"이 아니라 "감리 게이트". 형식이 다름 |
| `--batch-size 3` (TR 배치) | SSOT CLI 예시 | 3블록 배치는 스크립트 감리 단위. 5블록은 생산 정지 단위 | 5블록 = 배치 2회(3+2) 또는 배치 1회(5). 감리는 5블록 단위 |
| densification 배치 3블록 | densification harness §7 | densification도 5블록 단위로 변경 | §5에서 별도 명시 |

### 1.3 "자동 진행"의 재정의

```
[기존 해석]
"자동 진행해" = 70블록 끝까지 멈추지 마

[v3 해석]
"자동 진행해" = 5블록을 자동으로 만들어. 5블록 후 감리 결과를 보여줘.
                감리 PASS면 "다음 5블록 진행합니다" 하고 이어서 5블록 더.
                감리 FAIL이면 정지하고 FAIL 내용 보고.
```

자동 진행 시에도 5블록마다 감리 결과 출력은 필수. 생략 불가.

## 2. 5-Block 생산 사이클

### 2.1 사이클 구조

```
[사이클 N 시작]
  │
  ├── 사전 준비 (§2.2)
  │     골든 앵커 확인 + 직전 사이클 잔향 확인
  │
  ├── Block 5(N-1)+1 생산
  │     사전 선언(8항) → JSON 생성 → 완성도 게이트(CG-01~CG-14)
  ├── Block 5(N-1)+2 생산
  ├── Block 5(N-1)+3 생산
  ├── Block 5(N-1)+4 생산
  ├── Block 5(N-1)+5 생산
  │
  ├── 5-Block 감리 체크리스트 (§3)
  │     정량 6항 + 정성 6항 + 적대적 3항 = 15항
  │
  ├── PASS → 사이클 N+1 시작
  └── FAIL → 해당 블록 재작성 후 재감리
```

### 2.2 사전 준비 (매 사이클 시작 시)

| # | 항목 | 내용 |
|---|------|------|
| P1 | **골든 앵커 확인** | 사이클 1(B1~B5) 완료 후 고정. 이후 사이클에서 B1~B3의 avg_bundle_chars, avg_stakes_chars를 기준선으로 참조 |
| P2 | **직전 사이클 잔향** | 직전 블록의 realm_after, internal_energy_after, injury_status, 열린 복선 목록 확인 |
| P3 | **ARC 위치 확인** | 현재 사이클이 어느 ARC에 속하는지. ARC 경계를 넘는 사이클이면 경계 블록에서 phase0 arc_progression 재확인 |
| P4 | **패턴 피드백 재로드** | 직전 사이클 감리에서 나온 경고/피드백을 이번 사이클 프롬프트에 반영 |

### 2.3 블록 생산 규칙 (기존 하네스 계승)

블록 1개 생산 프로세스는 기존 하네스 그대로:
- 사전 선언 8항 (wuxia-production-harness §1.5)
- JSON 생성
- 완성도 게이트 CG-01~CG-13
- **CG-14 추가**: `bundle_chars ≥ 500` (위치 무관 단일 하한)

CG-14 FAIL 시 해당 블록만 즉시 재생성. 골든 앵커를 밀도 참조로 주입:

```json
{
  "_density_reference": {
    "_role": "밀도 참조 전용. 서사 내용을 복사하지 말 것. 길이와 구체성 수준만 참고.",
    "reference_bundle_chars": 975,
    "reference_event_villain": "[B1의 event_villain 전문]",
    "reference_solution": "[B1의 solution 전문]"
  }
}
```

## 3. 5-Block 감리 체크리스트 (매 사이클 후 필수)

### 3.1 정량 검증 (6항 — 스크립트 자동 판정 허용)

| # | 항목 | 기준 | FAIL 시 |
|---|------|------|---------|
| Q1 | 5블록 전체 `bundle_chars` | 전 블록 ≥ 500자 | 미달 블록 재작성 |
| Q2 | `stakes` 길이 | 전 블록 ≥ 35자 | 미달 블록 stakes 보강 |
| Q3 | `event_villain` 길이 | 전 블록 ≥ 80자 | 미달 블록 재작성 |
| Q4 | `solution` 길이 | 전 블록 ≥ 80자 | 미달 블록 재작성 |
| Q5 | 블록 간 유사도 | 5블록 내 Jaccard 유사도 전 쌍 < 0.30 | 유사 블록 재작성 |
| Q6 | 연속성 | `realm_before(N) == realm_after(N-1)`, `internal_energy_before(N) == internal_energy_after(N-1)` | 불일치 블록 수정 |

### 3.2 정성 검증 (6항 — LLM 수동 판정)

| # | 항목 | 판정 방법 | FAIL 시 |
|---|------|-----------|---------|
| S1 | **밀도 체감** | 5블록 중 마지막 2블록이 처음 2블록보다 명백히 짧거나 성긴가? | 마지막 2블록 보강 |
| S2 | **고유 사건** | 5블록 각각에 다른 블록과 구별되는 고유 사건이 있는가? | 동질 블록 재구상 |
| S3 | **적대자 차별** | 5블록 내 적대자 또는 갈등 대상이 최소 2종인가? | 적대자 교체/추가 |
| S4 | **감정 곡선** | 5블록의 emotional_beat.type이 최소 3종인가? | 감정 다변화 |
| S5 | **복선 진행** | 5블록 내 foreshadow 또는 callback이 최소 2건인가? | 복선 삽입/회수 |
| S6 | **골든 대비** | 5블록 avg_bundle_chars가 골든 앵커(B1~B3 avg)의 60% 이상인가? | 전체 보강 |

### 3.3 적대적 검증 (3항 — 자기 생산물을 의심)

| # | 항목 | 질문 | FAIL 시 |
|---|------|------|---------|
| A1 | **채우기 의심** | 글자 수를 채우기 위해 불필요한 묘사를 넣지 않았는가? 삭제해도 서사가 유지되는 문장이 있는가? | 군더더기 삭제 후 핵심 서사 보강 |
| A2 | **구조 복사** | 5블록 중 "상황 설명 → 적대자 등장 → 전투/대결 → 승리 → 보상" 구조가 3개 이상 반복되는가? | 구조 다변화 |
| A3 | **전작 오염** | 다른 작품의 인물명/지명/설정이 혼입되지 않았는가? | 즉시 수정 |

### 3.4 감리 출력 형식 (필수)

```markdown
### 5-Block 감리 — 사이클 N (Block X~Y)

#### 정량 검증
| # | 항목 | 기준 | 실측 | 판정 |
|---|------|------|------|------|
| Q1 | bundle_chars | ≥500 전 블록 | [최소값/최대값] | ✅/❌ |
| Q2 | stakes | ≥35 전 블록 | [최소값] | ✅/❌ |
| Q3 | event_villain | ≥80 전 블록 | [최소값] | ✅/❌ |
| Q4 | solution | ≥80 전 블록 | [최소값] | ✅/❌ |
| Q5 | 유사도 | <0.30 전 쌍 | [최대값] | ✅/❌ |
| Q6 | 연속성 | realm/energy 일치 | [불일치 수] | ✅/❌ |

#### 정성 검증
| # | 항목 | 판정 | 근거 |
|---|------|------|------|
| S1 | 밀도 체감 | ✅/❌ | [1문장] |
| S2 | 고유 사건 | ✅/❌ | [블록별 1문장] |
| S3 | 적대자 차별 | ✅/❌ | [적대자 목록] |
| S4 | 감정 곡선 | ✅/❌ | [beat type 목록] |
| S5 | 복선 진행 | ✅/❌ | [foreshadow/callback 수] |
| S6 | 골든 대비 | ✅/❌ | [avg vs 골든 avg, 비율] |

#### 적대적 검증
| # | 항목 | 판정 | 근거 |
|---|------|------|------|
| A1 | 채우기 의심 | ✅/❌ | [의심 블록과 문장 지적] |
| A2 | 구조 복사 | ✅/❌ | [5블록 구조 요약] |
| A3 | 전작 오염 | ✅/❌ | [검출 여부] |

**결과: PASS / FAIL (FAIL 항목: ...)**
```

**"전량 PASS" 한 줄은 무효.** 반드시 실측값과 근거를 채워야 유효.

## 5. Densification에 대한 정책 변경

### 5.1 첫 생산(신규 작품)

5-Block 정밀 생산으로 **densification 자체를 불필요하게 만드는 것이 목표**.

- 매 사이클 감리에서 밀도 미달을 즉시 잡음
- 70블록 완료 시점에 critical_thin = 0이 기본
- densification은 **예외적 후처리**로 격하

### 5.2 기존 작품 사후 보정 (천의무쌍 등)

이미 생산된 작품의 densification도 5블록 단위:

```
[기존 densification]
배치 크기: 3블록

[v3 densification]
배치 크기: 5블록
Critical 블록(< 300자): 전면 재작성
Thin 블록(300~349자): 핵심 4필드 재작성
Weak 블록(350~499, 필드 미달): 미달 필드만 보강
```

- 5블록 배치 후 동일한 15항 감리 체크리스트 적용
- 잠금 필드 무결성 추가 체크 (densification harness §1.1)
- 보조 입력은 phase0에서 반자동 추출 + LLM 보충

### 5.3 진입 게이트

기존: "BI 5-Pass 전량 통과" 필수
수정: "BI PASS 1,2,4,5 통과. PASS 3 FAIL이 밀도 관련 항목에 한정된 경우 진입 허용"

밀도 관련 FAIL 목록 (진입 허용):
`critical_thin_blocks_zero`, `thin_blocks_ratio_ok`, `late_thin_blocks_zero`,
`short_stakes_blocks_total_ok`, `endgame_low_stakes_zero`, `production_density_gate`

구조 관련 FAIL (진입 불허 — TR 자체 수정 우선):
`npc_deceased_violation`, `realm_continuity_failure`, `faction_drift`, `foreshadow_callback_linked` 대규모 불일치
