# Gemini 2.5 Pro 가성비 적합도 보고서

> 글도비 시스템 기준 · 2026-03-26 작성

---

## TL;DR

**Gemini 2.5 Pro는 "플래그십 중 가성비 1위"는 맞다. 하지만 "최적"은 아니다.**

- 가격: 플래그십 중 최저 (input $1.25/1M, output $10/1M)
- 한국어 토크나이저: 영어 대비 2.5~4x 비효율 → 실질 비용 2.5~4배
- 한국어 창작 품질: Claude > GPT-4o ≥ Gemini 2.5 Pro (커뮤니티 합의)
- 시스템 적합도: 현재 글도비가 Gemini-native로 구축됨 → 전환 비용 존재
- **결론: 비용 최적화는 역할별 모델 분리(Pro/Flash/외부)가 핵심이지, 단일 모델 올인이 아님**

### 1-2. 한국어 실질 비용 (토크나이저 패널티 적용)

한국어는 모든 주요 LLM에서 영어 대비 **2.5~4x** 토큰을 소비한다.

| 모델 | 명목 input | 한국어 실질 input | 명목 output | 한국어 실질 output |
|------|-----------|------------------|------------|-------------------|
| **Gemini 2.5 Pro** | $1.25 | **$3.1~5.0** | $10.00 | **$25~40** |
| GPT-4.1 | $2.00 | $5.0~8.0 | $8.00 | $20~32 |
| Claude Sonnet 4.6 | $3.00 | $7.5~12.0 | $15.00 | $37.5~60 |
| **DeepSeek V3.2** | $0.28 | **$0.56~0.84** | $0.42 | **$0.84~1.26** |

**핵심 발견:**
- Gemini 2.5 Pro는 플래그십 중 input 최저가이나, **output이 비싸다** ($10 → 한국어 실질 $25~40)
- GPT-4.1은 output이 $8로 Gemini보다 20% 저렴 — 글도비처럼 output-heavy(원고 생성) 시스템에서는 GPT-4.1이 output 단가 우위
- DeepSeek V3.2는 가격이 **10~30x 저렴** + CJK 토크나이저 효율도 더 좋음

## 2. 토크나이저 분석

### 2-1. 한국어 토큰화 효율

| 토크나이저 | 한국어 chars/token | 영어 대비 배율 | 비고 |
|-----------|-------------------|--------------|------|
| Gemini (SentencePiece) | ~0.8~1.5 | 2.5~4x | CJK 서브워드 분해 |
| GPT (tiktoken/o200k) | ~1.0~1.5 | 2.5~4x | BPE 한국어 빈도 부족 |
| Claude (custom BPE) | ~1.0~1.5 | 2.5~4x | 유의미한 차이 없음 |
| **DeepSeek** | ~2.0~2.5 | **1.5~2x** | CJK 최적화 어휘 |

**결론:** Big 3 (Google/Anthropic/OpenAI) 사이에서 한국어 토크나이저 효율 차이는 미미하다. DeepSeek만 유의미하게 효율적.

### 2-2. 200K 임계값 함정

Gemini 2.5 Pro는 **200K 토큰 초과 시 input 가격이 2배**($1.25 → $2.50).

한국어 토큰 부풀림(2.5~4x)으로 인해:
- 영어로 80K 분량의 프롬프트 → 한국어로 200K~320K 토큰
- **의도치 않게 2배 구간 진입 가능**
- 글도비 Stage 4에서 Bible + 이전 에피소드 컨텍스트가 커지면 위험

## 3. 한국어 웹소설 품질 비교

### 3-1. 차원별 평가

| 차원 | Claude (Sonnet/Opus) | GPT-4o/4.1 | Gemini 2.5 Pro | DeepSeek V3 |
|-----|---------------------|------------|----------------|-------------|
| **한국어 유창성** | ★★★★★ | ★★★★☆ | ★★★★☆ | ★★★☆☆ |
| **장르 관습 준수** (회귀/무협/헌터) | ★★★★★ | ★★★★☆ | ★★★☆☆ | ★★★☆☆ |
| **장문 스타일 일관성** | ★★★★★ | ★★★★☆ | ★★★☆☆ | ★★★☆☆ |
| **존댓말/반말 관리** | ★★★★★ | ★★★★☆ | ★★★★☆ | ★★★☆☆ |
| **번역체 회피** | ★★★★★ | ★★★★☆ | ★★★☆☆ | ★★★☆☆ |
| **지시 따르기 (창작 제약)** | ★★★★★ | ★★★★☆ | ★★★★☆ | ★★★☆☆ |

### 3-2. 커뮤니티 합의 (한국 AI 커뮤니티 기준)

- **Claude**: "한국어 글쓰기는 클로드가 압도적" — 에이닷, 클리앙, 디시 AI갤 일관된 평가
- **GPT-4o**: 구조/플롯에 강함, 문체는 Claude 다음
- **Gemini**: 사실적/분석적 한국어는 강하나 **창작 문체가 "딱딱하다", "번역체 느낌"** — 가장 빈번한 불만
- **DeepSeek**: 가격 대비 괜찮으나 "프로 수준"에는 부족

### 3-3. Gemini의 알려진 한국어 창작 약점

1. **번역체(Translationese)**: 영어 구문을 한국어로 직역한 느낌의 문장 생성 빈도 높음
2. **문체 평탄화**: 장문 생성 시 캐릭터 보이스 구분이 흐려지고 "보고서체"로 수렴
3. **장르 특유 관습**: 무협의 초식 묘사, 회귀물의 내면 독백 패턴 등에서 Claude 대비 부족
4. **경어 불일치**: 대화 중심 씬에서 동일 관계의 존/반말이 간헐적으로 뒤섞임

## 4. 글도비 시스템 적합도

### 4-1. 현재 시스템 상태

| 항목 | 상태 |
|------|------|
| Primary 모델 | `gemini-3.1-pro-preview` (fallback: `gemini-2.5-pro`) |
| Lightweight 모델 | `gemini-2.5-flash` |
| 멀티프로바이더 라우터 | ✅ 존재 (`llm_router.py`) |
| Anthropic/OpenAI 어댑터 | ✅ 구현됨 (현재 `enabled: false`) |
| 프로바이더 전환 준비도 | **~50%** (BaseAgent에 Gemini-native 하드코딩 잔존) |
| 비용 추적 | ✅ MetricsCollector 가동 중 |
| API 키 로테이션 | ✅ 429 방어 구현 |

### 4-2. 역할별 모델 배치 현황

| 역할군 | 현재 모델 | 요구 수준 |
|--------|----------|----------|
| Analyst, Chief Writer, Director | gemini-3.1-pro | 높음 (추론+창작) |
| Arc Generator, Blueprint Ensemble | gemini-3.1-pro | 높음 (구조 설계) |
| Writer, Weaver, Critics | gemini-2.5-flash | 중간 (실행+검증) |
| Block Enricher, Preflight | gemini-2.5-flash | 낮음 (전처리) |

### 4-3. 전환 비용 평가

현재 Gemini-native 종속 지점:
- `BaseAgent` 내 `google.genai.types.ThinkingConfig` 직접 사용
- Usage 키 Gemini 전용 (`prompt_token_count`, `candidates_token_count`)
- Structured output이 Gemini의 `response_schema` + `response_mime_type` 의존
- Prompt caching이 Gemini API 네이티브

**전환 노력 추정:**
- Claude/OpenAI 단순 활성화: 2~3일 (어댑터 존재, 키 하드코딩 정리 필요)
- BaseAgent 프로바이더 무관 리팩터링: 5~7일
- 역할별 혼합 배치 안정화: 1~2주

## 5. 종합 판정

### 5-1. "2.5 Pro가 가장 가성비인가?"

**부분적으로 맞다, 전체적으로는 아니다.**

| 기준 | Gemini 2.5 Pro 판정 |
|------|-------------------|
| 플래그십 중 단가 최저? | ✅ **맞음** (input 기준) |
| Output 단가 최저? | ❌ GPT-4.1이 20% 저렴 |
| 한국어 토크나이저 최적? | ❌ Big 3 차이 없음, DeepSeek이 우위 |
| 한국어 웹소설 품질 최고? | ❌ Claude가 압도적 1위 |
| 비용/품질 균형 최적? | ⚠️ **상황 의존** — 역할에 따라 다름 |
| 글도비 시스템 적합도? | ✅ 현재 네이티브 통합 상태 |

### 5-2. 최적 전략 제안

**단일 모델 올인이 아닌, 역할별 최적 배치:**

| 역할 | 추천 모델 | 근거 |
|------|----------|------|
| **Chief Writer** (원고 생성) | Claude Sonnet 4.6 | 한국어 창작 품질 압도적 1위. output-heavy지만 품질이 매출 직결 |
| **Director** (품질 판정) | Gemini 2.5 Pro | 추론 강점, output 짧음(판정문), 비용 효율적 |
| **Analyst** (분석/설계) | Gemini 2.5 Pro | 분석 태스크에서 Gemini 강세 |
| **Arc/Blueprint 설계** | GPT-4.1 | 구조적 추론 + 1M 컨텍스트 + output $8 |
| **Validator/Critics** | Gemini 2.5 Flash | 현행 유지, 최저가 |
| **Enricher/Preflight** | DeepSeek V3.2 | 단순 작업, 10x 비용 절감 |

**예상 효과:**
- 100화 기준 현행 $15~30 → 혼합 배치 시 $12~20 (품질 상승 + 비용 유지/절감)
- Chief Writer만 Claude 전환해도 최종 원고 품질 유의미한 상승 기대

### 5-3. 즉시 실행 가능 최적화 (현 시스템 내)

1. **Flash 확대**: Stage 2~3의 더 많은 역할을 Flash로 내리기
2. **Prompt Caching 예산 설정**: Bible/스타일가이드 prefix를 cache — cache read $0.125/1M
3. **200K 임계값 모니터링**: MetricsCollector에 200K 초과 경고 추가
4. **Batch API 활용**: 실시간 불필요한 Stage 0~1을 batch 처리 (50% 할인)

## 6. 벤치마크 한계 고지

- 한국어 웹소설 생성 전용 표준 벤치마크는 **존재하지 않음**
- KMMLU, KoBEST 등은 NLU 중심으로 창작 품질과 상관도 낮음
- 커뮤니티 평가는 2025 중반 기준이며, Gemini 2.5 Pro 이후 개선 가능성 있음
- **최종 확인은 글도비 파이프라인 내 A/B 테스트가 유일한 ground truth**
