## 0A. 초저지능 LLM용 빠른 시작

이 문서는 **Phase 0 이전 기획 단계 전용**이다.
사용자가 작품명, `work_id`, 짧은 기획안, Bible 조각만 던져도 아래 순서를 먼저 수행한다.

1. `SSOT_blockguide-integrated-order.md`를 **UTF-8로 먼저 읽는다.**
2. 그다음 `전처리_ssot\docs\SSOT_stage0_preprocess_integrated_order.md`를 읽는다.
3. `treatments/preprocess/{work_id}/source_manifest.json`, `profile_lock.json`, `material_bundle_summary.json`, `phase0_ready_snapshot.json` 존재 여부를 확인한다.
4. `phase0_ready_snapshot.manual_audit_pass != true`면 이 문서를 계속 읽지 말고 `Stage 0 preprocess`로 돌아간다.
5. 그다음 이 문서를 **UTF-8로 읽는다.**
6. 장르가 `alt_history`이거나 역사 재료 DB 조회가 필요하면 `alt_history_db_harness.md`를 추가로 읽는다.
7. 이미 `phase0_design`, `tr_block_070_draft`, `0_bi_{work_id}.json` 중 무엇이 있는지 확인한다.
8. `phase0_design`이 이미 있으면, 이 문서에서 새 기획을 다시 만들지 말고 통합 오더에 따라 다음 단계로 넘긴다.
9. 아직 기획 단계라면 **한 번에 설계 단위 1개만** 만든다.
10. 각 단위가 끝날 때마다 아래 3줄만 남긴다.
   - 이번 턴에 확정된 사실
   - 아직 비어 있는 사실
   - 다음 턴 기본 행동
11. `Phase 0 JSON`이 완성되면 이 문서의 역할은 끝난다. 즉시 `treatment-production-harness-v2.md` 단계로 인계한다.

금지:

- 기억만으로 다음 단계를 추정해 문서를 건너뛰기
- Stage 0 전처리 산출물 없이 Planning으로 들어가기
- 기획안 없이 바로 70블록을 쓰기
- `Phase 0` 슬롯 문장을 고밀도 TR처럼 취급하기
- 사용자가 `다음 스텝`만 입력했는데도 이미 확정된 기획을 처음부터 다시 쓰기

## 0B. SSOT 장르 범위

이 문서의 기본 장르는 `investment` 단일 장르가 아니다.
런타임 장르 이름이 당분간 `investment`로 남아 있어도, 여기서 말하는 SSOT는 **현대판타지 all-genre general mode**다.

기획 단계에서는 먼저 공통 코어를 잡고, 그다음 장르 프로파일을 고른다.

| 프로파일 | 핵심 전장 | 이 문서에서의 읽는 법 |
| ---- | ---- | ---- |
| `business_growth_profile` | 운영권, 공급망, 정산권, 반복매출 | 사업/운영 병목을 장악하는 성장물 |
| `investment_market_profile` | 지분, 가격, 수익률, 금융 이벤트 | 시장 타이밍과 금융 구조가 전장 |
| `entertainment_media_profile` | IP, 팬덤, 편성, 유통, 계약 | 연예/방송/플랫폼/IP 성장물 |
| `medical_professional_profile` | 집도권, 케이스, 신뢰도, 병원 권한 | 의학/병원 전문직 성장물 |
| `office_power_profile` | KPI, 예산, 결재선, 인사권 | 신입사원물 포함 조직 권력전 |
| `tech_startup_profile` | 제품, 데이터, 특허, 사용자 기반 | 기술 기업/창업/플랫폼 성장물 |
| `urban_power_profile` | 힘의 계급, 길드 자산, 권리, 위상 | 헌터/길드/현대 능력물 |

경계:

- 순수 연애물, 순수 일상물, 순수 직장 드라마처럼 **측정 가능한 성장 축**이 없으면 본 파이프라인 범위가 아니다.
- 신입사원물도 예산, KPI, 결재선, 실적, 프로젝트 오너십처럼 **성장/권력축**이 있으면 받는다.

## 0C. 공통 용어표

아래 용어는 이 문서 전체에서 같은 뜻으로 쓴다.

| 용어 | SSOT 의미 |
| ---- | ---- |
| `capital` | 돈, 예산, 반복 현금흐름, 권한, 케이스, 팬덤, 라이선스, 길드 자산 등 주인공이 실질 통제하는 성장 자원 |
| `deal_type` | 투자, 수술, 편성, 감사, 레이드, 승인권 회수, 조직 재배치 등 판을 바꾸는 결정적 진행 액션 |
| `power` | 돈만이 아니라 승인권, 정보권, 정산권, 집도권, 편성권, 조직 통제력, 사회적 위상 |
| `control` | 회사/가문/조직이 주인공을 거치지 않고는 움직이기 어려운 상태 |
| `business_lines` | 키 이름은 유지하되 실제 의미는 작품의 active domain lines. 예: 사업부, 진료과, 아티스트 라인업, 제품군, 길드 분대 |
| `company_state` | 키 이름은 유지하되 실제 의미는 current operating arena / base state. 예: 회사 상태, 병원 권력 구도, 레이블 상태, 길드 등급 |
| `failure` | 손실, 지연, 실점, 역풍, 여론전, 결재선 패배까지 포함한 실질적 후퇴 |
| `payoff` | 돈 회수만이 아니라 권한 회수, 관계 회수, 복선 회수, 굴욕 회수 |

## 0D. 장르 프로파일 선택 규칙

기획 단계에서는 아래 순서로 프로파일을 잠근다.

1. **주 프로파일 1개**를 먼저 고른다.
2. 필요할 때만 **보조 프로파일 1개**를 추가한다.
3. 두 프로파일이 충돌하면 주 프로파일의 성장 자원 해석을 우선한다.

빠른 기본값:

- 투자물 -> `investment_market_profile`
- 엔터물 -> `entertainment_media_profile`
- 의학물 -> `medical_professional_profile`
- 신입사원물/조직 권력물 -> `office_power_profile`
- 재벌/사업 운영물 -> `business_growth_profile`
- 기술 창업물 -> `tech_startup_profile`
- 헌터/길드물 -> `urban_power_profile`

## 0E. Stage 0 handoff 계약

Planning은 이제 Stage 0 전처리 이후 단계다.

Planning 시작 전 필수 입력:

- `treatments/preprocess/{work_id}/source_manifest.json`
- `treatments/preprocess/{work_id}/profile_lock.json`
- `treatments/preprocess/{work_id}/material_bundle_summary.json`
- `treatments/preprocess/{work_id}/phase0_ready_snapshot.json`

Planning 진입 금지 조건:

- 위 4개 파일 중 하나라도 없음
- `phase0_ready_snapshot.manual_audit_pass != true`
- `source_manifest.manual_audit_note` 없음
- `profile_lock.primary_profile` 없음

좋은 handoff 예:

- `source_manifest`에 정본/참고본 구분이 있다
- `profile_lock`에 자원축/권력축/실패축이 잠겨 있다
- `material_bundle_summary`에 Phase 0에 바로 옮길 사건/NPC/위기 재료가 있다

나쁜 handoff 예:

- `source_manifest` 없이 기획자의 감으로만 Phase 0를 쓰려 함
- 프로파일이 비어 있거나 3개 이상 섞임
- material summary가 “업계 감” 같은 추상 일반론뿐임

## 0G. `opening_bundle_contract` 의무

이제 Planning에서 `Phase0-ready`로 승격시키려면 `material_bundle_summary.opening_bundle_contract`와 `phase0_design.opening_bundle_contract`를 같은 의미로 잠가야 한다.

목적:

- `1 block = 2~6화 분량`이라는 운영 계약을 사람 감각이 아니라 실행 가능한 필드로 넘긴다
- opening macro-battlefield 체류가 길어지더라도 독자가 `TR 2~6` 안에서 signboard / reevaluation / next ticket을 받게 만든다
- live TR harness가 Stage0 / Phase0를 prompt authority로 읽을 때 같은 기준을 재사용하게 만든다

필수 필드:

| 키 | 의미 |
| ---- | ---- |
| `bundle_window` | 기본값은 `TR 2~6` |
| `macro_battlefield` | opening 주전장 이름 |
| `macro_battlefield_map` | opening 주전장 내부의 하위 lanes / sub-arenas |
| `bundle_goal` | `TR 2~6`이 독자에게 반드시 벌어야 하는 대표 보상 |
| `first_signboard_block` | 첫 공적 간판 사건이 터지는 블록 |
| `representative_reevaluation_block` | 대표 재평가가 발생하는 블록 |
| `next_battlefield_ticket_block` | 다음 전장 입장권이 발생하는 블록 |
| `timing_reconciliation_note` | Arc 스케일과 `TR 2~6` 체감 속도를 어떻게 reconcile했는지 |

Planning hard rule:

- `bundle_window`는 `TR 2~6`으로 고정한다
- 세 timing block은 모두 `2~6` 안에 있어야 한다
- 같은 `macro_battlefield`가 `Block 2~8`을 장악한 채 첫 signboard / reevaluation / ticket을 `Block 9+`로 미루면 invalid다
- `block_slots` 또는 arc outline이 길어도 `opening_bundle_contract`가 더 상위의 reader-speed contract다
- `Phase0-ready` 승격안에서 이 계약이 비어 있으면 promotion 금지다

권장 운영:

- `macro_battlefield_map`은 장소 목록이 아니라 리듬 변화가 보이게 쓴다
- `bundle_goal`은 돈 그 자체보다 권한, 입장권, 대표 재평가처럼 독자가 바로 체감하는 영수증 언어로 적는다
- `timing_reconciliation_note`에는 왜 arc는 길어도 독자 체감은 느려지지 않는지 한 문장으로 잠근다

## 0. 이 문서가 존재하는 이유

`treatment-production-harness-v2.md`는 **블록 생산**의 품질을 잡는 하네스다. 하지만 생산 이전에 **기획 자체가 핵심 원칙을 위반하면**, 아무리 깨끗한 블록을 찍어내도 이야기는 재미없다.

**핵심 전제**: 기획이 호구면, 생산이 아무리 정밀해도 호구 이야기가 나온다.

본 하네스는 기획안을 작성할 때 **반드시 관통해야 하는 서사 원칙**을 정의한다.

## 1. 대원칙: 자기중심성 (Self-Interest First)

### 1.1 정의

주인공의 **모든 행동은 자신의 이득을 최우선으로 고려**해야 한다.

- 선해도 된다. 악해도 된다. **그러나 이득이 최우선이다.**
- 도덕적 딜레마는 "갈등 연출 소재"이지, "행동 결정 기준"이 아니다.
- **호구되지 않기가 기본값이다.** 호구 행동을 하려면 그것이 호구가 아닌 이유를 증명해야 한다.

### 1.2 자기중심성 검증 체크리스트

매 기획 단위(대단원/블록)마다 아래 5문항을 통과해야 한다:

| #   | 질문                                                 | 실패 시                         |
| --- | ---------------------------------------------------- | ------------------------------- |
| 1   | 이 행동으로 주인공이 얻는 **구체적 이득**은?         | 이득 없으면 기획 재설계         |
| 2   | 이 이득 없이도 주인공이 같은 행동을 할까?            | "예"이면 이득이 허위라는 뜻     |
| 3   | 이 행동을 안 하면 주인공이 **잃는 것**은?            | 잃는 것 없으면 긴장감 부재      |
| 4   | 주인공보다 **더 싸게** 같은 결과를 얻는 방법이 있나? | 있으면 주인공이 비효율적(=호구) |
| 5   | 상대방이 이 행동을 예측하고 역이용할 수 있나?        | "예"인데 대비 없으면 호구       |

### 1.3 호구 패턴 탐지 (금지)

| 호구 유형      | 설명                            | 예시                                      |
| -------------- | ------------------------------- | ----------------------------------------- |
| **순진형**     | 상대의 선의를 검증 없이 신뢰    | "약속했으니 지키겠지"                     |
| **성인군자형** | 대가 없이 베품                  | "어려운 사람을 도와야지" (보답 계획 없음) |
| **체면형**     | 손해를 알면서 체면 유지         | "여기서 물러서면 창피하니까"              |
| **감정형**     | 분노/동정에 의한 비합리적 결정  | "저놈이 밉다" → 무계획 보복               |
| **관성형**     | 기존 관계/약속에 묶여 손절 불가 | "오래된 사인데..." → 출혈 지속            |

**허용되는 예외**: 위 행동이 **장기 이득의 포석/지배력 투자**로 설계된 경우. 단, 왜 이것이 미래의 현금흐름, 운영권, 승계 명분, 조직 통제로 돌아오는지 기획에 명시해야 한다.

## 2. 원칙 A: 동기-행동 일관성 (이득 구조 명시)

### 2.1 핵심

매 블록에서 주인공의 행동을 정당화하는 **이득 구조**를 명시한다.

"좋은 사람이라서" → ❌
"이 행동이 내게 X를 가져다주니까" → ✅

### 2.2 이득 구조 3-Layer

모든 기획 행동은 아래 3계층 중 최소 1개의 이득을 명시해야 한다:

```
Layer 1. 즉시 이득 (이번 블록 내 회수)
  → 현금 증가, 예산 확보, 운영권 획득, 정보 획득, 적 약화

Layer 2. 중기 이득 (5~15블록 내 회수)
  → 정산권 확보, 공급망 선점, 가문 내 포석, 신용 적립, 퇴로 확보

Layer 3. 장기 이득 (15블록+ 후 회수)
  → 시장 지배력, 조직 통제, 승계 명분, 규격/표준 장악, 최종 목표 기여
```

### 2.3 금지: 대가 없는 선의

| 상황        | 호구 기획      | 올바른 기획                                     |
| ----------- | -------------- | ----------------------------------------------- |
| NPC를 도움  | "의리니까"     | "구매실 실무자 신용 잔고 +2. Block 18 정산 표준화 때 인출 예정" |
| 적에게 관용 | "인간적으로"   | "살려두면 형 쪽 결재선이 갈라진다. 지금 자르면 역풍이 더 크다" |
| 손해 감수   | "어쩔 수 없이" | "500억 손실. 대신 병원 운영권과 정산표 접근권 확보" |

### 2.4 목적성 태그 (기획 시 필수 기입)

```
{
  "action_purpose": {
    "immediate": "이번 블록에서 얻는 것",
    "mid_term": "5~15블록 후 어떻게 연결되는가",
    "long_term": "최종 목표에 어떻게 기여하는가",
    "cost": "이 행동의 대가/리스크"
  }
}
```

4개 필드 중 `immediate`와 `cost`는 **필수**. `mid_term`과 `long_term` 중 하나 이상 필수.

## 3. 원칙 B: 정보 비대칭 관리

### 3.1 핵심

주인공이 **뭘 알고 뭘 모르는지** 블록마다 추적한다. 정보 우위 = 가장 강력한 레버리지.

### 3.2 정보 자산 원장

기획 단계에서 아래 원장을 운용한다:

```
| #   | 정보 내용            | 획득 블록 | 출처        | 사용 블록 | 잔여 가치 | 상태      |
| --- | -------------------- | --------- | ----------- | --------- | --------- | --------- |
| 1   | 호텔 린넨실 원가 누수 구조 | Block 2   | 현장 장부   | Block 8   | 중        | 부분 사용 |
| 2   | 형 라인의 유령업체 연결고리 | Block 12  | 내부 정보원 | Block 27  | 상        | OPEN      |
```

### 3.3 회귀/빙의물 특수 규칙

- **미래 정보의 유통기한**: 정보를 쓸수록 역사가 변하고, 남은 미래 지식의 정확도가 떨어진다.
- **정보 사용 = 소모**: 한 번 쓴 정보는 "이미 알려진 것"이 되어 레버리지가 감소한다.
- **기획에서 설계할 것**: 어떤 정보를 언제 쓸지, 아끼는 이유는 뭔지, 쓴 후의 나비효과는.

### 3.4 금지 패턴

| 금지              | 설명                                      |
| ----------------- | ----------------------------------------- |
| **전지적 주인공** | 회귀자인데 매번 모든 것을 다 아는 기획    |
| **정보 낭비**     | 핵심 정보를 사소한 곳에 소비하는 기획     |
| **정보 봉인**     | 알고 있는데 서사적 이유 없이 안 쓰는 기획 |
| **정보 무시**     | 입수한 정보를 기획에서 잊어버리는 것      |

## 4. 원칙 C: 상대방 모델링 (적대자의 합리성)

### 4.1 핵심

**적대자도 바보가 아니다.** 적대자가 호구이면 주인공의 승리가 무가치하다.

### 4.2 적대자 합리성 검증

매 기획에서 적대자의 행동에 대해 아래 3문항 통과 필수:

| #   | 질문                                               | 실패 시                       |
| --- | -------------------------------------------------- | ----------------------------- |
| 1   | 적대자가 **이 행동을 하는 이유**(이득)는?          | 이유 없으면 적대자가 꼭두각시 |
| 2   | 적대자가 **더 나은 선택지**를 놓친 이유는?         | 설명 없으면 적대자가 호구     |
| 3   | 적대자가 **주인공의 전략을 몰랐을 합리적 이유**는? | 없으면 플롯 갑옷              |

### 4.3 적대자 이득 구조 (기획 시 필수)

```
{
  "antagonist_model": {
    "name": "적대자명",
    "goal": "적대자의 목표",
    "rational_action": "이 블록에서 적대자가 하는 행동과 그 합리적 이유",
    "information_state": "적대자가 알고 있는 것 / 모르는 것",
    "why_loses": "이번에 지는 이유 (주인공이 잘해서 / 정보 열위 / 내부 문제)"
  }
}
```

### 4.4 금지: 바보 적대자 패턴

| 금지 유형  | 설명                                                       |
| ---------- | ---------------------------------------------------------- |
| **떡밥형** | 명백한 함정에 매번 걸리는 적대자                           |
| **독백형** | 자기 계획을 주인공 앞에서 설명하는 적대자                  |
| **분열형** | 서사적 필요에 따라 갑자기 내부 배신이 일어나는 적대자 진영 |
| **무능형** | 압도적 자원을 가지고도 매번 지는 적대자                    |

## 5. 원칙 D: 리스크-리턴 프레임

### 5.1 핵심

### 5.2 리스크-리턴 매트릭스 (기획 시 필수)

```
{
  "risk_return": {
    "upside": "성공 시 얻는 것 (구체적)",
    "downside": "실패 시 잃는 것 (구체적)",
    "probability_narrative": "성공 확률에 대한 주인공의 주관적 판단",
    "hedge": "리스크 완화 장치 (있으면)",
    "point_of_no_return": "되돌릴 수 없는 시점"
  }
}
```

### 5.3 포지션 유형

| 유형      | 설명                       | 서사적 효과                       |
| --------- | -------------------------- | --------------------------------- |
| 올인      | 전 자산/평판을 거는 결정   | 최대 긴장감. 남용 금지 (3회 이하) |
| 헷지 올인 | 전력 투구하되 보험 설계    | 합리적 주인공의 기본 모드         |
| 분산      | 여러 수를 동시에 두는 포석 | 전략가 이미지. 긴장감 낮음        |
| 관망      | 의도적으로 행동하지 않음   | "기다려야 이득인 상황" 증명 필수  |

### 5.4 금지: 무위험 승리

| 금지                | 설명                                                                 |
| ------------------- | -------------------------------------------------------------------- |
| **주인공 무적**     | 잃을 것이 없는 상태에서의 맞짱                                       |
| **보험 과잉**       | 모든 상황에 완벽한 대비가 있는 기획 (이기는 게 당연해져서 재미 없음) |
| **순해빠진 리스크** | "기껏 잃어봤자 100억" 이런 수준의 리스크                             |

## 6. 원칙 E: 관계의 거래적 구조 (신용 잔고)

### 6.1 핵심

NPC와의 관계를 **신용 잔고** 개념으로 관리한다. 도움 = 적립, 요청 = 인출.

### 6.2 신용 잔고 원장

```
| NPC        | 잔고 | 최근 거래                            | 적립 이력 | 인출 이력 | 한도 |
| ---------- | ---- | ------------------------------------ | --------- | --------- | ---- |
| 한유림 구매실 실무자 | +3   | Block 20: 정산 표준 도입 공동 돌파 (+2) | 3건       | 0건       | 5    |
| 배정호 세탁 사장 | +1   | Block 23: 감염세탁 라인 공동 운영 (+1) | 1건       | 0건       | 3    |
```

### 6.3 신용 잔고 규칙

1. **적립만 하고 인출 안 하면 호구**: 10블록 이상 잔고 적립만 한 NPC가 있으면, 인출 계획이 기획에 명시되어야 한다.
2. **과잉 인출은 관계 파괴**: 잔고 초과 인출 시 관계 악화 이벤트를 기획에 포함해야 한다.
3. **잔고 0인 NPC에게 요청하면 거절 당하는 기획**이 정상이다. 무조건 들어주는 NPC는 꼭두각시.
4. **일방적 헌신 NPC는 금지**: 주인공에게 무조건 충성하는 NPC는 서사적 깊이가 없다. "이 NPC가 주인공을 따르는 이유(이득)"가 있어야 한다.

### 6.4 금지: 관계 호구 패턴

| 금지                | 설명                                       |
| ------------------- | ------------------------------------------ |
| **ATM형**           | 주인공이 필요할 때마다 자원을 뽑아주는 NPC |
| **무조건 충성형**   | 이유 없이 주인공을 맹목적으로 따르는 NPC   |
| **배은망덕 면역형** | 주인공이 아무리 무시해도 떠나지 않는 NPC   |

## 7. 원칙 F: 승리 조건의 역산 구조

### 7.1 핵심

최종 목표 → 대단원 목표 → 블록 목표가 **역산 가능한 구조**여야 한다.

### 7.2 역산 체인 설계

```
최종 목표: 가문과 회사가 먼저 내 현금흐름망과 조건표에 의존하게 만든다
  └─ 필요 조건 1: 그룹 필수 운영비 절반 이상을 내 네트워크로 통과시킨다
       └─ 대단원 1~2 목표: 장례/호텔/공장 반복 현금흐름 장악
            └─ Block 1~10: 뒤문 생활비 계약 + 내부 실무자 확보
       └─ 대단원 3~4 목표: 병원/정산 시스템 표준 장악
            └─ Block 21~40: 운영 동선 표준화 + 위기 대응권 확보
  └─ 필요 조건 2: 가문 내 법률·정치 명분 확보
       └─ 대단원 5~7 목표: 유언, 정산표, 계열사 의존 구조를 한 방향으로 묶기
```

### 7.3 역산 검증

| #   | 질문                                                          | 실패 시                   |
| --- | ------------------------------------------------------------- | ------------------------- |
| 1   | 이 블록의 성과가 **어떤 대단원 목표에 기여**하는가?           | 기여 안 하면 필러 블록    |
| 2   | 이 대단원 목표가 **최종 목표의 어떤 필요 조건**을 충족하는가? | 연결 안 되면 기획 표류    |
| 3   | 이 블록 **없이** 대단원 목표를 달성할 수 있는가?              | "예"이면 이 블록은 불필요 |

### 7.4 역산 구조 태그 (기획 시 권장)

```
{
  "goal_chain": {
    "block_objective": "이 블록에서 달성할 것",
    "arc_contribution": "이것이 기여하는 대단원 목표",
    "final_contribution": "최종 목표의 어떤 필요 조건을 충족하는가",

  }
}
```

## 8. 원칙 G: 퇴로 설계

### 8.1 핵심

매 기획에서 **실패 시 B플랜**이 있는지. 주인공이 한 수에 올인만 하면 비합리적이다.

### 8.2 퇴로 유형

| 유형              | 설명                                             | 사용 빈도                            |
| ----------------- | ------------------------------------------------ | ------------------------------------ |
| **사전 보험**     | 실패에 대비한 헷지 (부동산 담보, 우군 사전 확보) | 기본값                               |
| **즉석 전환**     | 실패 순간 다른 전략으로 피봇                     | 위기 블록 전용                       |
| **전략적 후퇴**   | 일부를 포기하고 핵심을 지킴                      | 패배 블록 전용                       |
| **의도적 무퇴로** | 퇴로를 스스로 끊어 각오를 보임                   | 클라이맥스 전용 (70블록 중 최대 3회) |

> **올인(§5.3)과 무퇴로의 관계**: "올인"은 자산/평판을 전부 거는 것이고, "무퇴로"는 실패 시 B플랜이 없는 것이다. 올인이면서 무퇴로인 블록은 **하나의 카운트로 합산**한다. 즉, 올인+무퇴로가 동시에 해당되는 블록은 양쪽 카운터를 모두 1씩 소비한다. 70블록 전체에서 올인 3회, 무퇴로 3회이므로, 올인+무퇴로 동시 블록은 최대 3회.

### 8.3 퇴로 설계 태그

```
{
  "escape_plan": {
    "plan_b": "실패 시 대안 행동",
    "trigger": "B플랜 발동 조건",
    "cost_of_retreat": "후퇴의 대가",
    "is_no_retreat": false  // true이면 의도적 무퇴로 — 서사적 근거 필수
  }
}
```

### 8.4 금지: 퇴로 관련 호구 패턴

| 금지                    | 설명                                             |
| ----------------------- | ------------------------------------------------ |
| **무계획 올인**         | 리스크 인식 없이 전 재산을 거는 기획             |
| **퇴로 있는데 안 쓰는** | B플랜이 있었는데 서사적 필요로 "잊어버리는" 기획 |
| **무한 B플랜**          | 뭘 해도 대안이 있어서 긴장감 0인 기획            |

## 10. 원칙 I: 대리만족 우선주의 (실패 서사 설계)

### 10.1 핵심

**완전한 실패 서사는 금지.** 독자는 주인공에게 대리만족을 느끼러 왔다. 주인공이 처참하게 무너지기만 하면 독자가 떠난다.

실패 블록이 존재해야 하지만(§5 리스크-리턴), 그 실패는 반드시 **다음 중 하나 이상**과 연결돼야 한다:

### 10.2 허용되는 실패 유형 (4가지만 허용)

| 유형            | 설명                                                                                                                                                            | 독자 감정                | 예시                                                             |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ | ---------------------------------------------------------------- |
| **의도된 실패** | 주인공이 지는 걸 알고 들어감. 진짜 목적은 다른 곳                                                                                                               | "역시 다 계산이 있었어"  | 운영권 입찰에서 일부러 지고, 경쟁사가 떠안은 적자 구조를 확인    |
| **희망 연결형** | 지지만 그 패배 속에서 다음 수의 실마리를 발견                                                                                                                   | "아 이걸로 역전하겠구나" | 1,200억 손실이지만, 그 과정에서 적대자의 내부 배신자 존재를 포착 |
| **예측-전환형** | 예측했기에 B플랜으로 즉시 전환                                                                                                                                  | "역시 대비하고 있었네"   | A 루트 실패 → 이미 깔아둔 B 루트로 전환, 손실 최소화             |
| **피로스 승리** | 서사적으로는 승리이나 손실이 큰 블록. 결과만 보면 이겼지만, 자본/관계/포지션에서 실질 피해가 있어 **승리와 실패의 경계**에 위치. 관리 목적으로 실패 범주에 포함 | "아깝지만 이겼다"        | 병원 라인은 지켰지만 방어 비용과 여론전으로 자본 30% 소진         |

### 10.3 금지: 대리만족 파괴 패턴

| 금지 유형          | 설명                              | 왜 금지인가                       |
| ------------------ | --------------------------------- | --------------------------------- |
| **완전 패배형**    | 지고, 잃고, 아무 소득 없음        | 독자 이탈. "이 주인공 왜 따라가?" |
| **연쇄 패배형**    | 3블록 이상 연속 순손실            | 누적 좌절감 → 독자 피로           |
| **무의미 실패형**  | 실패가 이후 서사에 아무 영향 없음 | 낭비된 블록. 독자 시간 낭비       |
| **굴욕만 주는 형** | 굴욕을 당하고 회수 계획 없음      | 카타르시스 없는 굴종              |

### 10.4 실패 블록 설계 태그 (기획 시 필수)

```
{
  "failure_design": {
    "failure_type": "의도된 실패 | 희망 연결 | 예측-전환 | 피로스",
    "visible_loss": "독자에게 보이는 손실 (구체적)",
    "hidden_gain": "이 실패로 얻는 것 (독자가 곧 알게 될 것)",
    "hope_hook": "이 실패가 몇 블록 후에 어떻게 전환되는가",
    "reader_emotion": "독자가 느낄 감정 (분노→기대 / 안타까움→희망 등)"
  }
}
```

### 10.5 연속 실패 관리 규칙

1. **실패 블록 연속 최대 2개**. 3연속 순손실 금지.
2. 2연속 실패 시, 2번째 실패 블록에 **반드시 반전 씨앗**을 포함해야 한다.
3. 실패 직후 블록은 **반드시 소규모라도 승리**해야 한다. (자본 회복 아니어도 됨 — 정보 획득, 동맹 확보 등 비금전적 승리 포함)

## 11. 원칙 J: 에스컬레이션 곡선 (판돈 상승)

### 11.1 핵심

**판돈과 사업 파워가 계속 커져야 한다.** Block 1에서 작은 운영권을 걸었는데 Block 50에서도 같은 급의 생활비 계약만 반복하면 안 된다. "이 정도는 이제 껌이야"라는 **성장 실감**이 기획에 내장돼야 한다.

### 11.2 에스컬레이션 3축

```
축 1. 경제력 규모 — 움직이는 돈, 예산, 반복 현금흐름이 커진다
  초반: 작은 운영비, 단일 사업부 예산, 한두 개 계약
  중반: 복수 계열사, 복수 사업장, 그룹 단위 비용표
  후반: 그룹 전체 운영비, 지배구조, 시장 규격, 글로벌 조건표

축 2. 이해관계 복잡도 — 관련된 세력/NPC가 많아진다
  초반: 1:1 대결
  중반: 다자 구도 (3~4세력)
  후반: 글로벌 세력/정부/시장 전체

축 3. 통제권의 비가역성 — 실패 시 복구 난이도가 높아진다
  초반: 실패해도 재도전 가능
  중반: 실패하면 상당한 후퇴
  후반: 실패하면 게임 오버 (최종 목표 불가)
```

### 11.3 에스컬레이션 불가 시: 미래 가치 제시

자본 규모나 판돈을 매번 키울 수 없는 구간이 있다 (호흡 조절, 전략적 후퇴 블록 등). 이때는 **미래 가치를 제시**하여 에스컬레이션을 대체한다.

| 상황              | 미래 가치 제시 방법                                                  |
| ----------------- | -------------------------------------------------------------------- |
| 판돈이 작은 블록  | "이 작은 세탁 계약이 성공하면, 다음엔 병원 운영 표준까지 들어간다"   |
| 관망/준비 블록    | "지금 모으는 결재선 정보가 Block 45의 가문 표준계약 반전에 쓰인다"   |
| 패배 후 회복 블록 | "이 500억 손실을 감수했기에 정산권이 열렸다. 다음 판은 그룹 전체다" |

### 11.4 에스컬레이션 검증

| #   | 질문                                                                      | 실패 시                   |
| --- | ------------------------------------------------------------------------- | ------------------------- |
| 1   | 대단원 N+1의 **평균 판돈**이 대단원 N보다 크거나, 미래 가치가 제시되는가? | 정체 = 독자 지루          |
| 2   | 70블록 기준 후반 30블록의 stakes가 전반 30블록보다 **체감상 더 큰 편인가** | 아니면 줄거리 무게감 부재 |
| 3   | 최종 블록(65~70)의 판돈이 **지금까지 쌓아온 전부**를 걸 수준인가?         | 아니면 최종전이 허무      |

### 11.5 금지: 에스컬레이션 위반

| 금지               | 설명                                                |
| ------------------ | --------------------------------------------------- |
| **판돈 정체**      | 대단원 3개 연속으로 비슷한 규모의 거래              |
| **역에스컬레이션** | 후반부에 전반부보다 작은 판돈 (미래 가치 제시 없이) |
| **숫자만 인플레**  | 금액만 올리고 이해관계 깊이/복구 난이도는 동일      |

## 12. 원칙 K: 카타르시스 설계 (굴욕-회수 아크)

### 12.1 핵심

**적이 주인공을 밟을수록, 나중에 뒤집을 때 쾌감이 크다.** 굴욕의 깊이 = 복수의 쾌감.

기획에서 "이 굴욕을 몇 블록 후에 어떤 방식으로 갚는다"를 **사전 설계**해야 한다.

### 12.2 굴욕-회수 원장

```
| #   | 굴욕 내용            | 가해자      | 발생 블록 | 회수 방식            | 회수 블록 | 배율 | 상태 |
| --- | -------------------- | ----------- | --------- | -------------------- | --------- | ---- | ---- |
| 1   | 이사회에서 공개 모욕 | 큰아버지    | Block 8   | 큰아버지 계열사 인수 | Block 35  | 10배 | 예정 |
| 2   | 핵심 거래처 빼앗김   | 경쟁사 대표 | Block 15  | 경쟁사 정산망 붕괴 + 거래처 역유치 | Block 42  | 20배 | 예정 |
```

### 12.3 카타르시스 배율

**갚을 때는 받은 것보다 크게.** 이것이 대리만족의 핵심이다.

| 굴욕 규모               | 최소 회수 배율 | 예시                                     |
| ----------------------- | -------------- | ---------------------------------------- |
| 소규모 (체면 손상 수준) | 3배            | 모욕 → 상대를 공개적으로 무릎 꿇림       |
| 중규모 (실질적 손해)    | 5~10배         | 100억 손실 → 상대 1,000억 규모 사업 탈취 |
| 대규모 (생존 위협)      | 10배+          | 그룹 매각 위기 → 상대 그룹 자체를 인수   |

### 12.4 카타르시스 타이밍 규칙

1. **즉시 회수 금지**: 굴욕 직후 블록에서 바로 갚으면 카타르시스가 약하다. 최소 **5블록** 숙성.
2. **너무 늦은 회수 주의**: 20블록 이상 지연 시 독자가 이미 잊었을 수 있다. 중간에 **리마인더(독자가 기억하게 하는 장치)** 필수.
3. **회수 없는 굴욕 금지**: 기획에 굴욕이 있으면, **반드시 회수 블록이 지정**돼야 한다.
4. **회수 과정도 서사**: 갚는 과정이 1문장이면 안 된다. 회수 자체가 하나의 블록 분량 이벤트.

### 12.5 설계 태그

```
{
  "catharsis_arc": {
    "humiliation": "굴욕 내용",
    "perpetrator": "가해자",
    "humiliation_block": "Block N",
    "payback_method": "갚는 방식",
    "payback_block": "Block M",
    "multiplier": "배율 (최소 3배)",
    "reminder_blocks": ["Block X", "Block Y"],
    "reader_buildup": "독자가 기다리는 동안 느낄 감정 (분노 축적 → 통쾌한 해소)"
  }
}
```

### 12.6 금지: 카타르시스 파괴 패턴

| 금지            | 설명                                      |
| --------------- | ----------------------------------------- |
| **즉시 보복**   | 당한 직후 바로 갚음 → 긴장감 0, 쾌감 0    |
| **과소 보복**   | 당한 것보다 작게 갚음 → 독자 불만         |
| **망각 회수**   | 너무 늦게 갚아서 독자가 맥락을 잊음       |
| **미회수 굴욕** | 굴욕만 당하고 끝까지 안 갚음 → 독자 이탈  |
| **쉬운 회수**   | 갚는 과정에 서사적 무게 없이 "한 방에 끝" |

### 14.1 대화형 순차 진행 프로토콜 (`다음 스텝` 루프)

사용자가 긴 지시 대신 `다음 스텝`, `계속`, `승인. 다음 스텝`만 입력해도
기획 단계가 끊기지 않도록, **Phase 0 이전의 설계 순서**를 고정한다.

규칙:

1. 한 턴에 **설계 단위 1개**만 전진한다.
2. 이미 확정된 항목은 다시 묻지 않고, 바로 다음 필수 설계 항목으로 넘어간다.
3. 사용자가 방향 수정 없이 `다음 스텝`만 입력하면, 아래 표의 다음 행을 자동 실행한다.
4. 막히는 경우는 오직 2가지뿐이다.
   - 필수 전제(장르/주인공 타입)가 아예 비어 있어 다음 단계가 정의되지 않는 경우
   - 직전 단계와 정면충돌하는 새 요구가 들어와 재고정이 필요한 경우
5. 이 단계의 종료 조건은 `Phase 0 JSON 또는 동등한 대단원 설계 시트`가 만들어지는 시점이다.

### 14.1A 초세분화 안전 모드 (저지능 LLM용)

아래 표는 `다음 스텝`을 아주 단순하게 해석하는 모델을 위한 **더 느리고 더 잘게 쪼갠 기본 순서**다.
모호하면 이 표를 우선한다.

권장 순서:

| 순번 | `다음 스텝` 시 기본 출력 | 목적 |
| ---- | ------------------------ | ---- |
| 1 | 작품 한 줄 정의 | 제목, 장르, 핵심 대리만족을 3줄 이내로 고정 |
| 2 | 주인공 핵심 욕망 | 왜 이 인물이 지금 움직여야 하는지 고정 |
| 3 | 주인공 이득 구조 | 자기중심성, 즉시 이득, 비용을 먼저 고정 |
| 4 | 시작 연도/시대 | 산업 변화축이 가능한 시간대를 고정 |
| 5 | 시작 무대/회사/가문 | 첫 10블록의 생활권과 사업권을 고정 |
| 6 | 출발 자산과 결핍 | 초반 자본, 권한, 정보 열세를 고정 |
| 7 | 핵심 아군 1차 묶음 | 초반 협력 축을 만든다 |
| 8 | 핵심 적대자 1차 묶음 | 내부 적대축을 만든다 |
| 9 | 중기/후기 적대자 확장 | 업계 적대자와 최종 권력전을 고정 |
| 10 | 7대단원 한 줄 골격 | 70블록의 큰 산업 확장 순서를 고정 |
| 11 | 대단원별 입구/출구 | 각 10블록 묶음의 시작점과 종착점을 고정 |
| 12 | 자본 곡선 | 성장, 하락, 재도약, 최종 안정 구간을 고정 |
| 13 | 정보 원장/복선 맵 | 언제 심고 언제 회수할지 고정 |
| 14 | 패배 블록/리스크 | 진짜 손실이 나는 지점을 고정 |
| 15 | 감정 곡선/섹터/장소 분산 | 읽는 체감과 산업 전면을 분산 |
| 16 | 핵심 NPC 관계 변동표 | 신용 잔고와 배신, 화해 지점을 고정 |
| 17 | 1~7대단원 상세 스타트 설계 | 각 대단원의 첫 2~3블록 엔진을 고정 |
| 18 | `Phase 0 JSON`화 | 생산 하네스로 넘길 수 있는 SSOT 생성 |

매 턴 종료 시 최소 보고 형식:

1. 이번에 고정된 것
2. 아직 비어 있는 것
3. 다음 턴 기본 출력

금지:

- `다음 스텝` 때마다 처음부터 요약 재작성
- 확정된 NPC/시대/회사 설정을 임의로 바꿔 다시 설계
- 70블록 전체를 한 번에 생성하려고 건너뛰기
- BI 요구가 나오기도 전에 BI 형식을 미리 섞기
- Phase 0 슬롯 문장을 그대로 늘여 `TR draft`로 취급하기

주의:

- `Phase 0 JSON`은 생산 SSOT이지, 그 자체가 고밀도 TR이 아니다.
- 대단원 슬롯, 자본 곡선, 복선 맵만 맞는 결과물은 `설계 완료`일 뿐 `생산 완료`가 아니다.
- 실제 TR 단계에서는 장면 밀도, 결과 밀도, 관계 차별화, 복선-회수 밀도가 별도 검증되어야 한다.
- 기획 단계에서 조금이라도 애매하면 블록 생산으로 점프하지 말고, 위 18단계 표의 다음 빈칸으로 돌아간다.

### 14.1B Phase 0 완료 금지 조건 (적대자/약점 배분)

아래는 "적대자를 설계했다"와 "적대자를 배분했다"를 구분하기 위한 느린 규칙이다.
저지능 모델은 opponent 이름 목록만 적고 완료라고 착각하기 쉬우므로, 이 항목을 별도로 강제한다.

핵심 규칙:

1. `적대자 3세력`만으로는 부족하다. 반드시 **아크별 배분표**가 있어야 한다.
2. 같은 macro villain의 재등장은 허용한다. 다만 front 인물, weakness, 전장 중 2개 이상이 바뀌어야 한다.
3. weakness는 opponent 이름 치환이 아니라 **구조적 빈틈**이어야 한다.
4. 아래 표가 없으면 `Phase 0 미완성`으로 본다.

최소 배분표 예시:

```text
ARC-01
- primary opponent: 내부 CFO
- secondary opponent: 장례식장 총괄
- weakness pool:
  1) 운영비를 복지비로 뭉개 실제 원가를 못 본다
  2) 현장 승인보다 본사 결재를 먼저 세워 병목이 생긴다
  3) 외주 교체 비용을 단가표에 반영하지 않는다

ARC-02
- primary opponent: 호텔 관리본부장
- secondary opponent: 세탁 외주 대표
- weakness pool:
  1) 객실 점유율만 보고 세탁 병목을 놓친다
  2) 체크인 동선보다 정산 주기를 과소평가한다
  3) 야간 인력 공백 비용을 숨긴다
```

나쁜 예시:

```text
ARC-01 opponent: 윤석진
ARC-02 opponent: 윤석진
ARC-03 opponent: 윤석진
weakness:
- 윤석진이 기술보다 고용, 인수, 규제 프레임에 먼저 매달린다
- 서도윤이 기술보다 고용, 인수, 규제 프레임에 먼저 매달린다
```

좋은 예시:

```text
ARC-01 primary: 윤석진 / secondary: 노현주
ARC-02 primary: 서도윤 / secondary: 외주 세탁 대표
ARC-03 primary: 윤석진 / secondary: 감사실 파견 팀장

weakness:
- 승인권이 현장보다 본사에 몰려 긴급 대응이 느리다
- 원가 누수를 CAPEX로 숨겨 손실이 늦게 드러난다
- 대체 공급망이 없는데도 가격 협상력만 믿는다
```

기억용 4줄:

1. opponent는 목록이 아니라 배분표로 쓴다.
2. weakness는 이름 치환이 아니라 구조 차이로 쓴다.
3. 각 아크는 primary 1, secondary 1, weakness 3이 기본이다.
4. 이 표가 없으면 블록 생산으로 넘어가지 않는다.

### 14.2 연속 진행 허용 모드 (Quality-First)

기획 단계는 연속 진행을 허용하지만, 기본 철학은 **quality-first**다.
즉 `다음 스텝`을 기다리지 않고 이어 갈 수는 있어도, 직전 설계 단위의 감리 없이 밀어붙이지 않는다.

원칙:

1. 연속 진행은 허용 모드일 뿐, 품질보다 우선하지 않는다.
2. `auto-run`의 의미는 **다음 설계 단위로 순차 진행**이지 스크립트 실행 강제가 아니다.
3. 연속 진행이어도 한 번에 전진하는 단위는 여전히 1개다.
4. 각 단위가 끝날 때마다 짧은 진행 로그와 수동 감리 메모를 남긴다.
5. 아래 정지 게이트를 만나면 연속 진행을 멈추고 사용자 판단을 받는다.
6. 컨텍스트 compaction이 발생해도 직전 SSOT를 재오픈한 뒤 같은 규칙으로 재개한다.
7. 본 단계의 모든 중간 시트와 보고서는 **UTF-8 only**로 읽고 쓴다. 한글 깨짐은 P0 취급이다.

정지 게이트:

- 장르/주인공 타입 같은 필수 전제가 비어 있는 경우
- 직전 확정 설정과 충돌하는 신규 요구가 들어온 경우
- 적대축/시대/사업축이 재설계되지 않으면 다음 단계가 무의미한 경우
- 직전 설계 단위의 수동 감리 메모가 없는 경우
- 사용자가 특정 단계만 따로 검토하겠다고 한 경우
- UTF-8 파싱 실패 또는 한글 오염(`triple-question placeholder`, `replacement character`)이 발생한 경우

자동 진행 종료 조건:

- `Phase 0 JSON` 또는 동등한 설계 SSOT 생성 완료
- 이후 단계는 `treatment-production-harness-v2.md`의 연속 진행 규칙으로 인계

**Phase 0 완료 후 행동 (필수):**

- Phase 0 JSON이 정상 생성되면 이 문서의 역할은 끝난다. **멈추지 않고** 즉시 `SSOT_blockguide-integrated-order.md` §2 판정표를 재적용하여 다음 단계(Production)로 자동 진행한다.
- "Phase 0 끝났습니다. 계속 진행합니다."처럼 사용자 재확인을 묻는 문구는 금지한다. 정지 게이트가 발동하지 않았으면 다음 단위(Production Block 001)로 바로 넘어간다.
- 단계 전환은 정지 게이트가 아니다.

## 15. 나쁜 기획 vs 좋은 기획 비교

### 15.1 나쁜 기획 (이것을 피하라)

```
Block 15 기획:
- 사건: 계열 호텔 세탁 라인이 위기에 처함
- 주인공 행동: 무상으로 외주 인력과 자재를 대준다
- 이유: "호텔이 망하면 안 되니까"
- 리스크: 없음
- 적대자: 재무실이 반대하지만 금방 설득됨
- 결과: 호텔 실무진이 감사해서 나중에 도와줌
```

**나쁜 이유**: (1) 이득 구조 불명확 — "호텔이 망하면 안 되니까"는 주인공 이득이 아님, (2) 리스크 부재, (3) 적대자(재무실) 호구화 — 왜 금방 설득됨?, (4) 결과가 보장됨 — 실무진이 감사해서 돌아설 보장 없음, (5) 호구 센서 5유형 중 "성인군자형" 해당.

### 15.2 나쁜 실패 기획 (이것을 피하라)

```
Block 23 기획:
- 사건: 물류 연합이 공급망 공격
- 주인공 행동: 전력 방어
- 결과: 노선 3개 중 3개 전부 빼앗김. 자본 40% 증발.
- 다음 블록 연결: 없음. 다음 블록에서 새로운 사업을 시작.
- 카타르시스: 없음. 물류 연합은 이후 등장하지 않음.
```

**나쁜 이유**: (1) 완전 패배 — 소득 0, (2) 희망 연결 없음 — 독자가 왜 계속 읽어야 하는지 모름, (3) 굴욕 미회수 — 물류 연합이 사라져서 갚을 기회 없음, (4) 대리만족 파괴.

### 15.3 좋은 기획 (이것을 목표로)

```
Block 15 기획:
- 사건: 계열 호텔 두 곳의 린넨·청소 정산이 꼬이며 백오브하우스가 멈출 위기에 처함
- 주인공 행동: 세탁 공장과 야간 청소팀을 묶은 조건부 운영권 인수 제안을 건다
- 이득 구조:
  - 즉시: 운영권 확보 + 정산표 접근권 획득
  - 중기: 호텔 두 곳의 표준 계약을 한 장으로 묶을 근거 확보
  - 장기: 그룹 전체 백오브하우스 비용표를 자기 조건표 아래로 끌어오는 포석
- 리스크: 세탁 공장 정상화 실패 시 500억 손실 + "도련님 외주" 낙인 심화
- 퇴로: 설비 소유권과 출입기록 데이터를 따로 확보해 실패 시에도 린넨 라인만 회수 가능
- 적대자 반응: CFO가 "외주 하나에 운영권을 넘긴다"며 정산 승인 지연과 감사 카드를 동시에 꺼냄
  → 적대자의 합리적 이유: 통제권 방어
  → 적대자가 이기지 못하는 이유: 이미 현장 실무와 야간반 동선이 주인공 쪽 데이터에 묶여 있음
- 타이밍: 월말 정산 직전 — 이 시점을 넘기면 실무진과 재무실이 각자 다른 숫자를 들고 버틴다
- 정보 비대칭: 린넨 회전율과 유령업체 단가를 함께 쥔 상태라 누가 진짜 병목인지 주인공만 안다
- 신용 변동: 한유림 잔고 +1 (정산 구조 설계 협력), 배정호 +2 (공동 설비 운영)
- 에스컬레이션: 이전 대단원 최대 승부가 장례식장 단일 계약이었다면, 이번엔 복수 호텔 운영권과 정산표를 동시에 건다
```

### 15.4 좋은 실패 기획 (이것을 목표로)

```
Block 23 기획:
- 사건: 물류 연합이 공급망 공격
- 주인공 행동: 전략적 후퇴 — 노선 1개를 의도적으로 양보하며 핵심 2개 사수
- 실패 유형: 피로스 승리
- 눈에 보이는 손실: 800억 순손실, 노선 1개 상실
- 숨겨진 이득: 양보한 노선이 적자 노선 → 경쟁사가 떠안음 + 방어 과정에서 동남아 정부 신뢰 확보
- 희망 연결: Block 31 독점 입찰 자격으로 연결
- 카타르시스 설계:
  - 굴욕: 물류 연합이 "노선 뺏은 것" 언론에 승전보로 보도
  - 회수: Block 42에서 물류 연합의 적자 노선이 폭탄이 되어 컨소시엄 와해
  - 배율: 노선 1개 → 컨소시엄 분해 후 잔여 자산 인수 (10배+)
  - 리마인더: Block 35에서 적자 보도 시 "그때 넘긴 노선이..." 독백
```

**좋은 이유**: (1) 3-Layer 이득 전부 명시, (2) 구체적 리스크 + 헷지, (3) 적대자가 합리적으로 반응, (4) 타이밍 근거 있음, (5) 관계 변동이 양방향, (6) 호구 요소 0건, (7) 실패해도 대리만족 유지, (8) 카타르시스 배율 설계 완비, (9) 에스컬레이션 연결.
