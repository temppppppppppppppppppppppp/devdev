## 2. Strengthen — 맞지만 보강이 품질을 높이는 항목

### ST-01. solution 말미 분석 정밀도 (D2 §1.2, §3.0)

**D2 기술**: "T (solution 말미 20자 5블록+) | FAIL (70블록 동일)"

**직접 파싱 결과**:
- tail-20 고유값: **27종** (70블록 전량 동일이 아님)
- tail-20 최다 반복: **14블록** (≥5 = P0 → FAIL 판정 자체는 정확)
- tail-20 ≥5블록 반복: **4종** (14, 8, 5, 5)
- **tail-15**: 1종, 70블록 **전량 동일** ("도권을 자기 쪽으로 당긴다.")

**보강 제안**: "70블록 전량 동일"은 tail-15 기준에서만 성립. tail-20 기준으로는 "27종이나 최다 14블록 반복(P0)"이 정확한 기술. D2 §1.2의 탐지 결과란을 `FAIL (27종 중 최다 14블록 반복)`, §3.0의 solution 열을 `"~당긴다" tail-15 전량 동일, tail-20 최다 14블록`으로 보강하면 정밀도 향상.

T 규칙의 FAIL 판정 자체는 **정확**하므로 결론 변경 없음.

### ST-02. business_sector 필드 위치 (D2 §1.1, D1 validate_v3)

**실제 구조**: `block["genre_ext"]["business_sector"]` (중첩)
**D1 validate_v3 코드**: `block.get("business_sector")` (최상위 탐색)
**D2**: "business_sector 7종 70블록 존재"

최상위에 `business_sector`가 없으므로 validate_v3 코드가 실제로 이 필드를 **탐지하지 못함**. 결과적으로 U 패턴이 항상 스킵됨. D2의 "PASS" 판정은 우연히 맞지만(sector 필드 없음 = P0/P1 아님), validate_v3의 탐색 경로가 실제 JSON 구조와 불일치.

**보강 제안**: validate_v3의 sector 탐색 경로에 `genre_ext` 중첩 참조 추가:
```python
block.get("sector") or block.get("business_sector")
or block.get("genre_ext", {}).get("business_sector")
or block.get("genre_ext", {}).get("section_rotation")
```

### ST-03. 재작업 목표 vs PASS 기준 명시적 구분 (D2 §2.1, §7.1)

D2에서 두 수준이 혼재:
- PASS 기준: ≥8명, ≤30% (D1 R29 원문)
- 재작업 목표: ≥10명, ≤25% (D2 독자 설정)

이것이 **의도적 여유**인지 혼동인지 문서에 명시 없음.

**보강 제안**: §2.1 상단에 1줄 추가: "재작업 목표는 PASS 기준보다 의도적으로 엄격하게 설정함 (여유 마진 확보용). 출고 판정은 PASS 기준으로, 품질 목표는 재작업 목표로 평가."

### ST-04. validate_v3 중간 실행 시 false-alarm (D2 §5.2~5.3)

아크 1(10블록) 완성 후 validate_v3를 누적 실행하면:
- R29 "70블록 고유 opponent ≥8명" → 10블록에서 구조적으로 최대 10명. 하한 8명은 가능하나 빡빡함.
- R30 "70블록 전체 고유 weakness ≥10종" → 10블록에서 10종은 불가능(아크 1만으로).

D2 §5.3에 "누적 블록 전체 대상"이라 했으므로, 아크 1 시점에서 R29/R30의 **전체 기준** P1이 구조적 false-alarm을 낼 수 있음.

**보강 제안**: §5.3에 단서 추가: "R29/R30의 70블록 전체 기준(P0/P1)은 블록 70개 완성 후에만 최종 판정. 중간 실행 시 아크 단위 기준(대단원 내 ≥2명 P0, ≥3종 P0)만 적용."

### ST-05. 안전 배치가 아크 1에만 적용 (D2 §5.2)

아크 1만 3→4→3 안전 배치. 아크 2~7은 "10블록 단위". 아크 2가 첫 섹터 전환 + opponent 대거 교체 지점인데, 아크 1보다 생산 리스크가 높을 수 있음.

**보강 제안**: §5.2에 "아크 2도 안전 배치(3→4→3) 권장. 섹터 전환 + opponent 교체가 동시 발생하는 첫 아크이므로." 추가. 아크 3~7은 10블록 일괄 유지.

**수정 필요**:
1. D2 헤더의 골든 TR 경로를 `treatments/chaebol_allowance_zero_tr_block_070_draft.json`으로 교정

### CR-02. 실패 TR 아크 6 opponent 구성 오류 (D2 §3.0, §3.6) — **MAJOR**

**D2 기술**: "아크 6 | 서도윤(2), 윤석진(5), 백도현(3)" — 3명

**직접 파싱** (블록 51~60):
```
51: 백도현, 52: 윤석진, 53: 백도현, 54: 윤석진,
55: 백도현, 56: 윤석진, 57: 백도현, 58: 윤석진,
59: 백도현, 60: 윤석진
```
고유 opponent: **2명** (백도현 5, 윤석진 5). **서도윤 0블록**.

D2 §3.0에서 아크 6이 "유일하게 3명 아크"라는 기술도 오류. 실제로 3명인 아크는 **아크 7만** (백도현, 서도윤, 윤석진).

**수정 필요**:
- §3.0 아크 6: `서도윤(2), 윤석진(5), 백도현(3)` → `윤석진(5), 백도현(5)`
- §3.6: "유일하게 3명 아크" 삭제. 재설계 방향에서 "현재 2명 → 최소 3명" 유지.

### CR-03. TF-BH1 "골든 02: 15명" vs 현재 골든 31명 (D1 §0.1, D2 §1.1) — **MAJOR**

D1과 D2 모두 "골든 02 = 15명"으로 기술. 현재 골든 TR 직접 파싱 결과 **31명**. D1 작성 시점 이후 골든 TR이 개선된 것으로 추정.

이로 인해 **D2의 재작업 목표가 과소** 설정됨:
- D2 목표 "≥10명" vs 현재 골든 31명 → 목표가 골든의 1/3 수준
- D2 목표 "≤25%" vs 현재 골든 24.3% → 이건 적절

**수정 필요**: D2 §7.2, §7.3의 "골든 02" 열을 현재 실측(31명, 24.3%, 854자)으로 갱신. 재작업 목표도 상향 검토 (≥15명 권장).

### CR-04. 골든 TR 자체의 R31(T 패턴) false-FAIL 리스크 (D2 §8.2)

**D2 기술**: "R31 (말미 5블록 P0) | 골든 02 다양 → PASS | false-FAIL 아님"

**현재 골든 TR 직접 파싱**:
- tail-20 고유값: **8종**
- tail-20 최다 반복: **57블록** (70블록 중)

이 수치는 R31 "말미 20자 동일 5블록+ → P0"에 **확실히 FAIL**.

현재 골든 TR이 R31에서 false-FAIL되므로, R31 규칙 자체의 임계값 또는 적용 범위를 재검토해야 할 가능성이 있음. 또는 "골든 TR이 TF-BH1 이전에 만들어져서 TF-BH1 규칙을 만족하지 못하는 것이 정상"이라는 해석도 가능.

**수정 필요**: §8.2에서 현재 골든 TR 기준 R31 결과를 정직하게 기록하고, "골든 TR이 TF-BH1 이전 산물이므로 false-FAIL이 아니라 **true-FAIL (개선 대상)**"인지, "R31 임계값을 골든 TR에 맞춰 조정해야 하는지" 판정을 명시.

### OI-02. 서사 클라이맥스 배치 부재

D2 §3에서 7아크의 opponent/weakness/solution 재설계를 지시하지만, **서사적 정점(위기/반전/클라이맥스)이 어느 블록인지** 지정이 없음. 실패 TR의 근본 문제 중 하나가 "70블록 전량 균일"이었는데, 재설계 오더도 이 관점이 빠져 있으면 다시 균일한 결과가 나올 수 있음.

**검토 필요**: 블록 30(중반 위기), 50(후반 전환), 65(최종 위기) 등 서사 곡선 앵커를 추가할지 여부.

### OI-03. R29 점유율 30% 임계값과 골든 TR

D1 "골든 02 최대 ~33%"로 30% 임계값 설정. 현재 골든은 24.3%.

만약 D1의 "~33%"가 이전 버전 골든 기준이라면, 현재 골든은 30% 임계값을 쉽게 통과하므로 false-FAIL 리스크 없음. 단, D1의 근거 수치(~33%)가 더 이상 유효하지 않으므로, TF-BH1 자체의 임계값 근거도 갱신이 필요할 수 있음.

### OI-04. 신규 opponent 설계 주체와 시점

D2 §4.2에서 "opponent_transition_plan ≥10명으로 확장"이라 했지만, 이 10명의 이름/성격/동기/갈등 구조를 **누가, 언제** 설계하는지 명시 없음. Phase 0에서 미리 확정해야 하는지, 배치 생산 중 즉석으로 만드는지에 따라 생산 워크플로우가 완전히 달라짐.
